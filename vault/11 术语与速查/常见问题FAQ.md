## 1. 这个项目到底是干什么的？

**用屏幕截图 + 键鼠模拟，自动化《三角洲行动》烽火地带的"跑刀"流程**（进场 → 搜刮 → 撤离 → 结算）。

- 只做**界面导航与拾取流程**；明确**不做**任何战斗/瞄准/击杀辅助。
- 技术栈：C#/.NET 10 + WinForms + OpenCvSharp + Windows 自带 OCR，加一个离线训练的小 CNN。
- 一句话人设：**不是"更强的玩家"，是一双会看屏幕、会动鼠标、但随时能被你打断的手。**

→ [[01 项目总览]]、[[架构-总览]]、[[决策-红线与边界]]

## 2. 为什么不能读内存？

三个原因，按重要性排：

1. **性质变了**：读内存/注入/抓封包属于外挂手段，一旦用了，整个项目的立论（"看得见的自动化"）就崩了；
2. **风险高**：这类操作更容易被反作弊直接判定，后果比"行为像不像人"严重得多；
3. **不需要**：跑刀要的信息全在屏幕上——撤离点有 HUD 标记、可通行性看画面、界面状态有文字。**能用眼睛解决的，不必伸手进别人脑子里。**

→ [[决策-红线与边界]]、`docs/项目大纲.md` §1

## 3. 为什么有的功能要"观察期"？

因为**"离线指标好"不等于"现场可信"**。观察期（observe-only）就是让新功能**只看不动**：

- 照常推理、照常写日志，但预警**不影响动作**；
- 跑几局之后看两件事：**误报多不多**、**矛盾率高不高**；
- 数据说话，才决定要不要 `enforce`。

这是所有 AI 能力的统一纪律，不跳步。AI 视觉现在就在这个阶段（金标 0.695 → 强制仅观察）。

→ [[决策-AI视觉observe-only]]、[[AI-模型与门禁]]

## 4. 小地图定位准不准？

**"落在正确区域"是可靠的，"像素级精度"还没量化。**

- 真机回归集：**6 对 0 错**（m1a/m1b/m1c/m1d/m2a/m2b，用户肉眼逐张确认）；
- 全量两局：常规局接受率 **70%**（313 帧里 220）、机密局 **54%**（391 帧里 211）；
- 速度中位 **4.0-4.4 m/s**、p90 约 7.6 m/s——是"人跑步"的量级，说明轨迹物理上合理；
- **但分数不是置信度**：出现过 0.904 高分却是错的位置。所以真实链路用 `LocalizerTrack` 做轨迹过滤（首锚双帧确认、速度门 ≤30px/s、重锚定）。

→ [[模块-小地图定位器]]、[[决策-小地图定位导航]]、`docs/小地图定位P0验证.md` §7/§9

## 5. 为什么有时候定位不到？

四类原因，全都可解释（不是随机故障）：

| 情况 | 原因 | 处理 |
|---|---|---|
| **刚落地那几秒** | 部署动画/小地图还没绘制 | 等 2-3 秒 |
| **开着背包/地图/结算** | 左上角根本不是小地图，是别的 UI | `HudStateGate` 会识别出来并**跳过定位** |
| **室内/地下** | 小地图显示的是**楼层平面图**，和室外底图不匹配 | 需要分层地图（已挖通数据，待投入；且三层得分几乎相同，楼层判别还没解决 ❓） |
| **长空档后瞬移** | 速度门按 30s 封顶，间隔太久会漏过一次误接受 | 已知待改进项 |

→ [[坑-背包界面不是小地图]]、[[标定-分层图层]]、`docs/小地图定位P0验证.md` §9

## 6. VLM 那条线为什么放弃了？

**不是"模型不够大"，是"任务类型不对"。**

- **P0**（整帧直问）：框大 5-8 倍（143×213 vs 真图标 25-40px）、队友图标被误标成撤离点、`conf` 全 0.95-0.98 没区分度；
- **P0.5**（两步缩放）：框紧了（24×23px ✅），但**类别区分仍失败**——理由里明写"内含数字1"，照样判"符合撤离点定义"（自相矛盾地附和）；精度结构性受限 **±10-20px**；
- 换 32B 要 18GB 显存（只有 12GB），云 API 违反"数据不出机器"。

**结论**：VLM 收缩为"粗定位"实验能力，UI 模板线回人工五步流程，`aiground` GUI 暂停，YOLO 线关闭。**它仍然是初筛质检员**——那是它擅长的（整帧级判断），不是标注员。

→ [[AI-VLM预标注探索]]、[[AI-VLM初筛]]、[[决策-VLM预标注探索与收尾]]

## 7. 声音感知在做吗？

**没做，只立了项。** 2026-10-22 用户决定"暂不投入，作为未来能力立项"（原话："这是我还没有了解到的领域"）。

- 技术上可行：WASAPI 回环采集（录系统正在播的声音，不碰游戏进程），延迟 30-80ms；
- 左右容易（声道能量差），**前后很难**（HRTF 的频谱细节，要机器学习）；
- 红线：**只做"感知→避让/暂停/改道"，绝不做"感知→交战"**，不许"声呐透视"。

→ [[决策-声音感知立项未投入]]、[[知识点-WASAPI与HRTF]]

## 8. 怎么加一个新界面的识别？

四步，**只改数据不改代码**（这才是"数据驱动"的意义）：

1. `capture` 截一张该界面的图；
2. 找 2-3 个**稳定的特征词**（别用会串台的词），写进 `data/screens.json` 的新条目：`markers` 里 `type: ocr` + `keywords` + `require_all: true`；
3. 如果是对局内界面，记得加 `group: "match"`（分表，见 [[决策-局内界面分表group]]）；
4. 验证：`dotnet run -- annotate` 画标记冒烟，或 `chain` 跑到那一步看是否识别；`screens.json` 的 schema 有单测冻结（`DataStoreTests`）。

> [!tip] 防串台口诀
> **一个词不够就两个词，两个词不够就加区域。** 备战界面和配装界面都有"配装"——只靠一个词必然认错。

→ [[标定-界面标记与分组]]、[[模块-视觉识别]]、[[坑-链路校验回归]]

## 9. 转向不准了，怎么重标？

`px_per_90deg`（转 90° 需要移动多少像素，当前 **4500**）变了——通常是因为改了**鼠标 DPI 或游戏内灵敏度（EDPI）**。

标定法（文档原文）：**反复 `turn 1000 0`，数几次能回到原方向，90° ≈ 250×n 像素**。改完写回 `data/runtime.json` 的 `px_per_90deg`。

```powershell
dotnet run -- turn 1000 0     # 转一次，看画面转了多少
```

→ [[标定-转向灵敏度]]、`data/runtime.json`

## 10. 改了配置要重启吗？

**大部分要。** `data/*.json` 是启动时加载的（`DataStore`），改成运行中不生效。分情况：

| 改了什么 | 要不要重启 |
|---|---|
| `runtime.json` / `screens.json` / `elements.json` / `ai_vision.json` | **要**（下次启动生效） |
| `workflows/*.json`（链路） | 要（链路在启动时读） |
| `assets/ai/models/*.onnx` + `ai_vision.json.model` | 要 |
| 只是跑一次诊断命令（`tplprobe`/`ocr`/`aiprobe`） | 不用——每次都重新读 |

> [!warning] 有一条例外要记住
> **AI 被自动禁用时会把 `enabled=false` 写回 `ai_vision.json`**。所以"重启也不行"往往不是 bug，而是它上次自己关了——去看日志里的 `⛔` 那行，确认后手动改回 `true`。

## 11. 出问题先看哪里？

按这个顺序，90% 的问题三步内能定位：

| 顺序 | 看什么 | 能回答什么 |
|---|---|---|
| 1 | **控制台最后 20 行 + `logs/status_*.log`** | 它停在哪一步、报了什么 |
| 2 | `StatusText`（状态栏那行） | 加载了哪个模型、跑在 DirectML 还是 CPU、ROI/滤波配置、是否被降级 |
| 3 | `logs/ai/*.jsonl` + ROI 环形图 | 模型**看到了什么**、判了什么、置信度多少 |
| 4 | `screenshots/unknown/` | 认不出的界面长什么样（含 OCR 词表） |
| 5 | 诊断命令复现：`capture` / `ocr` / `tplprobe` / `aiprobe` / `aieval` | 把整条链路拆成单环节验证 |

> [!tip] 一句经验
> **"识别错"和"动作错"是两种病。** 先用 `annotate`/`tplprobe` 看识别对不对；识别对而点击错，就去查 `MapDesignToScreen` 与窗口/DPI（见 [[坑-坐标缩放偏移]]）。

→ [[工具-CLI命令速查]]、[[坑-链路校验回归]]

## 12. 退出码 130 是什么意思？是不是崩了？

**不是崩，是你按了 Ctrl+C（或点了急停）。**

130 = 进程被 SIGINT 中断的标准退出码。本项目的急停是**协作式**的：置 `StopRequested` 标志 → 各循环在检查点收尾 → **释放所有按住的键** → 自然退出，退出码保持 130。

- 看到 130：正常收工。
- 看到别的非零：才是真问题，去看日志。
- 卡住不动、按键没释放：那是另一个问题（理论上不该发生，急停路径有 `finally` 兜底）。

→ `docs/模块说明.md` §2（`InstallEmergencyStop`）、[[模块-chain引擎]]

## 13. 金标才 0.695，这模型到底能不能用？

**能"看"，不能"动手"。**

- 0.695 落在 **0.60-0.85** 区间 → 强制仅观察：预警照常记录，但不影响动作；
- 主短板是 **blocked 召回**（更容易把"挡住"看成"能走"——对跑刀来说是最危险的方向）；
- 想开 `enforce`，需要：金标 **≥0.85** + 真机误报可接受 + 矛盾率正常，而且 `avoid.enforce` 还要手动打开。

**下一步不是调阈值，是补 blocked 难例重训**（怼墙/贴箱子/栅栏）。

→ [[AI-模型与门禁]]、[[AI-数据集与标注]]

## 14. 我想学训练，从哪开始？

**先跑通一遍管线，再按需补知识**。九周计划（每周一个小目标）见 [[AI-学习路径]]，第一周就一件事：

```powershell
cd D:/MeineArbeit/DeltaUnlimited/ai-training
.venv-train/Scripts/python.exe src/smoke_test.py
```

看到 `✅ 冒烟通过` 就说明环境对了。然后是一个采集夜（`airecord`）→ 打标（`ailabel`）→ 训练（`train.py`）。

> [!tip] 三个"不用"
> 不用手推公式、不用先学完机器学习、不用看懂所有 C#。**能讲清"图片 → ONNX → PathWarning"这条链就算达标。**

→ [[AI-学习路径]]、[[知识点-图像基础]]、[[工具-Python脚本清单]]

## 15. 为什么每次只跑一会儿就停？

**会话限额**：`data/runtime.json → session_limits` 里 `max_minutes_per_day: 240`，也就是**每日累计 4 小时后自动停止**（`max_matches_per_day: 0` = 不限局数）。

这是**自控红线**，不是 bug：项目原则是"低频 + 人在场"，而不是挂机一整天。要改可以改，但风险自担——而且拟人化做得再好也不免疫风控。

→ [[决策-会话限额与风控]]、[[知识点-拟人化与风控]]
