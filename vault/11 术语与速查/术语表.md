# 术语表

> [!info] 一句话
> 这个项目里"听不懂就查一下"的词都在这——按主题分组，每条一两句，能点进去的都点了。**忘了某个词什么意思，先来这里搜。**

> 记号说明：表格里的 `→` 指向深入讲解的笔记；带 ❓ 的是本库尚未定稿的口径。

## 一、架构与流程

| 术语 | 一句话解释 |
|---|---|
| **链路（chain）** | 一条按顺序执行的步骤清单（`workflows/*.json` 的 `steps`），由 `chain` 命令跑起来。**一条链路 = 一个业务流程**（如进场 `enter_match`）。见 [[模块-chain引擎]]、[[架构-总览]] |
| **op** | 链路的"步骤类型"：`key` 按键、`click_element` 点元素、`if_ocr` 条件分支、`switch_screen` 界面分流、`pause` 人工确认… 换 op 就是换这一步干什么 |
| **伺服（servo）** | 高频闭环控制循环（本项目 8Hz）：读感知 → 算一个小修正 → 执行 → 再读。**用于局内"跟着路标走"这种连续动作**，与 2Hz 的链路（界面流转）分工。见 [[模块-伺服循环]]、[[决策-双引擎架构]] |
| **标定（calibration）** | 把"某个具体数值"测出来写进配置的过程。如 `px_per_90deg=4500` 是实测"转 90° 要移动多少像素"。标定不是猜，是量。见 [[标定-转向灵敏度]] |
| **设计分辨率** | 全项目统一的坐标系基准 **1920×1080**。模板、ROI、元素坐标都写在这上面，运行时按窗口实际尺寸缩放。 |
| **变更门（ChangeGate）** | 一个"要不要真扫一遍"的开关：先用 1/6 缩略图帧差（约 2ms）看画面有没有变，没变就跳过整轮识别（Detect 要 600-700ms）。见 [[知识点-工程实践]] |
| **fail-open** | 出错时选择"最保守的动作并记录"，而不是继续赌。如 OCR 不可用就判未命中、定位识别不到界面就放行。见 [[知识点-工程实践]] |
| **门面（facade）** | 一个对外只暴露少数接口、内部藏一堆细节的类。`AiVision` 就是 AI 模块的门面（`EnsureStarted` / `Observe` / `RecordGuardFired` / `SnapshotStats`）。见 [[模块-AI视觉感知]] |
| **半自动** | 默认形态：异常点停下来等人按回车确认；`--auto` 才是全自动。见 [[决策-红线与边界]] |

## 二、视觉与感知

| 术语 | 一句话解释 |
|---|---|
| **ROI** | Region of Interest，感兴趣区域。本项目 AI 只看 `[592,656,648,324]` 这一块（中央偏下），因为"前面能不能走"就在那儿。见 [[标定-可通行ROI]]、[[知识点-图像基础]] |
| **模板匹配** | 拿一张小图在大图上滑窗找最像的位置。"这个按钮在哪"用它。见 [[知识点-模板匹配与NCC]] |
| **NCC** | 归一化互相关。一种"减掉亮度、除掉对比度"的相似度算法，范围 -1~1，不受整体明暗影响。见 [[知识点-模板匹配与NCC]] |
| **match_map** | 匹配得到的**完整得分图**（每个位置一个分数），不是只取最大值——用来分析"还有哪些位置也不错"。见 [[知识点-FFT与卷积]] |
| **OCR** | 光学字符识别：把画面里的字变成可比较的文本。本项目主力识别手段。见 [[知识点-OCR原理]] |
| **STRICT（严格层）** | OCR 匹配里"可以裁决"的那一层（单词包含 / 行内连续词拼接）。候选层只告警不裁决。见 [[知识点-OCR原理]] |
| **颜色判（color 策略）** | 不用模板也不用 OCR，直接数"某种颜色的像素占比"。受击红屏、品质色都用它。见 [[标定-危险信号阈值]] |
| **HUD** | 游戏画面上的常驻信息层（血条、罗盘、小地图、准星提示）。它**不是**界面，但会遮挡 ROI。见 [[知识点-坐标系统与地图]] |
| **小地图定位** | 用左上角圆形小地图去官方大地图上做匹配，反推"我在哪"。见 [[模块-小地图定位器]]、[[决策-小地图定位导航]] |
| **图层（分层地图）** | 室内/地下是**另一张地图**（`daba_0f/1f/2f`），与室外主图坐标系参数不同，需要分别标定。见 [[标定-分层图层]] |
| **感知信号** | 从画面推出来的"危险/机会"结论（红屏、贴墙、可通行性预警），交给状态机消费。见 [[模块-感知信号]] |

## 三、数据与配置

| 术语 | 一句话解释 |
|---|---|
| **分表（group）** | `screens.json` 里给界面加 `group` 字段，把"大厅界面"和"对局内界面"分成两张表分别扫。省一半 OCR，且局内 unknown 的兜底**不是按 Tab**。见 [[决策-局内界面分表group]]、[[标定-界面标记与分组]] |
| **`screens.json`** | 界面识别表：每个界面配"哪些标记全部命中才算它"（`require_all` 防串台）。见 [[模块-视觉识别]] |
| **`elements.json`** | 元素识别表：语义名 → 识别方式（`coord` / `template` / `ocr` / `color`）。流程只引用名字，换识别方式不改代码。见 [[模块-数据表]] |
| **manifest** | 清单文件。训练用 `datasets/passability/manifest.csv`（relpath/label/map/season/source/created），录制用 `record_manifest.csv` |
| **`label_map.csv`** | "录制帧 → 裁剪出的训练图"的映射表，`audit.py` 靠它对账。**不是标签源**。 |
| **fixtures** | `tests/fixtures/` 下的真机截图，用于"素材在就跑真机回归，缺了就跳过"。见 [[知识点-工程实践]] |
| **决策记录（ADR）** | 带日期和理由的决定档案，允许翻案但不许抹掉旧记录。见 [[知识点-工程实践]] |
| **P0 闸门** | 大方案开工前先花 1-2 小时做"能判死刑"的最小验证。见 [[知识点-工程实践]] |

## 四、AI 与模型

| 术语 | 一句话解释 |
|---|---|
| **passability（可通行性）** | 本项目第一个模型要回答的问题：前方能不能走。三分类 `passable`（能走）/ `blocked`（被挡）/ `no_ground`（弃权，看不清）。见 [[AI-数据集与标注]] |
| **金标集（golden set）** | 门禁用的"期末考卷"：**独立采集**、人工反复核对、绝不参与训练、绝不用 VLM 判断的一小份数据。当前 376 张。见 [[AI-数据集与标注]] |
| **门禁（gate）** | 用自动检查决定"能不能上线"的闸门。金标 macro-F1 三档：≥0.85 可 enforce / 0.60-0.85 仅观察 / <0.60 自动禁用。见 [[AI-模型与门禁]] |
| **observe-only（仅观察）** | 模型照常推理、照常记日志，但**预警不影响动作**。所有新模型必须先跑这个阶段。见 [[决策-AI视觉observe-only]] |
| **enforce** | 允许预警"提前拉动**既有**守卫（Escalate）"。注意它不新增决策逻辑，只是让已有守卫更早触发。见 [[AI-模型与门禁]] |
| **矛盾率** | "模型说没事，但贴墙守卫触发了"的比例。用免费的真值衡量模型是否变瞎，>25%/10min 自动禁用。见 [[AI-模型与门禁]] |
| **macro-F1** | 三类 F1 的**平均**（小类与大类同权）。类别不均衡时比 accuracy 可信。 |
| **ONNX** | 模型的通用文件格式（计算图 + 权重）。训练（Python）与运行（C#）之间的交接物。见 [[知识点-ONNX与DirectML]] |
| **DirectML** | 用任意 DX12 显卡跑推理的 Windows 后端（不绑显卡品牌、不用装 CUDA）。本项目 `ep=auto` 时优先用它。见 [[知识点-ONNX与DirectML]] |
| **EP（Execution Provider）** | ONNX Runtime 的"执行后端"：CPU / DirectML / CUDA… |
| **VLM** | 视觉语言模型：能看图并回答问题的大模型。本项目用它做**初筛质检员**，不做标注。见 [[AI-VLM初筛]] |
| **vLLM** | 跑大模型的推理服务框架（Linux 优先，本项目装在 WSL 里）。"加载一次、随叫随到"——所以服务必须常驻。见 [[AI-VLM初筛]] |
| **预标注** | 让模型先出一版框/标签，人只做确认与修正。本项目试过，结论：**细粒度图标不划算**。见 [[AI-VLM预标注探索]] |
| **漂移（drift）** | 赛季更新导致模型表现下降。检测手段：金标集回放 + 运行期矛盾率。见 [[AI-模型与门禁]] |
| **类别权重 / weight_cap** | 类别不均衡时给小类更高权重；`weight_cap=5.0` 压住上限，防止损失被单一小类垄断。见 [[知识点-轻量CNN与MobileNet]] |

## 五、游戏与跑刀

| 术语 | 一句话解释 |
|---|---|
| **跑刀** | 低成本进场、只捡普通材料、尽快撤离的玩法。本项目的自动化目标就是这个流程。见 [[01 项目总览]] |
| **撤离点** | 对局里"能撤出去"的位置。地图图例上是绿色"奔跑人形/右上箭头"图标；灰色同形状是"未开启撤离点"，也算撤离点。当前零号大坝标了 4 个（E1-E4）。见 [[标定-出生点与撤离点]] |
| **出生点** | 开局落地位置。零号大坝标了 **14 个**（S1-S14，与官网筛选面板数量一致）。"出生点 → 撤离点"是当前允许的**计划路线**。见 [[标定-出生点与撤离点]] |
| **常规撤离点** | 默认开放、不需要额外条件的撤离点（本项目 E1 东区隧道、E2 西区公路口）。 |
| **丢包撤离** | 需要**丢掉背包/负重**才能用的撤离点（E3 坝顶）。见 [[决策-点位表恢复与路线规划]] |
| **条件撤离点** | 有额外触发条件的撤离点（如 E4 维修通道要求**负重条件**）。另有随机开放/电梯撤离点，本轮**不标**（前者费时间、后者可能被堵且要开门）。 |
| **K0–K6** | 跑刀的七个阶段里程碑：K0 标定采集 → K1 撤离直通 → K2 搜刮原语 → K3 背包管理 → K4 危险与死亡兜底 → K5 漫游与节奏 → K6 经济闭环。见 [[路线图与待办]]、[[02 时间线]] |
| **撤离直通（K1）** | K1 的验收形态：落地 → 标点 → 跟随 → F → 倒计时 → 撤离成功 → 结算 → 回大厅（**空手**跑通，人全程盯） |

## 六、工程与排错

| 术语 | 一句话解释 |
|---|---|
| **exit code 130** | 进程被 **Ctrl+C（SIGINT）中断**时的标准退出码。本项目的急停是"协作式"的：置标志 + 释放所有按键 + 优雅收尾，所以退出码**保持 130**（而不是被强杀）。看到 130 = 你按了急停，不是崩溃。 |
| **协作式急停** | 不调用 `Environment.Exit`，而是设 `StopRequested` 标志，各循环在检查点自行收尾。三路同源：GUI 按钮 / Ctrl+C / 暂停面板"中止"。见 [[模块-chain引擎]] |
| **会话限额（session_limits）** | 每日累计运行时长上限（`max_minutes_per_day: 240`，即 4 小时；`max_matches_per_day: 0` = 不限局数）。这是**自控红线**（别真挂机一整天），不是技术限制。见 [[决策-会话限额与风控]] |
| **`px_per_90deg`** | 标定参数：视角转 90° 需要移动多少像素（当前 4500）。EDPI 一变就要重标。见 [[标定-转向灵敏度]] |
| **`StatusText`** | 状态栏那一行"AI 感知：已启用（DirectML \| 模型 \| ROI \| 滤波）"——排查第一现场。 |
| **`logs/ai`** | AI 运行日志目录：JSONL 每帧记录 + ROI 图环形缓冲（默认 2GB）。**出问题先看这里**，能直接看到"模型看到了什么"。 |
| **GBK 崩溃** | Windows 控制台默认 GBK 编码，打印 emoji 会抛异常。所有 Python 脚本首行都 `import _console` 做 UTF-8 护栏。见 [[坑-GBK控制台崩溃]] |
