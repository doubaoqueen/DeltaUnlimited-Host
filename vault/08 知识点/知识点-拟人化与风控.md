# 知识点：拟人化与风控

> [!info] 一句话
> 机器人最容易暴露的地方不是"它做得对不对"，而是"**它做得太整齐**"——瞬间移动、笔直路径、匀速、每次间隔都一样。拟人化就是把每一条"规律"换成"范围"，而风控的第一原则不是"更聪明"，是**低频 + 人在场**。

## 为什么需要它（在这个项目里）

这个项目做的是**屏幕截图 + 键鼠模拟**的桌面自动化。从游戏服务器的视角，它看到的是"一个客户端在发输入"——如果这些输入的**时间分布**和**轨迹形状**明显不像人，那就是一个可检测的特征。

> [!warning] 清醒的话要写在前面
> 拟人化只能**降低机械感**，**不等于免疫风控**。这也是项目坚持半自动、低频使用、每日限额的原因。任何"我加了随机数所以安全"的想法都是自欺。

## 原理（够用就好）

### 机械规律 = 可检测特征

人的操作有三个"不规律"：

| 维度 | 人的样子 | 机器的默认样子 |
|---|---|---|
| **轨迹** | 弧线、有抖动、常常冲过头再拉回 | 两点之间一条直线 |
| **节奏** | 有时快有时慢，会停顿思考 | 每次间隔一模一样 |
| **时长** | 按键时长有波动（90-180ms 都正常） | 固定 100ms |

所以拟人化的做法就是**逐个维度注入随机性**，而且要注意：**随机本身也会形成特征**——如果每次都从同一个分布里抽，样本一多还是能统计出来。所以参数必须是**范围**且彼此独立。

> [!danger] 项目铁律
> `runtime.json` 里写着：**humanizer 全部参数必须保持随机范围（min/max 或概率），禁止改为固定值。**
> 原因很直白：**固定的"拟人轨迹"跑上一百次，本身就成了最明显的机器特征。**

### 轨迹：给鼠标一条"不直"的路

`MousePathPlanner` 给每次移动叠加四层：

| 层 | 做法 | 像人的哪一点 |
|---|---|---|
| **贝塞尔弧线** | 控制点 = 中点 + 法向随机偏移（幅度受 `curvature_max_px` 限制） | 人的手腕是转的，路径天然带弧度 |
| **smoothstep 缓动** | `e = t²(3-2t)`：起步慢 → 中途快 → 收尾慢 | 手先加速再减速，不是匀速 |
| **逐点抖动** | 途中每点 ±`jitter_px`（末点**必须精确**） | 手有微小颤动 |
| **随机过冲** | 概率 `overshoot_probability`，沿末段冲出 5-22px 再收回 | 人甩鼠标常"冲过头再拉回来" |

还有两个细节很讲究：

1. **落点用绝对坐标归一化（SendInput 的 0-65535）**，不受系统"提高指针精确度"（鼠标加速）影响——保证**像素级精确**；
2. **拟人化只作用在"移动过程"**，落点绝不抖——否则点击会飘。

### 节奏与时长：把"节拍器"拆掉

| 参数（`runtime.json → humanizer`） | 范围 | 作用 |
|---|---|---|
| `click_pause_min/max` | 150 / 320 ms | 点击后的停顿 |
| `press_hold_min/max` | 100 / 220 ms | 按下保持时长 |
| `key_tap_min/max` | 35 / 90 ms | 轻敲时长 |
| `key_gap_min/max` | 15 / 30 ms | 连招之间的间隔 |
| `mouse_step_delay_min/max` | 3 / 11 ms | 鼠标路径点间隔 |
| `hold_jitter_min/max` | 0.92 / 1.08 | 长按时长的乘性抖动 |

还有 `servo.turn_gain_min/max`（0.35-0.55）、`turn_jitter_px`（12）——**转向也是随机的**，因为"每次都精确转 260px"本身就是特征。

### 为什么"低频 + 人在场"比"更聪明"重要

这是整个项目最反直觉、也最重要的一条：

| 做法 | 效果 |
|---|---|
| 把拟人化做到极致，7×24 挂机 | 行为再像人，**时长分布**也不像人（真人不会连续 12 小时每局都跑同样的路线） |
| 拟人化一般，每天跑 1-2 小时且人在旁边 | 时长、时段、失败处理都天然合理 |

所以项目设了**会话限额**（`runtime.json → session_limits`）：

```json
"max_minutes_per_day": 240,     // 每日累计 4 小时后自动停止
"max_matches_per_day": 0        // 0 = 不限局数
```

这条限额是**自控红线**（`docs/项目大纲.md` §7："自控，别真挂机一整天"），不是技术限制。

## 在本项目中的用法

| 位置 | 内容 |
|---|---|
| `Input/MousePathPlanner.cs` | 纯逻辑路径规划器（可单测）：终点精确、短距单步、弧线偏离、过冲收回、步数随距离 |
| `Input/InputService.cs` | `ClickAt`（移动 + **落点校验**）、`MoveHumanized`、`PressKey`、`HoldKey(s)`、`PressKeys`（持续移动）、`ReleaseAllHeldKeys` |
| **落点校验**（fail-open） | 点击后读回光标实际位置，偏差 > `verify_tolerance_px`（默认 6px）→ 直接绝对钉正一次 → 仍偏就**放弃点击**返回 false。**绝不盲点** |
| 参数注入 | `InputService.Configure(config)` 从 `runtime.json → humanizer` 读，启动时注入；调参不改代码 |
| 其它随机化 | `servo.turn_gain_min/max`、`turn_jitter_px`、`deadzone_px`（40）、`max_turn_per_cycle`（260） |
| 急停 | GUI 按钮 / Ctrl+C / 暂停面板"中止"三路同源，任何路径都**释放所有按住的键** |

## 常见误解 / 坑

> [!warning] 误解 1："随机数越大越安全"
> 过大的随机反而异常：真人不会每次点击前停 2 秒。参数要**贴人**，不是贴"随机"。项目给的都是 150-320ms、35-90ms 这种"人体尺度"的区间。

> [!bug] 坑 2：把随机参数"调优"成固定值
> 调参时最危险的动作：发现某个值好用，就写死它。这直接违反铁律，而且**单测不容易发现**（每次跑都对，只是不再随机）。改 `runtime.json` 时一定要检查 min/max 是否成对存在。

> [!bug] 坑 3：末点也加抖动
> 移动过程中抖动没事，**末点抖一下，点击就可能点到别的元素上**。`MousePathPlanner` 里那句 `if (i < steps)` 就是为此——末点严格等于目标。

> [!bug] 坑 4：以为"落点校验"多余
> 没有校验时，任何坐标换算 bug 都会变成"安静地点错地方"。有了校验，超出 6px 就放弃——**宁可不动，不可乱动**（fail-open 思路）。这条也顺带帮我们抓到过真实的坐标偏移问题，见 [[坑-ClickAt点到光标位置]]。

> [!danger] 坑 5：把拟人化当"免责声明"
> 加随机数不等于合规，也不等于安全。项目文档原话：**以上手段只降低风险，不保证不被风控；请谨慎、低频使用。**

## 一句话记住

**机械规律才是可检测特征——轨迹要弧、要有抖动、要偶尔冲过头，节奏要落在人体尺度上，而且**参数永远保持范围**；但真正管用的不是拟人化本身，是"每天 4 小时、人在旁边"这条自控线。**
