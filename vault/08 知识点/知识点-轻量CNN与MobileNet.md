# 知识点：轻量 CNN 与 MobileNet

> [!info] 一句话
> 卷积网络就是**一堆"小放大镜"在图上滑来滑去找特征**：先找边缘，再找纹理，再找形状，最后把这些线索汇总成一个判断。MobileNet 是专门把这件事做"便宜"的版本——用**深度可分离卷积**把算力砍掉一个数量级，好塞进 12GB 显卡和几毫秒的预算里。

## 为什么需要它（在这个项目里）

要回答的问题很小：**这 648×324 的一块画面，往前走会不会被挡住？**

- 不能太重：伺服 5-10Hz，推理预算毫秒级；
- 不能太大：要和 9.6GB 的 vLLM 服务共享一张 12GB 卡（还不能同时跑）；
- 不能太笨：要能区分"地砖"和"墙壁"，"远处地面"和"贴脸怼墙"。

MobileNetV3-Small 正好卡在这个甜蜜点上：**6 MB、112×224 输入、约 0.8-0.9ms/帧**。

## 原理（够用就好）

### 卷积在干什么

想象你拿一个 3×3 的小窗口在图上滑动，每到一处就做一次"加权求和"，把结果写成一个新像素。这个小窗口就是**卷积核**，它的权重是**训练学出来的**。

| 层的深浅 | 学到的东西 | 类比 |
|---|---|---|
| 浅层 | 边缘、色块、明暗边界 | 先看清"哪里有线条" |
| 中层 | 纹理、角、简单图案 | 认出"这是砖纹/金属反光" |
| 深层 | 物体部件、整体形状 | 判断"这是墙/地面/箱子" |

两个关键性质让它比"全连接"省得多：

1. **局部感受野**：每个输出只看输入的一小块（因为墙就是由局部纹理决定的，不需要看整张图）；
2. **权重共享**：同一个卷积核全图复用（"墙的纹理"出现在画面哪个角落都该被认出来）。

### 深度可分离卷积：MobileNet 的核心一招

普通卷积一次干两件事：**在空间上找模式** + **在通道间混合信息**。MobileNet 把它拆成两步：

| 步骤 | 干什么 | 代价 |
|---|---|---|
| **Depthwise（深度卷积）** | 每个通道**各自**做 3×3 卷积（通道之间不混合） | 很便宜 |
| **Pointwise（逐点卷积）** | 用 1×1 卷积在通道之间做加权组合 | 也便宜 |

对比普通 3×3 卷积，理论算力大约降到 **1/8 ~ 1/9**（3×3 卷积的近似是 `1/9 + 1/N`，N 是通道数）。

生活化类比：普通卷积像"每做一道菜都要把全部调料重新配一遍"；深度可分离是"先各自处理主料，最后统一调味"——**工序拆开，总开销小得多，味道差不太多**。

MobileNetV3 还加了两个小设计：

- **SE 模块**（Squeeze-and-Excitation）：给每个通道算一个"重要度"，重要的放大、不重要的压低；
- **h-swish 激活**：比 sigmoid 便宜、比 ReLU 平滑，量化友好。

### Attention 之外，别忽略"输入尺寸"这件事

112×224 **不是随便定的**，它有两个含义：

1. **比例 2:1**，跟 ROI 648×324 的比例一致——所以缩放不会把画面拉扁；
2. **112 高** 意味着模型看到的是"一条横带"，横向 224 像素能看到更宽的视野（左右有没有墙），纵向分辨率低一些（远处/近处的地面差异被压缩）。

代价是：**远处的细节看不清**。这也是为什么 v2 计划用"双带 ROI"（近带判 blocked、远带判 Warn）——同一个分类器喂两块区域，而不是硬把一大块塞进 112×224。

## 训练时真正影响结果的几件事

模型结构是现成的（torchvision 一行 `mobilenet_v3_small`），真正决定成败的是训练配置：

| 技巧 | 本项目做法 | 为什么 |
|---|---|---|
| **迁移学习** | 默认加载 ImageNet 预训练权重（`--scratch` 只作对照） | 小数据集上，预训练明显优于从零训练 |
| **类别不平衡** | 逆频率权重 `total/count`，再 `clamp(max=5.0)`（`--weight-cap`） | passable 是 no_ground 的 28 倍；不压上限，损失会被单一小类垄断 |
| **缺类保护** | `per_class_f1` 对该类记 **0** 而不是 1 | 早期记 1 会让 macro-F1 虚高、门禁误放行（2026-09-30 修正） |
| **学习率调度** | AdamW + 余弦退火（`CosineAnnealingLR`） | 简单稳定，末段自动收小 |
| **模型选择** | 按 **val macro-F1** 存 best（不是 loss、不是 accuracy） | 门禁看的就是 macro-F1 |
| **增广** | ColorJitter / RandomJpeg / 水平翻转 | 抗赛季光照漂移 + 对齐 JPEG 压缩差异 |
| **badcase 容错** | 读图失败就随机换一张，连续 4 次才报错 | 一张坏图不该中断 30 个 epoch 的训练 |

## 在本项目中的用法

| 位置 | 内容 |
|---|---|
| `ai-training/src/model.py` | `build_mbv3s`（替换 `classifier[3]` 为 3 类）、`build_tiny`（极简 CNN，约 0.2ms，算力受限时用）、`CLASSES` / `INPUT_SIZE` / `IMAGENET_MEAN/STD` |
| `ai-training/src/train.py` | 训练循环、按类 F1、macro-F1、best checkpoint（含类别表 + 输入尺寸 + 混淆矩阵） |
| `ai-training/src/dataset.py` | 会话级切分、增广、类别权重 |
| 运行时 | `PassabilitySensor` 做预处理，`OnnxRunner` 推理，`PassabilityFilter` 做时域滤波 |

> [!tip] 为什么 checkpoint 里要存 `classes` 和 `input_size`
> 因为导出/评估时要用它们重建模型结构。如果只存 `state_dict`，加载时得靠人记住"这是 3 类还是 2 类、输入是 112×224 还是 224×112"——记错就是一次静默的错误。

## 常见误解 / 坑

> [!warning] 误解 1："输入越大越准"
> 不一定。112×224 是精度/速度/显存三方妥协的结果。盲目上 224×448 会让推理变慢 4 倍、显存变大，而可通行性这种任务**瓶颈在数据覆盖，不在分辨率**。

> [!warning] 误解 2："accuracy 高就行"
> 类别不平衡时 accuracy 会骗人：三类里 passable 占 69%，**全猜 passable 也有 0.69 的 accuracy**。所以门禁用 **macro-F1**（三类 F1 的平均，小类一样有权重）。

> [!bug] 坑 3：val 里没有某一类
> `stratified_split` 会打印警告。此时该类的 F1 按 0 计入 macro-F1——指标会偏低，但这比"记 1 分假装完美"安全得多。看到"⚠ 类别 X 只出现在同一会话"就去补采。

> [!bug] 坑 4：改了 `weight_cap` 不重训就对比指标
> 这是两套不同的损失函数，指标不可直接比。要比较，必须同数据、同种子、只改一个变量。

> [!note] 坑 5：把模型当"检测器"用
> 三分类只回答"这一块整体能不能走"，**不告诉你障碍物在哪**。想知道"哪个箱子可交互"，得换检测任务（见 [[知识点-YOLO与目标检测]]）。

## 一句话记住

**CNN = 小放大镜层层找特征；MobileNet = 把"找特征"和"混通道"拆开做，便宜 8 倍；本项目靠 112×224 + 迁移学习 + 类别权重 + 增广，把 6MB 的模型训到能用。**
