# 知识点：坐标系统与地图

> [!info] 一句话
> 这个项目里同时活着**四套坐标**（世界坐标、底图像素、设计分辨率、屏幕像素），每一套都有自己的原点和单位。所有"点错位置""定位偏移"的经典事故，本质都是**把一个坐标系里的数直接拿到另一个坐标系里用**。

## 为什么需要它（在这个项目里）

同一句话"撤离点在那边"，在四个地方是四个完全不同的数字：

| 场景 | 用的坐标 |
|---|---|
| 官网地图数据 | 世界坐标，x/y 几十万量级 |
| 官方底图（4096×3072） | 底图像素，来自瓦片拼接 |
| 识别/标定 | 设计分辨率 1920×1080 |
| 点击鼠标 | 屏幕物理像素（还受窗口位置和 DPI 影响） |

只要有一处没换算，结果就是"点到了旁边"或者"定位飘到别的城市"。

## 四套坐标，逐个说清

### ① 世界坐标（游戏世界的米/单位）

游戏内部的坐标系，`x`/`y` 都是**几十万**量级（例如 `x=343938, y=-797007`）。官网地图工具的 JS 数据里存的就是它。

特点：**与分辨率无关、与窗口无关**，是最"客观"的一套。缺点是**没法直接画到图上**——得先换算。

### ② 底图像素（官方大地图）

官网用 Leaflet 瓦片拼出来的静态大图，零号大坝室外图是 **4096×3072**（z=4 时 16×12 块 256px 瓦片，188/192 成功，缺的 4 块在边界外）。

这一层是"地图上的位置"，单位是像素。所有点位表（`data/zero_dam_points.json` 的 `map_px`）都存在这一层。

**世界坐标 → 底图像素**的换算（来自官网 `main.js` 的 `getMapPos` / `getSourceMapPos`）：

```
lng = 128 - (centerX - worldX) / xB2       # centerX = 358155.6875, xB2 = 633.486755
lat = -128 - (centerY + worldY) / yB2      # centerY = 750191.75,  yB2 = 632.722656
px  = lng * 2^z                            # z = 4 → 每单位 16px
py  = -lat * 2^z
```

看着像玄学，其实就三步：**先平移到地图中心 → 再除以比例尺 → 再乘 2^z 换成像素**。`2^z` 是 Leaflet 的 CRS.Simple 约定（每放大一级，像素翻倍）。

> [!tip] 坐标系必须先自校验，再去用它
> 1423 条物资点算完，**1422 条落在 4096×3072 图内**，且分布合理（x 974-3076、y 643-2222，留了边距）——这才证明公式和参数都对。
> **这个习惯比公式本身重要**：任何一个新坐标系，先拿已知点验一遍，别直接拿去生产。

### ③ 设计分辨率（1920×1080）

项目的**识别与标定基准**。所有模板、ROI、元素坐标、界面标记，全部写在 1920×1080 上。

为什么要有这一层：因为游戏窗口大小会变（窗口化、不同显示器、DPI 缩放）。如果模板直接按"当前屏幕"裁，窗口一改就全废。所以：

```
运行时帧（任意尺寸） --FrameTools.Normalize--> 1920×1080 --识别--> 结果在设计坐标系
```

这一层是"**归一化**"思想的体现：**把变化挡在外面，让里面永远面对同一个世界**。

### ④ 屏幕像素（点击用）

鼠标只能点屏幕上的物理坐标。从设计坐标到屏幕坐标要过两道：

```
设计坐标 ──(× 客户区尺寸/设计尺寸)──> 客户区坐标 ──(+ 客户区屏幕原点)──> 屏幕坐标
```

代码就是 `CaptureService.MapDesignToScreen`：

```csharp
double fx = client.W / (double)designW;
double fy = client.H / (double)designH;
return ((int)Math.Round(client.X + designX * fx),
        (int)Math.Round(client.Y + designY * fy));
```

**两个细节决定成败**：

1. **等比缩放**：`fx`/`fy` 分别算，不要假设窗口一定是 16:9（窗口可以被拉成任意比例）；
2. **视口偏移**：`client.X/Y` 是客户区在屏幕上的左上角。窗口不在 (0,0) 时，漏了它就会整体偏移一个窗口位置。

## 为什么"屏幕坐标点错位"是经典事故

历史上真踩过（见 [[坑-坐标缩放偏移]]）：

> **截图按窗口客户区取，点击按全屏坐标点。**

后果：窗口化模式下，识别是对的（图里确实有那个按钮），点击却点到别处——因为识别结果的 (x,y) 是"客户区内的坐标"，而点击 API 以为是"屏幕坐标"。

这类 bug 有三个特征，很好认：

| 特征 | 说明 |
|---|---|
| **识别成功、点击失败** | 日志里"命中 0.95"，但界面没变 |
| **全屏模式正常，窗口化就错** | 因为全屏时客户区原点恰好是 (0,0) |
| **偏移量 = 窗口位置** | 把错误坐标减去 `client.X/Y` 就对了 |

修法只有一条：**所有点击/移动前，必须走 `MapDesignToScreen`**（`ElementClicker` 与 `OperatorPicker` 都强制这么做，且有单测钉住）。另外还要开 **Per-Monitor V2 DPI 感知**，否则系统缩放（125%/150%）会再插一脚。

## 小地图这一层：坐标还要再多想一步

小地图定位的本质是"**在一块大图里找一小块**"，所以同时涉及三层：

```
局内帧（1920×1080）
  └─ 裁小地图面板：圆心 (165,185)、半径 ~120-129 的【圆】
        └─ 灰度 + 缩放 → 模板
              └─ 在底图（4096×3072，可先降采样）上多尺度 NCC
                    └─ 命中点 = 底图像素坐标 → 反算世界坐标 → 查最近点位
```

三个常见误区：

| 误区 | 事实 |
|---|---|
| 小地图是个矩形面板 | 它是**圆形**罗盘。第一版按矩形裁，用户一眼看出"完全不是"（见 [[坑-小地图圆形vs矩形]]） |
| 找最高分就够了 | 分数不是置信度。0.904 分也可能是错的位置（地形重复） |
| 尺度只有一个 | 小地图缩放未知，同一局相邻帧的最佳尺度在 150/210/380 之间跳——需要尺度先验 |

还有一层隐藏问题：**室内/地下的小地图是另一张图**。室外 `map_db` 用 `bj=128`，楼层图（`daba_0f` / `daba_1f` / `daba_2f`）用 `bj=64`，**换算参数不同**——所以楼层坐标系必须单独标定，不能拿室外公式套。

## 一个实用检查清单

任何"图上坐标"相关改动，按顺序过一遍：

- [ ] 这个坐标属于哪一层？（世界 / 底图 / 设计 / 屏幕）
- [ ] 目标层需要什么换算？（`MapDesignToScreen`？`getMapPos`？只是 ×缩放比？）
- [ ] 有没有**原点偏移**没加/没减？（客户区原点、裁剪偏移 `offX/offY`）
- [ ] 给的是**中心点**还是**左上角**？（差半个宽高）
- [ ] 送图给模型前缩放过吗？返回的框除回 scale 了吗？
- [ ] 有没有用已知点自校验一次？

## 常见误解 / 坑

> [!warning] 误解 1："坐标不就是 x,y 吗"
> 同一个 (100, 100)，在四套坐标里指四个不同的地方。**坐标必须带"坐标系标签"才有意义**——所以本项目所有字段都写清 `map_px` / 设计坐标 / 屏幕坐标。

> [!bug] 坑 2：以为"等比缩放"就是"乘一个数"
> 宽和高的缩放比可能不同（窗口被拉伸），必须 `fx`/`fy` 分别算。用同一个 `f` 会在非 16:9 窗口下逐渐偏移。

> [!bug] 坑 3：漏了裁剪偏移
> 在 ROI 里找到目标，返回的坐标是**ROI 内坐标**，必须加回 `rx/ry` 才是全帧坐标。`TemplateMatcher` 和 `WindowsOcrEngine` 都显式做了 `offX/offY` 回加——这类"局部坐标忘记还原"是最常见的静默 bug。

> [!bug] 坑 4：以为 DPI 缩放不影响
> 系统 150% 缩放下，截图尺寸和点击坐标都可能被"逻辑像素"污染。项目用 `EnsureDpiAwareness()`（Per-Monitor V2）先把这个变量锁死。

> [!note] 坑 5：忽略画面比例
> 如果运行时窗口是 2560×1440 而设计是 1920×1080，比例恰好相同（都是 16:9），换算很安全；但 21:9 或 4:3 窗口下会拉伸，位置就会偏——这时要么强制窗口比例，要么接受误差。

## 一句话记住

**先还原再使用**——把任何坐标先还原到"设计分辨率"这一层，再用 `MapDesignToScreen` 送到屏幕；世界坐标 ↔ 底图像素走官方公式，且必须先用已知点自校验。
