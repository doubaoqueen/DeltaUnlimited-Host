# 知识点：工程实践

> [!info] 一句话
> 这个项目里反复用到的八条方法论——**每条都能在仓库里指出一处真实代码或一次真实决策**，不是空话。看懂它们，比看懂任何一个算法都值钱。

## 为什么专门写一篇"方法论"

因为这个项目踩过的坑，**大部分不是算法错，是流程错**：验证顺序错了、数据写死在代码里、失败时选择了"赌一把"、改了配置忘了同步另一处。算法在网上有教程，流程只能从自己的失败里长出来。

## ① 决策记录：带日期和理由

**做法**：每个重要决定都记"什么时候、为什么这么定、当时放弃了什么"。**允许翻案，但不许抹掉旧记录。**

**真实例子**：2026-09-26 定了铁律"**全流程禁止预设路线**"（理由：地图随赛季变，路线表维护成本高）。2026-10-21 用户**推翻了它**——因为研究零号大坝后发现：物品刷新位置固定、出生点只有 14 个、撤离点分类型，"每个出生点离哪几个撤离点近"可以提前算。新原则是"**路线是计划，感知是裁判**"。

项目里的原话值得抄下来：

> 翻案不可耻，假装自己从没错过才可怕。

**为什么重要**：如果你只保留"最终结论"，三个月后你会忘记"当初为什么这么定"，然后在一个已经变了的世界上继续执行旧结论——或者更糟，反复推翻又重建，每次都不知道上次为什么放弃。

## ② 数据驱动：改数据不改代码

**做法**：把所有"会变的东西"抽成 JSON/CSV，代码只负责"解释执行"。

**真实例子**（一个加界面不用改代码的完整链路）：

| 想改什么 | 改哪 | 代码要不要动 |
|---|---|---|
| 机器人认识哪些界面 | `data/screens.json`（`markers` + `require_all`） | 不动 |
| 按钮是 OCR 还是模板还是固定坐标 | `data/elements.json` 的 `strategy` 字段 | 不动 |
| 拟人化停顿多长 | `data/runtime.json → humanizer` | 不动 |
| 模型用哪个、ROI 在哪、阈值多少 | `data/ai_vision.json` | 不动 |
| 转 90° 要多少像素 | `data/runtime.json → px_per_90deg` | 不动 |

**反例长什么样**：`if (screen == "plaza_ready") click(1740, 980);` 写死在 C# 里——界面一改版就要改代码、重编译、重测。

> [!tip] 判断标准
> 如果"游戏改版"和"代码改动"之间还需要一个人来做翻译，说明你的抽象没做到位。

## ③ 先验证再投入（P0 闸门）

**做法**：任何"看起来不错的大方案"，先花 1-2 小时做一个**能判死刑的最小验证**。活着才投入，死了立刻收兵。

**真实例子**：

| 方案 | P0 验证 | 成本 | 结果 |
|---|---|---|---|
| VLM 预标注（省 YOLO 标注力） | P0 整帧直问 40 帧；P0.5 两步缩放 35 帧 | 1h + 1-2h | **失败** → 立刻收兵，UI 模板线回人工（见 [[AI-VLM预标注探索]]） |
| 小地图定位（新导航方案） | P0 拿 704 帧里的 8 组样本跑圆形掩膜 NCC | 当天 | **可行** → 才移植到 C# |
| 声音感知 | A1 实证分析（先用已有两局的已知事件时刻验证可行性） | 2-4h（计划） | 未开工，先验证再决定 |

**为什么重要**：P0 + P0.5（方案里估 1 小时 + 1-2 小时，实际一天内跑完两轮）证明了"8B 模型做不了细粒度图标定位"。如果不做这个验证，直接上 P1-P3（批量、GUI、导出，方案里估 7-8 小时），做完才发现能力不成立——损失的是十倍时间，还有信心。

## ④ fail-open：不确定就别动

**做法**：识别不出、拿不准、出异常时，默认"**不操作**"，把决定权交还给人，而不是赌一把。

**真实例子**（四个位置，都是同一原则）：

| 位置 | 行为 |
|---|---|
| `if_ocr` 分支 | OCR 不可用 → **判未命中**，走安全分支，不硬点 |
| `AiVision.Observe` | 单帧推理抛异常 → 吞掉、记日志、返回"无预警"——感知模块永远不许把主流程带崩 |
| `HudStateGate` | 识别不到界面 → **放行**（交给轨迹过滤兜底），而不是拒绝定位 |
| `InputService.ClickAt` | 落点校验偏差 > 6px → 钉正一次 → 仍偏就**放弃点击**返回 false |

**配套思路**：识别失败时不是"静默跳过"，而是 `mark_unknown`——截图 + OCR 词表存证 + 暂停等人工。**失败也要留下证据**，否则你永远不知道为什么失败。

> [!warning] fail-open 不是"什么都不做"
> 它是"**做最保守的那件事，并且记录**"。静默吞掉异常不叫 fail-open，叫隐藏 bug。所以上面每一条都配了日志。

## ⑤ 合成自检：自己出题自己答

**做法**：不依赖真实素材，**人为造一个"已知答案"的输入**，验证算法能不能找回来。

**真实例子**（三处，层层递进）：

| 位置 | 怎么造 | 判据 |
|---|---|---|
| `LocalizerTests.MakeSynthetic` | 1200×900 噪声底图 + 红方块 + 绿圆 + "ZONE"文字；帧里把小地图内容画进圆形面板 | 应该找回 (550,450) 附近 |
| `minimap_localizer.py --selftest` | 从底图挖 300×300 一块、缩到 150 当模板，再匹配回去 | `score > 0.9` 且位置误差 <20px |
| `smoke_test.py` | 伪造 3 类 × 12 个"分钟会话"的随机噪声图 + manifest | 全链路可执行（**不验证精度**） |

**为什么重要**：真实素材缺失时，合成自检是唯一能证明"我的实现没写反"的东西。它抓到的正是最隐蔽的 bug——**NCC 分子多减一次均值**，分数全变 -2，肉眼看代码根本看不出来（见 [[坑-NCC分子多减一次]]）。

## ⑥ fixtures：真机帧回归，缺了就跳过

**做法**：把真机截图放进 `tests/fixtures/`，测试里"素材在就跑真机回归，素材不在就跳过"，**不允许因为缺素材而失败**。

**真实例子**：`FixtureFrames.RunIfAvailable(name, assertion)`——`Has/Load` 判断存在性，不存在直接 `return`（跳过）。素材目录已在 gitignore（真机帧含账号信息，不进库），由用户采后人工放入。

用途：`LocalizerTests.Fixture_BackpackFrame_IsGatedByHudStateGate` 用一张**真实的背包帧**钉住"背包界面不该定位"这条规则，还顺手抓出了 `match_backpack` 关键词不稳的问题（见 [[坑-背包界面不是小地图]]）。

**为什么重要**：纯合成测试能证明"算法对"，但证明不了"**对这张真实截图也对**"。fixtures 是二者之间的桥；"缺失跳过"则保证 CI 在干净机器上也能绿。

## ⑦ 门禁：让"能不能上"由数字决定

**做法**：关键变更必须有**自动化的准入检查**，不靠"我觉得差不多了"。

**真实例子**：

| 门禁 | 拦什么 |
|---|---|
| **金标集三档**（macro-F1 ≥0.85 / 0.60-0.85 / <0.60） | 拦"模型退化了还上线"；<0.60 直接不启用 |
| **运行期矛盾率**（>25%/10min） | 拦"上线后才变瞎"；超限自动禁用并**写回配置** |
| **`dotnet test`**（200+ 用例） | 拦"改 A 坏 B"；坐标换算、路径规划、滤波、门禁逻辑都有断言 |
| **`per_class_f1` 缺类记 0** | 拦"指标虚高导致门禁误放行"（早期记 1，2026-09-30 修正） |

**设计要点**：门禁要**自动执行**（启动时回放金标、运行中算矛盾率），否则它只是文档里的一句话。

## ⑧ 可观测性：出问题能看见

**做法**：每个环节都留下"能事后回看的痕迹"，而不是只有一个最终结果。

**真实例子**：

| 痕迹 | 内容 |
|---|---|
| `logs/ai/*.jsonl` | 每帧的类别、置信度、延迟、帧差、预警级别 |
| **ROI 图环形缓冲**（2GB） | 每帧送进模型的那张小图都留着——出问题直接看图 |
| `SnapshotStats()` | 巡逻收尾打印 帧数 / blocked 预警数 / 矛盾数 |
| `StatusText` | 状态栏一行说清"跑在哪（DirectML/CPU）、哪个模型、ROI、滤波配置、是否被降级" |
| `ChangeGate.Skipped` | 变更门跳过了多少轮识别（诊断"是不是太频繁识别了"） |
| `LogWindowAnchor` | 一行打印 屏幕/DPI/窗口矩形/客户区/缩放比——坐标问题的第一现场 |
| `mark_unknown` | 未知界面截图 + OCR 词表，存 `screenshots/unknown/` |

**为什么重要**：`StatusText` 里那句 "DirectML | passability_v1.onnx | ROI [...] | 滤波 3/5" 看起来平平无奇，但它能在 5 秒内回答"它到底加载了什么、跑在哪、配置对不对"——这是最容易出错的三个地方。
