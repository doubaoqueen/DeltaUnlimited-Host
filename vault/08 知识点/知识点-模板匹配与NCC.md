# 知识点：模板匹配与 NCC

> [!info] 一句话
> 模板匹配就是**拿一张小图去大图上"逐格比对"，找最像的那个位置**；NCC 是"比得像不像"的打分方式，它先减去亮度均值、再除以明暗幅度，所以**画面整体变亮变暗都不影响得分**。

## 为什么需要它（在这个项目里）

链路的很多判断是"**屏幕上有没有这个东西**"：

- 备战界面右下角有没有"出发"按钮 → 有就点；
- 地图屏上撤离点图标是亮的还是灰的 → 决定去哪个撤离点；
- 确认配装按钮长什么样 → 点击前先确认它真的在那。

这些目标**长得固定、位置不固定**，而且很多是美术字（OCR 会稳定误读），所以最可靠的办法是：把这个图标裁成一张小图存起来，运行时在屏幕上找它。

## 原理（够用就好）

### 第一步：滑窗

把模板（比如 120×40 的按钮小图）放到大图的左上角，算一个"相似分"；然后往右挪 1 像素，再算；挪到头换下一行……直到全图扫完。分数最高的那个位置就是答案。

生活化地说：**拿一张透明底片在照片上一点点挪，看哪一格最对得上。**

### 第二步：怎么算"相似分"

最朴素的想法是**逐像素相减**（差越小越像）。它有两个致命毛病：

| 毛病 | 例子 |
|---|---|
| 对整体亮度敏感 | 夜里截的模板，白天用，每个像素都差 40，于是"完全不像" |
| 对对比度敏感 | 起雾了、被闪光弹照了，像素差全变大 |

**NCC（归一化互相关，Normalized Cross-Correlation）** 就是来治这两个病的。它的做法是：

1. 先把模板和它盖住的那块图**各自减去自己的平均值**（去掉"整体亮度"这个共同偏移）；
2. 再算"方向是否一致"（点积）；
3. 最后**除以两者的波动幅度**（标准差）——把"对比度大小"也归一化掉。

公式（看懂结构就行，不用背）：

```
score = Σ((T - T̄)·(I - Ī)) / sqrt( Σ(T - T̄)² · Σ(I - Ī)² )
```

结果的取值范围是 **-1 到 1**：

- **1** = 完全一致（同样的图案，同样的明暗关系）；
- **0** = 毫无关系；
- **负数** = 明暗关系反了（白底黑字 vs 黑底白字）。

因为分子分母都有"幅度"，你把整张图调亮 20%，分子分母同时变大，**分数不变**——这就是"归一化"的威力。

> [!note] OpenCV 里的名字
> `TemplateMatchModes.CCoeffNormed`（相关系数归一化）。`C` 是 coefficient（系数，已去均值），`Normed` 是归一化。仓库里 `TemplateMatcher` 与 `tplprobe` 都用它。

### 第三步：阈值怎么定

阈值是"多像才算有"。它**不是概率**，是经验安全线：

| 阈值 | 用在哪 | 为什么是这个数 |
|---|---|---|
| **0.85** | `screens.json` / `elements.json` 的 `template` 标记 | 同一台机器、同一画质下真命中的分数通常明显高于它；0.85 既留了余量，又不至于乱认 |
| **0.50** | 小地图定位器 `MinScore` | 那是"模糊匹配"任务（地形缩放未知），分数天然低；且 CCOEFF 分数比 Python 掩膜 NCC 低约 0.1-0.2 |

调阈值的本质是**在"漏检"和"误检"之间选一个你更能忍的**。跑刀场景里通常宁可漏检（顶多不点，等人工），不可误检（点错地方）。

## 在本项目中的用法

| 位置 | 干什么 |
|---|---|
| `Vision/TemplateMatcher.cs` | 内存模板匹配：`Match(frame, templatePath, threshold, region?)` → `MatchResult(Found, Confidence, CenterX, CenterY, W, H)`。模板按路径缓存在 `ConcurrentDictionary`，避免循环里反复读盘 |
| `region` 参数 | 只在指定矩形内搜索——更快，也更抗干扰（别的地方有长得像的东西也不管） |
| 通道转换 | 实时帧是 **BGRA 4 通道**，模板是 **BGR 3 通道**；`TemplateMatcher` 内部自动 `BGRA2BGR`，否则 OpenCV 会直接抛异常 |
| 中心点计算 | 返回的是 `offX + maxLoc.X + tpl.Width/2`——**模板中心**，不是左上角。点错位置多半是这里漏了半宽 |
| 模板缓存 | `ClearCache()` 给程序退出/测试清理用 |
| `tplprobe` | 单张截图的模板匹配诊断：给截图 + 模板，打印置信度与命中位置。**怀疑模板坏了，先跑它**，不要在整条链路里猜 |
| `annotate` | 把命中位置画绿框 + 中心十字，输出到 `screenshots/annotated/`——"看得见的识别冒烟" |
| `match_map`（Python） | 小地图定位器里返回**完整得分图**而不是只取最大值，用于多峰分析（"还有几个位置分数也不错"） |

## 常见误解 / 坑

> [!bug] 坑 1：纯色/低方差 → 假匹配（分数爆炸）
> NCC 的分母里有"局部方差"。如果模板或候选区域几乎是**纯色**（大片纯黑边框、一片天空），方差接近 0，除下去分数会从 [-1,1] 炸到 **28、346486** 这种离谱值。
> **修法**：给方差设下限，低方差区域直接判无效（`minimap_localizer.py` 里 `MIN_STD = 0.012`，低于它 `score = -1`）。详见 [[坑-模板零方差假匹配]]。

> [!bug] 坑 2：NCC 分子多减一次均值
> 用圆形掩膜做 NCC 时，分子需要"去均值后的互相关"。若在一个**已经去过均值**的结果上又减一次均值，同一位置的分数会变成 -2（本该 +1）。这种 bug 分数**全是负的**、看起来像"完全不像"，很容易误判成"模板不对"。
> **修法**：写合成自检——从大图里挖一块当模板再匹配回去，位置必须对、分数必须 ≈1。详见 [[坑-NCC分子多减一次]]。

> [!bug] 坑 3：缩放过
> 模板是在 1920×1080 下裁的，如果窗口被拉成 1600×900，模板会比目标大一圈，0.85 的阈值永远过不了。
> **修法**：所有识别前先 `FrameTools.Normalize` 把帧归一到设计分辨率（1920×1080）。这是铁律不是建议。

> [!bug] 坑 4：UI 改版
> 游戏一更新，按钮换了皮肤/加了描边，模板就废了。模板匹配**没有泛化能力**——它只会认"像素长得一样的东西"。
> **修法**：模板跟赛季一起维护；或者该处改用 OCR（文案通常比美术风格稳定）；或者两者组合成"多标记"（`screens.json` 的 `markers` 全部命中才算）。

> [!warning] 坑 5：把分数当置信度
> 0.90 分不代表"90% 可能对"。地形重复、UI 元素长得像，都可能让**错的候选拿到高分**（小地图定位里实打实出现过 0.904 分却是错的位置）。
> **修法**：分数只做"候选筛选"，最终靠上下文约束（时间连续性、尺度先验、多标记交叉验证）。

## 一句话记住

**模板匹配 = 用"逐格比对"回答"这个图标在哪"；NCC = 一种减去亮度、除掉对比度的比法；阈值 = 你愿意为漏检/误检各付多少代价。**
