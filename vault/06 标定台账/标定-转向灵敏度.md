# 标定：转向灵敏度（px_per_90deg）

> [!info] 一句话
> `px_per_90deg = 4500`——往游戏里注入 **4500 像素的相对鼠标位移 ≈ 视角转 90°**。
> 所有"转身"动作都靠它换算。它由**鼠标 DPI × 游戏内灵敏度（EDPI）**决定，换设置就必须重标；否则转身要么转不够、要么转过头。

## 数值

| 参数 | 值 | 含义 |
|---|---|---|
| `px_per_90deg` | **4500** | 视角转 90° 需要的相对鼠标位移（px） |
| 转一圈（360°） | 18000 px | = 4 × 4500 |
| 速算 | 90° 的 px = **250 × n** | n = 用 `turn 1000 0` 转满一圈的次数（n=18 → 4500） |
| 存放位置 | `data/runtime.json` | 与 EDPI 绑定，属于"本机 + 本设置"参数 |
| 设计分辨率 | 1920×1080 | 与转向换算无关（相对位移只认鼠标增量） |

**用到它的地方**：

| 命令/模块 | 用途 |
|---|---|
| `drill` | 靶场四边回路：每边"冲刺前进 + 右转 90°（=4500px）" |
| `patrol` | 贴墙/横移低效时右转；也可用第 4 参数临时覆盖 |
| `follow_marker` / 伺服 | 转向增益、死区、单周期钳制**计划按它校准**（`servo.turn_gain` 0.35-0.55、`deadzone_px` 40、`max_turn_per_cycle` 260、`turn_jitter_px` 12）→ ❓增益尚未按实测重标 |

## 怎么标定的

1. 进游戏（靶场或安全角落），**面朝一个固定参照物**（墙角、门框、远处建筑），记下画面；
2. 命令行反复执行 `turn 1000 0`：
   - `turn` 命令内部就是 `InputService.MoveRelative(1000, 0)`（**相对移动**，正好对应游戏读的鼠标增量）；
   - 每步都有帧差验证（"确实转了"才算数）；
3. 数"转了几次才回到原方向"= **n**；一圈 = 1000·n px → **90° ≈ 250n px**；
4. 实测结果落在 **n = 18**（由存档值反推：4500 ÷ 250 = 18）→ 18 × 1000 = 18000 px = 360° → 90° = **4500**；
5. 写进 `data/runtime.json` 的 `px_per_90deg`。

> [!tip] 为什么是 250n
> 转一圈 = 1000n 像素 = 360°，所以 1° ≈ 1000n/360 ≈ 2.78n 像素，90° = 90 × 2.78n ≈ **250n**。n=18 → 4500。

**为什么用"转回原方向"而不是"量 90°"**：转满一圈的终点是最好判断的（同一张画面），误差被 4 等分，比直接用眼睛估 90° 准得多。

## 失效条件（何时需要重标）

| 变了什么 | 要重标吗 | 为什么 |
|---|---|---|
| 鼠标 DPI / 游戏内灵敏度（EDPI） | **必须** | 转角 = 鼠标计数 × 灵敏度，比例直接变 |
| 换鼠标 / 改回报率 / 改驱动设置 | **必须**（同 DPI 也复测一次） | 部分鼠标与驱动会改变实际计数 |
| 游戏版本改了转向手感 | 可能 ❓ | 无实测；改版后跑一次 `drill` 就能看出来 |
| 分辨率 / 窗口大小 / 系统 DPI 缩放 | **不用** | 相对位移只认鼠标增量（前提：游戏读原始鼠标输入；本机实测与窗口尺寸无关） |
| 只在桌面鼠标设置里改指针速度/加速 | ❓待确认 | 游戏一般读原始输入，桌面设置不应影响；本项目未实测 |

### 怎么判断"该重标了"（看症状，不看数值）

> [!warning] 程序不会提醒你
> 只有 `px_per_90deg ≤ 0`（完全没标）时才会告警（`Program.cs` / `GuiApp.cs`）。**填过值以后它再也不提醒**——换了设置得自己想起来重测。

1. **`drill` 跑完 4 段 90° 后没有回到原朝向**（转多了 / 转少了）——最直接的证据；
2. `patrol` 右转后走成斜线，或一直贴着同一面墙打转；
3. 手动验：对着参照物 `turn 4500 0`，看是不是正好 90°；
4. 换完鼠标/灵敏度后**先跑一次 `drill`** 当验收，比事后猜便宜。
