# 标定：界面标记与分组（screens.json）

> [!info] 一句话
> `data/screens.json` 用"**OCR 关键词组合**"认界面：每个界面挂一组标记，标记命中就认它。
> 对局内的 4 个界面用 `group: "match"` 单独分表，并且**每个都用 `require_all` 组合了 2-3 个关键词**——因为单个词会在多个界面同时出现，必然串台。

## 数值

### 分组

| 组 | 数量 | 谁扫它 |
|---|---|---|
| `lobby`（默认值，没写 group 的都算这组） | 13 个 | 进场链路 |
| `match`（局内） | 4 个 | 局内链路、`HudStateGate` |

### 局内 4 个界面（全部 `require_all`）

| 界面 id | 关键词（全部命中才算） | 命中后的动作 |
|---|---|---|
| `match_backpack` | **本局收获 + 胸挂 + 背包** | 按 Tab 关闭背包 |
| `match_map` | **未开启 + 高价值点位** | 标点撤离点 → 关闭地图 |
| `match_settlement_success` | **撤离点 + 本局收获** | 等自动跳转 / 按空格 |
| `match_settlement_fail` | **淘汰者 + 对局时长** | 等自动跳转 / 按空格 |

### 大厅 13 个（标记类型混用模板/OCR）

`lobby`（Tab 提示条模板）/ `mode_select`（精选·战役·烽火地带·前往游玩 任一）/ `space_continue`（"空格继续"模板 + OCR 兜底，`dismiss: space`）/ `plaza_first`（行前备战）/ `plaza_ready`（配装 **+** 出发，`require_all`）/ `map_pool`（零号大坝标题**模板** + OCR 兜底）/ `map_select`（开始行动）/ `loadout`（确认配装）/ `preset_select`（新兵 + 精锐 + 特种，`require_all`）/ `deploy_reminder`（入局提醒 / 仍要继续）/ `settlement`（撤离成功）/ `matching`（取消行动）/ `char_select`（请选择干员 / 当前出战）。

## 为什么必须 `require_all`（这是本篇的重点）

> [!important] 判据不是"这个词重要"，而是"这个词**只有它有 / 只有它没有**"
> 一个好的界面标记词，必须在**其他界面里不出现**。做不到的时候，就用组合把它"独占"出来。

**"本局收获"在三个地方都出现**：背包、撤离成功结算、撤离失败结算。如果只用它一个词：

| 串台后果 | 具体表现 |
|---|---|
| 定位器误跳过 | `HudStateGate` 把"结算帧"认成"背包帧"，两者都判"无小地图"——这次侥幸；但反向就会把背包认成结算，逻辑分支走错 |
| 链路走错分支 | 局内链路看到"本局收获"就去执行"按 Tab 关背包"，实际在结算界面 → 按 Tab 什么也没关，反而把界面搅乱 |
| 统计/回归失真 | fixture 回归里两个界面互相"命中"，测试看着全绿其实测错了 |

加上区分词之后就各自独占了：

| 界面 | 独占它的词 | 为什么能独占 |
|---|---|---|
| `match_backpack` | **胸挂** / **背包** | 结算界面没有这两个词 |
| `match_settlement_success` | **撤离点**（撤离点名标签，如"西区公路"） | 背包界面没有 |
| `match_settlement_fail` | **淘汰者** / **对局时长** | 其他界面都没有 |

> [!warning] 严格匹配是"包含"关系，短词更容易撞车
> OCR 严格命中用的是"单词包含关键词"（`Norm(w.Text).Contains(kw)`，`Norm` = 去空白 + 转小写）。所以关键词"撤离点"会命中"**未开启撤离点**"——而后者是地图屏的图例文字。
> 也就是：关键词要选**长且带区分度**的，再做 `require_all` 组合；不要用两三个字的通用词。

## 怎么标定的

1. **真机截图**：进游戏走到那个界面，截一张（尽量在"特征最全"的时刻）；
2. **`ocr` 命令做词表诊断**：看全帧/区域 OCR 实际读出了什么，分清"严格命中"和"候选命中"——只信严格命中；
3. **选词**：优先选"实测稳定命中 + 别的界面没有"的词；美术字（大标题、卡名）读不出就别硬上，改用**模板**（`tplprobe` 验）；
4. **写进 `data/screens.json`**，把"为什么用这个词、哪个词被否决了"写进该条目的 `note`（这个仓库的数据文件里全是这种实测注释，价值极高）；
5. **`annotate` 复验**：在截图上画出命中位置，肉眼看对不对；
6. **fixture 回归**：把真机帧放进回归集（如 `MatchScreensTests`），钉住"这几个界面不能互相命中"。

### 两个"从失败里选出来"的词

| 界面 | 被否决的词 | 原因 |
|---|---|---|
| `match_backpack` | 剩余离 | OCR 常读成 **刺余 / 离阎**，严格匹配失败 → 换成"本局收获/胸挂/背包" |
| `match_settlement_*` | 撤离成功 / 撤离失败（大标题） | 该两条的 `note` 写的是"大号美术字、OCR **逐字拆分不可拼**" → 换成小字的稳定组合 |

> [!note] 一处结论不完全一致
> `match_settlement_success` 说"撤离成功"读不出，但大厅组的 `settlement` 条目**正是**用"撤离成功"作标记、且注明是"真机 2026-09-21 22:58:08 现场标定"。
> 可能是两次截图的字体/清晰度/缩放不同（也可能是不同的结算画面变体）。❓待确认；在不确认之前，局内组用组合词更稳。

## 失效条件（何时需要重标）

| 变了什么 | 会怎样 | 要做什么 |
|---|---|---|
| 游戏改版改界面文字（最常见） | 关键词不再命中，界面"消失" | 重新 `ocr` 诊断 → 换词 → 更新 note |
| 换语言 | 中文关键词全废 | 整套重标（或用模板替代） |
| 分辨率/UI 缩放导致**区域裁切丢字** | 限定 region 的标记失效 | 去掉 region 改用全帧（`char_select` 就是这么修的：区域裁切会丢"战/请/择"，全帧反而两词都能严格命中） |
| 新界面出现 | 该界面没有标记，识别永远不到它 | 加条目；用 `ScreenDetector.UnconfiguredScreens()` 主动列出"没配标记的界面"，别让它静默 |
| 新条目忘写 `group` | 被当大厅界面，在局内被误扫 | 加条目时检查 `group` |

> [!note] 一处文档与代码不一致
> `docs/模块说明.md` §5 写的是"标记**全部**命中才判定为该界面"，但代码 `ScreenDetector.Scan()` 的实际行为是"**任一** marker 命中即判定"（`data/screens.json` 的说明字段也是这么写的）。
> **以代码为准**；`require_all` 管的是"**同一个 marker 内**的多个关键词"。❓文档待同步。
