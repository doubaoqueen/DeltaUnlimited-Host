# 标定：分层图层（室外 + 三层室内）

> [!info] 一句话
> 零号大坝的官方地图不止一张：**室外主图 `map_db`（4096×3072）**，加三层室内/地下 **`daba_0f` / `daba_1f` / `daba_2f`（各 4096×4096）**。
> 室内段用室外图匹配必然失败——这就是全量轨迹里那批"长时间无定位"帧的主要来源。楼层图已挖通拼好，但**楼层判别和楼层坐标系还没解决**，所以本篇状态是方案稿。

## 数值

| 图层名 | 含义 | 瓦片网格 | 瓦片尺寸 | 拼接结果 |
|---|---|---|---|---|
| `map_db` | 室外主图（P0 一直在用） | 16 × 12 | 256 px | **4096 × 3072** |
| `daba_0f` | 地下通道（B1） | 8 × 8 | 512 px | **4096 × 4096** |
| `daba_1f` | 行政辖区 1F | 8 × 8 | 512 px | **4096 × 4096** |
| `daba_2f` | 行政辖区 2F | 8 × 8 | 512 px | **4096 × 4096** |

| 参数 | 值 |
|---|---|
| 瓦片 URL | `https://game.gtimg.cn/images/dfm/cp/a20240729directory/img/{图层}/{z}_{x}_{y}.jpg` |
| 必需请求头 | `Referer: https://df.qq.com/cp/a20240729directory/`（腾讯 CDN，不带就 **403**） |
| 层级 `z` | 4（`2^4 = 16` 像素/世界单位） |
| 室外世界参数 | `bj = 128`、bounds 81086.304688 × 80988.5、center (358155.6875, 750191.75) |
| **楼层**世界参数 | 来自 `daba_floor.js`：`boundsW/boundsH`、**`bj = 64`**、`pixelToLatLngRatio = -0.85`；**世界坐标中心与室外图一致** |
| 拼接工具 | `ai-training/src/stitch_map_tiles.py`（参数化图层/网格/瓦片尺寸，通用） |

> [!warning] 楼层图的 `bj = 64` 是关键差异
> 室外是 `bj = 128`，楼层是 `bj = 64` —— 所以 **同一套 `map_px ↔ 世界坐标` 公式不能直接套用**。楼层坐标系还没推导/校验，这是硬待办。

## 怎么标定的（其实是"挖瓦片 + 拼图"）

```bash
# 室外主图（已用于 P0）
python ai-training/src/stitch_map_tiles.py --layer map_db  --z 4 --nx 16 --ny 12 --tile 256 \
       --out screenshots/mapoverview/zero_dam_tiles_z4.png

# 楼层图（三层各一次）
python ai-training/src/stitch_map_tiles.py --layer daba_1f --z 4 --nx 8 --ny 8 --tile 512
```

流程要点：

1. 从官网地图页的图层配置里读出**图层名 + 网格数**（`map_db` 16×12，`daba_*f` 8×8）；
2. 按 `{z}_{x}_{y}.jpg` 批量下载（**必须带 Referer**）；
3. 缺瓦片（404）**填黑**，拼完打印"非黑占比"做体检；
4. 室外图 192 块里缺 4 块，都落在**地图边界外**，正好是空白——所以图上左下角那几块黑方块不是 bug；
5. 楼层图的楼层配置（`bj=64`、`pixelToLatLngRatio=-0.85`）从 `daba_floor.js` 里读，**不要猜**。

### 首轮室内验证结果（2026-10-22）

拿机密局"无定位"段的帧（室内）对三层图分别匹配：

| 结论 | 数据 |
|---|---|
| ✅ 室内帧对**楼层图**确实能匹配 | 分数 **0.51-0.74**（同帧对室外图多为"无定位"） |
| ❌ **分不清楼层** | 三个楼层得分几乎相同：00:37:14 三层都 **0.736**；00:34:00 分别 0.530 / 0.566 / 0.607 |
| ❌ 部分室内帧仍无匹配 | 00:34:05-00:34:16——可能小地图显示了楼层图未覆盖的区域（走廊），或那段其实是别的界面 |

## 失效条件（何时需要重标）

| 变了什么 | 会怎样 | 要做什么 |
|---|---|---|
| 官网换瓦片路径 / 图层名 / 网格 | 下载 404、拼图错位 | 重新探测网格（先试 16×12×256，再试 8×8×512），用"非黑占比"判对错 |
| 赛季改版改楼层结构 | 内容过时 | 重新拼图 + 重跑室内验证 |
| 换地图 | 每张地图有各自的图层集合 | 另挖（本表只对零号大坝） |
| `z` 变了 | 像素/单位变 | 改 `2^z` 并重拼瓦片 |

## 待办（为什么状态是方案稿）

- [ ] **楼层判别**：验证哪种信号能区分 B1 / 1F / 2F —— ① 小地图上的楼层字样（可 OCR）；② 各楼层唯一地形特征（门/楼梯口）；③ 时序先验（进门后楼层连续变化）
- [ ] **多图层定位器**：`MinimapLocalizer` 扩展为多图层匹配（先判层再定位，或全层扫描取最高分 + 分差 margin 判据）
- [ ] **楼层坐标系标定**：`bj = 64` 下的 `map_px ↔ 世界坐标` 换算，用已知点位校验
- [ ] **室内/室外切换点**：门 / 楼梯位置标定，作为图层切换事件
