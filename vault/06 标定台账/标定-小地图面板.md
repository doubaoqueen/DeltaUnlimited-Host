# 标定：小地图面板（圆心 / 半径）

> [!info] 一句话
> 局内小地图是**左上角的圆形罗盘**：圆心 ≈ **(165, 185)**、半径 ≈ **129px**（1920×1080 帧坐标）。
> 定位器只在这块圆里找地形；圆裁错了（或游戏里 UI 缩放改了）整个定位就废。

## 数值

| 参数 | 值 | 含义 |
|---|---|---|
| 面板形状 | **圆形** | 不是矩形——圆形外还有一圈方形 HUD 底衬，别被它骗了 |
| 圆心 | **(165, 185)** | 1920×1080 帧坐标（用户口述四点定圆换算） |
| 半径（看到的外沿） | **≈129 px** | 四点定圆的实际半径，文档记为 120-129 区间 |
| 半径（实际裁切用） | **120 px** | 比 129 小 9px，**避开边框/描边**（边框是 HUD 装饰，不属于地图内容） |
| 裁切结果 | 240×240 | `2 × 120`，送进匹配器前转灰度 |
| 掩膜 | 圆形 | 模板构造时圆外像素填模板均值（`CCOEFF` 里贡献≈0） |

> [!tip] 为什么"看到的半径"和"裁的半径"不一样
> 129 是眼睛能看到的圆盘外沿（含一圈亮边）；裁切往里收一点，可以避免把 HUD 的描边/高光当成地形去匹配。少裁 9px 的代价远小于把边框喂给匹配器。

## 怎么标定的

1. **用户口述四个边界点**（左 / 右 / 上 / 下），换算成圆心与半径：

   ```
   圆心 = ((左 + 右) / 2, (上 + 下) / 2)
   半径 = ((右 - 左) + (下 - 上)) / 4
   ```

2. 写进代码常量（Python 探索版 `MINI_CX/MINI_CY/MINI_R = 165/185/120`；C# 版 `LocalizerConfig.MiniCenterX/MiniCenterY/MiniRadius = 165/185/120`）；
3. 验收：裁出来的 240×240 里**必须是小地图内容**（可用 `localize --frame` 存对照图，左边是小地图、右边是底图上匹配到的区域）；
4. 定位回归：用户肉眼确认的 6 帧（`m1a/m1b/m1c/m1d/m2a/m2b`）全部命中 → 面板参数算配套了。

配套的掩膜做法（两种实现等价）：

| 实现 | 做法 |
|---|---|
| Python 探索版 | 真正的圆形 mask 做掩膜 NCC（只在圆内算均值/方差/互相关） |
| C# 生产版 | 模板缩到目标尺度后，把**圆外**像素填成模板均值 → `CCOEFF_NORMED` 里这些像素贡献≈0 |

## 失效条件（何时需要重标）

| 变了什么 | 会怎样 | 要做什么 |
|---|---|---|
| 游戏内 **UI/HUD 缩放** | 面板变大/变小、圆心偏移，裁出来一半是画面 | **重标圆心+半径**（最常发生） |
| 分辨率 / 画面比例 | 帧会先归一化到 1920×1080，但归一化后面板位置/大小可能变 | 重标（并复核 `FrameTools.Normalize` 后的位置） |
| 换了地图 / 模式 | 不同地图的 HUD 布局可能不同 | ❓只在零号大坝标过，其他地图未验证 |
| 游戏改版换了小地图样式 | 圆形→方形、加罗盘刻度、加边框 | 重标（且要改"圆形掩膜"这个前提） |
| 只在 21:9 等超宽屏窗口化运行 | 归一化后左右留黑/拉伸 | 重标 |

**怎么判断该重标了**：

1. `localize` 的候选分数整体变低、位置乱跳（而且不是"无小地图"的帧）；
2. 用 `localize --frame <帧>` 看输出的对照图——左边那块是不是小地图？被裁掉了多少？
3. `HudStateGate` 报"该帧为 UI 界面"但肉眼看是正常 HUD（说明识别也被裁歪的区域影响了）。
