# 坑：把"送模型前的图坐标"当"原图坐标"用，框系统性偏 1/3

> [!bug] 症状
> VLM 在缩小后的图上框出了目标（送图宽 1280），我们把框直接当"原图坐标"画到 1920 宽的原图上。
> 预览图上：框**整体偏右偏下**，越靠近右边越离谱，最右侧的框直接飞出画面。
> 第一反应是"模型框不准"——其实是**坐标没还原**。

## 根因

发给模型的图是**缩过的**（宽 1280，省显存）；模型返回的 bbox 是**送图坐标**。

代码里少了（或漏了某一层）"送图坐标 × 原图/送图"的还原，于是把 1280 坐标系里的数字当 1920 坐标系用：

```
1920 / 1280 = 1.5   →   同一个像素数字，真实位置要再乘 1.5
```

所以模型说的 `x=800`，真实位置是 `x=1200`；**报出来的坐标只有真实位置的 2/3，比真实位置少 1/3**——文档里那句"系统性偏 1/3"就是这个意思（越靠右/下，绝对偏差越大）。

> [!warning] 多层缩放最容易漏
> 两步缩放那条链路要换 **3 次**坐标（代码注释里叫"三层坐标换算"）：① 整帧的送图坐标 → 原图（`map_bbox`）；② 原图 → 裁图矩形（`crop_rect`，外扩 25%）；③ 裁图的送图坐标 → 原图（`map_box_to_orig`）。**每多一层缩放，就多一个坐标空间**，每层都要显式还原一次。

## 修复方式

**① 分别按 x / y 的比例换算**（`map_bbox`）：

```python
def map_bbox(box, sent_w, sent_h, orig_w, orig_h):
    """送图坐标 → 原图坐标。scale 按宽高分别算，避免舍入累积。"""
    sx, sy = orig_w / sent_w, orig_h / sent_h
    x1, y1, x2, y2 = box
    return [round(x1 * sx), round(y1 * sy), round(x2 * sx), round(y2 * sy)]
```

不假设等比、不用单一 scale、不先算中心再算框（那样会累积舍入误差）。

**② 裁图坐标还原**（`map_box_to_orig`）：细框（裁图放大后的送图坐标）→ 原图坐标，**先乘裁图缩放、再加裁图原点偏移**。

**③ 离线自检钉住**（`--selftest`）：

| 用例 | 期望 |
|---|---|
| 1080p 整帧送图 1280×720，框 `(100,50,200,100)` | 原图 `(150,75,300,150)` |
| 裁图 → 送图 → 原图**往返一致性** | 必须回到原值（`map_box_to_orig` 的逆运算结果相等） |
| 退化框过滤 | `x1≥x2` 或 `y1≥y2` 的框直接丢掉（模型偶尔输出空框/反框） |

**④ 写成红线**：方案文档 §4 明写「坐标系必须显式处理……**不写这一步会系统性偏 1/3**」，并要求"换算函数单测钉住 + 预览图上画'图上框 vs 还原框'双框自检"。

## 教训（以后怎么避免）

> [!important] 任何"缩放过"的图像，坐标必须显式还原
> 而且要在**每一层**都还原——不是"记得还原一次"，而是"每进出一层就换一次坐标系"。

1. **x/y 分开按比例算**，别用一个 scale 蒙。宽高比一变就会错——这里三种比例都不同：整帧 16:9、被面积约束压过的送图比例、裁图放大后的又是一个比例。
2. **往返一致性自检是最便宜的坐标测试**：A → B → A 必须回到 A。再配"退化框过滤"兜住模型乱输出的情况。
3. **"模型不准"是最容易下的错结论。** 先检查"我拿它的输出去做了什么换算"，再怀疑模型。
4. 同一个函数的用途写在 docstring 里（"送图坐标 → 原图坐标"），比事后考古便宜。
