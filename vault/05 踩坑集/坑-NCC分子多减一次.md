# 坑：匹配分数全是负数（-2.0），因为均值被减了两次

> [!bug] 症状
> 小地图定位器（圆形掩膜 NCC）写完，拿真机帧跑：所有候选位置的分数都是**负数**，真实位置也只有 **-2.0** 左右。
> 把最低分阈值 `MinScore` 从 0.55 一路往下调都没用——因为**所有分数都在 -2 附近**，调阈值只能决定"要不要全收"。
> 代码里的公式看着完全正确，这也是最气人的地方。

## 根因

掩膜 NCC 的分子要的是**"去均值后的互相关"**：

```
num = Σ [(T - meanT) · (I - meanI)]     （只比较掩膜内的像素）
```

实现里做了两件"各自都对"的事，叠在一起就错了：

1. 模板侧先减了均值：`T0 = (tpl - mT) * mask`（对照公式 = 对）；
2. 计算窗口侧均值项时，用 `corr(img, T0)` 展开成形如 `corr - mT·s1` 的式子——而这一项里 **`mT` 的扣除又做了一次**。

**均值被扣两次 → 符号翻转 → "最像的位置"拿到的是负分。** 分数范围本该是 [-1, 1]，真匹配应该接近 +1。

> [!warning] 为什么看代码看不出来
> 公式每一行都对，错的是"两个都对的东西叠在一起"。这类错误只能靠**跑数据**发现，靠读代码发现不了。

## 修复方式

**① 去掉重复的减均值**，让分子只减一次（`ai-training/src/minimap_localizer.py` 的 `_ncc_scores`）。

**② 更重要的：补一个合成自检**——"自己出题自己答"：

- 从官方底图里**挖一块**（300×300，缩到 150×150 当"小地图"）；
- 再用同一个匹配器**把它找回去**；
- 判定标准：位置误差 < 20px **且** 分数 > 0.9（实测 0.997 才算通过）。

这个自检一次能同时验证三件事：符号对不对、坐标系有没有翻、尺度换算对不对。

C# 版有等价的自检：`LocalizerTests.Synthetic_FindsEmbeddedPatch` —— 1200×900 噪声底图里嵌 300×300 图案，断言中心误差 ≤25px、尺度 = 300。

## 教训（以后怎么避免）

> [!important] 写匹配器必须配合成自检
> "挖一块再匹配回去，位置对且分数 ≈1.0"——过了这条才算实现正确。读代码永远读不出符号错。

1. **"分数系统性为负"是第一信号。** NCC 的值域是 [-1, 1]，真匹配接近 +1；整片负分几乎一定是符号/均值处理错了。
2. **阈值调不动的时候，要看分数的分布，不要继续调阈值。** 调阈值只能改"收不收"，改不了"算得对不对"。
3. **自检要写成测试**（能反复跑），不要只在命令行里试一次就完事。
