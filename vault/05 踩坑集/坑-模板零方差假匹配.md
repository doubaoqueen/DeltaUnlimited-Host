# 坑：合成测试图"太干净"，匹配器在任意位置都给 1.0

> [!bug] 症状
> 给"跟着导航标记走"写单元测试，用合成帧当游戏画面：一张纯底色图，中间画个白色方块当标记。
> 断言"能找到标记"——通过。断言"没有标记时找不到"——**失败**：匹配器在画面任意位置都返回 **1.0 满分**。
> 程序于是"到处都看到标记"，伺服会对着空气走。

## 根因

归一化互相关（`CCoeffNormed`，OpenCV 里的模板匹配方式）的分母是**窗口内像素的标准差**。

- 合成帧是纯色背景 → 大量窗口的方差 = 0；
- 模板本身是一个纯白方块 → 模板内部方差也是 0；
- 分母为 0（或极小）→ 分数被放大到 1.0，**位置信息彻底丢失**。

所以 1.0 不代表"完美匹配"，只代表"这个窗口也是纯色，数学上无从比较"。

> [!warning] 这不是算法 bug，是**测试素材不真实**
> 真实游戏画面永远有纹理（噪点、光照、材质、暗角）；真实模板（游戏图标）永远有内部花纹。合成素材"干净好读"恰恰把这些真实世界的性质去掉了。

## 修复方式

把合成素材造成"脏的"（`tests/DU.Tests/FollowMarkerChainTests.cs`）：

| 素材 | 旧做法 | 新做法 |
|---|---|---|
| 测试帧 | 纯底色 | **带纹理的假帧**：底色 + 600 个随机彩色小圆点（`TexturedFrame`）→ 任何窗口都有方差 |
| 模板 | 纯白方块 | **带特征的标记**：20×20 白块 + 左上角 6×6 黑角块（`DrawMarker`）→ 模板内部有结构 |

两处的代码注释都写明了"为什么不能纯色"，给下一个人看：

```csharp
/// <summary>带纹理的假帧（彩色噪点）——真实游戏帧永远有纹理；
/// 纯色帧会让 CCoeffNormed 在零方差窗口上产生假匹配（测试合成帧必须造得真）。</summary>
```

小地图定位器的合成自检同理：`LocalizerTests.MakeSynthetic()` 的底图是 1200×900 的噪声图 + 4000 个随机色块，再嵌一块可辨认图案当"小地图内容"。

## 教训（以后怎么避免）

> [!important] 匹配算法的输入必须有方差
> 写合成测试素材时，"像真的一样脏"比"干净好读"重要得多。

1. **一个"永远通过"的断言比没有断言更危险。** "找不到标记却 1.0 命中"如果不写这条反向断言，bug 会一直藏在测试全绿里。
2. **算法的边界条件要主动造出来**：除零、零方差、纯色、全黑、单像素……这些在真实素材里很难碰到，在合成素材里必须碰到。
3. 遇到"分数动不动就 1.0 或动不动就 0"，先看**分母**（方差/能量项），而不是看分子。
