# 坑：双击 GUI 七连"打不开"——构造期事件链摸到还没创建的控件

> [!bug] 症状
> v0.6.3 双击后**无声死亡**：没有窗口、没有弹窗、没有报错。事件日志（.NET Runtime 条目）实锤：`NullReferenceException at MainForm.UpdateBusyUi()，line 418`，连续 7 次。

## 根因

**构造期设置 `SelectedIndex` 会同步触发事件链，而事件链引用的兄弟控件还没创建。**

重排布局时把命令侧栏的构建放在了顶栏之前：`BuildCommandSidebar()` 末尾的 `PopulateCommands()` 设置 `_cmdBox.SelectedIndex = 0` → 同步触发 `OnCommandSelected` → `UpdateBusyUi()` 碰 `_startButton`（顶栏块在后面才建）→ **NRE**。`ApplyTheme()` 同理摸到 `_topBar/_pausePanel/_statusStrip`。

**为什么无声**：发布版是 WinExe（GUI 子系统，[[坑-双击exe黑窗残留]]），没有控制台——启动崩溃不打印任何东西，进程静默退出。

## 修复方式

1. **构建顺序**：顶栏/状态栏/暂停面板 → 日志窗/分栏 → 命令侧栏**最后**构建（它的事件链依赖前面所有控件）；
2. **启动兜底**：`GuiApp` 里 `Application.Run(new MainForm(...))` 包 try/catch → `Logger.Error` 落日志 + `MessageBox` 弹窗——**WinExe 启动失败必须可见，无声死亡不允许再有**；
3. 验证：发布版真机启动 + 事件日志无新崩溃 + 262 测试全绿。

## 教训（以后怎么避免）

1. **构造期给 `SelectedIndex`/`Checked` 赋值 = 同步跑一遍完整事件链**——链上每个引用都必须在赋值点之前存在。布局代码里"先建谁后建谁"是功能约束，不是审美；
2. **GUI 程序的启动路径必须有兜底**（弹窗 + 落日志），否则任何构造期 bug 都表现为"双击没反应"，排查成本翻十倍；
3. 排查"双击没反应"第一步：事件查看器 → Application 日志 → `.NET Runtime` 条目，堆栈直接指到行号。
