# 坑：让所有尺度"投票"，5 票的错误答案压过了 2 票的正确答案

> [!bug] 症状
> 小地图上显示的地形比例是未知的，所以在 8 个尺度（150 / 180 / 210 / 245 / 285 / 330 / 380 / 440 px）上都匹配一遍。
> 为了"稳"，让所有尺度**投票选位置**——取票数最多的那个点。
> 结果：好几帧都定到同一个错误位置（一片纯色/重复地形），而用户肉眼确认过的正确位置上只有 2 票。

## 根因

"投票"隐含了一个假设：**每个投票者都可信**。

实际情况是：

- 小尺度模板（150px，内容很少）在纯色区/重复纹理区会**同时命中一大片区域**；
- 多个尺度、多个峰**扎堆投给同一个错误位置**（于是凑出 5 票）；
- 正确位置只有少数尺度能命中（2 票）。

所以票数在这里度量的不是"多可信"，而是**"有多少个瞎猜的猜到了同一处"**——重复地形越平，错误答案越容易凑票。

## 修复方式

**改成按分数排序选优**：每个尺度取自己的最高分，再在所有"各尺度最高分"里取最大者。

```python
hits.sort(key=lambda h: -h[0])   # h = (score, scale_px, cx, cy)
```

```csharp
hits.Sort((a, b) => b.Score.CompareTo(a.Score));
var top = hits.Take(Math.Max(1, _cfg.TopK)).ToArray();
```

改完之后，用户之前确认过的三帧全部命中。

> [!warning] 但最高分也不是置信度
> 后来又被现实修正了一次：八组样本里有一组 **0.904 的高分却是错的**（重复地形误报）。所以"按分数选优"只是比"按票数"诚实，仍然必须叠加**跨帧连续性 / 尺度先验**约束——见 [[坑-背包界面不是小地图]] 里的轨迹过滤。

## 教训（以后怎么避免）

> [!important] 投票前先确认每个投票者可信
> 不可信的投票者越多，结论越糟——它们会系统性地一起犯错（因为诱因相同：纯色、重复纹理）。

1. **多尺度/多模型融合时，"取最高分"通常是更诚实的基线。** 它保留了"这个答案有多好"的信息；票数把这个信息丢掉了。
2. **"稳"不等于"投票"。** 真正让它稳的是**约束**（尺度先验、速度门、状态门），不是把不可靠的判断加起来。
3. 看到"高置信度却是错的"，要接受一个事实：**单帧分数不能当置信度**，得靠上下文兜底。
