# 坑：给链路加了"未知 op 就报错"，结果所有合法 op 全被判非法

> [!bug] 症状
> 前一天给链路加载器加了一道"防手滑"校验：op 拼错（比如把 `switch_screen` 写成 `swich_screen`）应该在**启动时**就报错，别等到跑起来才炸。
> 第二天跑 `dotnet run -- chain enter_match.json --auto`，链路**一步都跑不动**，启动就甩出 **17+ 条**"未知 op"，然后拒绝执行。
> 而那 17 条里的 op 全是**合法**的。

## 根因

C# 的 `switch` 一旦加了 `default:` 分支，就"兜住一切没写 case 的值"。

原来的校验只给"**有必填字段要检查**"的 op 写了 case（`click_element` / `if_screen` / `switch_screen` / `key` …）。像 `jump` / `wait` / `pause` / `detect` / `mark_unknown` 这类**没有必填字段**的 op，从来没有出现在 case 里——以前它们落到 `default` 也无所谓（`default` 是空的，等于"不检查，放行"）。

改完之后 `default` 变成了"报错"。于是这五个 op 的每一次出现都被判成"未知 op"。真实链路里它们出现得非常多（跳转、等待、人工确认点、未知界面留证），所以一加载就是十几条错误。

> [!warning] 单测为什么没抓到
> 当时没有任何测试**真的跑一遍** `ValidateChain`——它是 `private`，而且测试只覆盖了旁边那个纯函数（死步骤可达性分析）。"纯函数有测试"给人一种"这块有测试"的错觉。

**谁抓到的**：助手拿 CLI 做冒烟测试（真的跑一次链路），第一次就撞上。这恰好证明：**加载期校验这种代码，必须用真实数据文件跑一遍。**

## 修复方式

1. **把"合法 op"写全**：把那五个无必填字段的 op 显式列进 `switch`，并在注释里钉住原因——

   ```csharp
   case "jump":
   case "wait":
   case "pause":
   case "detect":
   case "mark_unknown":
       break; // 无必填字段——必须显式列出，否则会被 default 误判为未知 op
   ```

2. **补测试**：新增 `tests/DU.Tests/ChainValidationTests.cs`，其中一条是**用真实链路文件**跑校验（`enter_match.json`：无死步骤、所有 `jump_to` / `branches` / `default` 目标都存在）。
3. 顺手修了同一批评审里的 P1-1：匹配超时后不再"假成功"（`after_match_check.default` 由 `done` 改成 `match_fail` 重等），并加了"死步骤告警"（只告警、不阻断，防孤立分支复发）。

## 教训（以后怎么避免）

> [!important] 校验器扩展 = 把"合法集合"写全
> 凡是把 `default` 从"放行"改成"拒绝"的改动，都要能回答一句话：**合法值一共有哪些？** 答不全就不要动 `default`。

1. **"没有必填字段"不等于"不需要列出来"。** 在"穷举式校验"里，沉默不等于同意——每一类合法值都要有一行。
2. **单测覆盖纯函数 ≠ 覆盖加载路径。** 至少留一条"拿真实数据文件跑一遍主流程"的测试。这条测试往往比十个小单测更能挡住回归。
3. **改完校验器，手动冒烟一次真实链路。** 成本 30 秒，收益是避免第二天整条链路跑不动。
4. 加载期报错比运行时崩溃好，但代价是"错得很早、很响"——所以更要有冒烟兜底。
