# 坑：VLM 把队友图标框成"撤离点"，理由里还自己写着"内含数字1"

> [!bug] 症状
> 让本地 VLM（Qwen3-VL-8B）在官方地图截图上框"撤离点"图标。它框出来一堆不该框的东西：
> 带数字 **1/2/3** 的图标（那是自己+队友的位置标记）、**红色 X**、**橙色**图标……
> 最离谱的是它的理由栏：明写着「**内含数字 1**」「**此处为橙色**」，结论依然是「**符合撤离点定义**」——**自相矛盾，还在附和我。**

量化：P0 跑 40 帧，其中 36 帧出框、共 **73 框**，而 `extract`（"撤离点"）这一类就有 **27 个**框（远超每帧真实撤离点数）；v2 两步缩放后框是紧了（中位 24×23px），但 99 个框里仍有 **72 个**混入了这些错目标。

## 根因

**① 提示词没排除队友图标（我方盲区，第一次的错）**

带 1/2/3 的图标是"玩家自己 + 队友"，形状与撤离点相似。第一版提示词只写了"找撤离点"，没写"不要找什么"。用户后来补充：带数字 1/2/3 的是自己+队友。

**② 8B-AWQ 这类小模型"顺着你说"（无解的那一半）**

它把"你这是撤离点吗？"当成一个**需要被确认的命题**，于是倾向于回答"是"——哪怕自己写下的依据正好否证结论。**排除条款压不住**：把"排除带数字图标"写进提示词后，它仍然框，理由里仍然写"内含数字1"，然后说"符合撤离点定义"。

**③ 结构性精度上限**

Qwen3-VL 对 1280×720 只有约 **46×26** 的感知网格。30px 的图标 ≈ 1 个网格；两步缩放后在送图里约 81px ≈ 3 个网格，输出精度 ±1-2 个网格 ≈ **原图 ±10-20px**——框在图标附近，但打不中。

## 修复方式（其实是"执行退路"）

按 **P0 阶段就事先写下的退路**执行，不重新吵架：

| 线 | 处置 |
|---|---|
| **UI 模板线** | 退回**手动五步流程**：`capture` → `crop` → `tplprobe` → 写 `elements.json` / `screens.json` → `annotate` 复验（工具全都现成，模板只有几十张，一次性成本） |
| **VLM 线** | 收缩为"粗定位（大区域找得准）+ 世界物体粗框"的**实验能力**，暂停 `aiground` 图形审批 GUI（P2）投入 |
| **换更大模型** | 不可行：32B AWQ 需 ~18GB 显存（本机 5070 只有 12GB）；云端 API 违反"数据不出机器"红线 |

**结论一句话**：8B-AWQ 对**细粒度游戏图标检测**能力不合格。

## 教训（以后怎么避免）

> [!warning] 小模型会"顺着你说"
> 给它一个"请找出 X"的框架，它倾向于产出 X——哪怕理由自相矛盾。判断类任务不能只看它说"是/否"，要看它**能不能给出可验证的依据**（这里依据恰好否证了结论）。

1. **先写退路，再开跑。** P0 阶段就写清"若放大后仍分不清队友/撤离图标 → UI 模板线退回人工"。有了这句话，判失败只是执行预案，不用重新决策。
2. **提示词的排除条款只对"模型本来就能分辨"的东西有效。** 分辨不了的时候要**换方法**（模板匹配 / 人工），而不是写更长的提示词。
3. **conf 不能当置信度。** 这批候选的 conf 全在 **0.95-0.98**，错的框和对的框一样高——和初筛那边的观察完全一致（见 [[AI-VLM初筛]]）。
4. **有些活本来就不该给 VLM。** 图标类目标用自家 `TemplateMatcher` / `tplprobe` 预标 + 人工修正，比通用大模型实用得多。
