# 坑：小地图是圆的，我按矩形面板裁，怎么匹配都是错的

> [!bug] 症状
> 第一版小地图定位：按"左上角矩形面板"裁出小地图，还做了边缘检测验证——从截图上看**确实有个方框**，自以为很稳。
> 结果：所有帧的匹配结果全错，位置在底图上到处乱跳，跟玩家实际位置毫无关系。

## 根因

游戏的小地图是**圆形罗盘**，不是矩形面板。

矩形裁出来的四个角，内容是**游戏画面本身**（墙、地面、远处建筑、别的 HUD）——这些东西在官方大地图上根本不存在。等于把一堆"虚构像素"喂给匹配器，真正的正确位置自然被压下去。

那为什么边缘检测会"看起来很像矩形"？因为圆形面板外面还有一圈**方形 HUD 底衬/描边**。视觉上有方框，不代表方框里全是地图。

> [!warning] 领域常识不是你的常识
> "小地图是圆的"对玩这个游戏的人是废话，对刚接手代码的人（尤其是我）是一个必须问出口的问题。

## 修复方式

用户给四个点定圆，换算成：

| 参数 | 值（1920×1080 帧坐标） |
|---|---|
| 圆心 | ≈ **(165, 185)** |
| 半径 | ≈ **129** px（实际裁切用 120，避开边框） |

定位器改成**圆形裁切 + 圆形掩膜**：

- 裁切：以 (165,185) 为中心裁 240×240（`MiniRadius = 120`）；
- 模板构造：把圆外的像素**填成模板均值**——在 `CCOEFF_NORMED` 里这些像素的贡献≈0，等价于"圆外不参与打分"，把 HUD 边角干扰压掉；
- Python 探索版用**真正的圆形 mask** 做掩膜 NCC（只在圆内算均值、方差、互相关）。

改完之后，用户肉眼确认 3/3 样本命中（后续扩展到 6 对 0 错的回归集）。

## 教训（以后怎么避免）

> [!tip] 把"看"的判断交给用户最省事
> 我自己推断"矩形 + 边缘检测"花了不少时间，还推错了；用户看一眼、给四个点，一次就定。

1. **形状/布局这类"看一眼就知道"的事实，问一句比自己推十句便宜。** 尤其是游戏 UI，玩家的常识就是标准答案。
2. **掩膜不只是"少算点像素"**，它同时是"排除掉不存在的内容"的手段——这次错的正是后者。
3. **"看起来像"是最危险的证据。** 边缘检测"看起来很像"恰恰来自面板外面的方形底衬，而不是地图内容。
