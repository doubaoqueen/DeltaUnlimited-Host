# 写作规范（给写笔记的人看）

> 这份笔记是**给（我/任何 AI）写这个库用的规范**，用户可以不看。目的是保证 60+ 篇笔记风格一致、链接不断、可维护。

## 1. 笔记文件命名

- 文件名 = 笔记标题，**全库唯一**（Obsidian 的 `[[链接]]` 按文件名解析，重名会歧义）。
- 用中文，不加序号前缀（文件夹负责排序）。
- 命名模式：
  - 模块：`模块-<名字>`（如 `模块-chain引擎`）
  - 决策：`决策-<主题>`（如 `决策-双引擎架构`）
  - 踩坑：`坑-<一句话症状>`（如 `坑-小地图圆形vs矩形`）
  - 标定：`标定-<对象>`（如 `标定-地图坐标换算`）
  - 知识点：`知识点-<概念>`（如 `知识点-模板匹配与NCC`）
  - AI：`AI-<主题>`
  - 工具/数据：`工具-<名字>` / `数据-<主题>`

## 2. 每篇笔记的固定结构

```markdown
---
title: 标题
tags: [分类标签1, 分类标签2]
status: 现行 | 方案稿 | 未来待办 | 历史
created: 2026-XX-XX
related: ["[[关联笔记1]]", "[[关联笔记2]]"]
---

# 标题

> [!info] 一句话
> 用一两句话讲清楚这篇笔记解决什么问题（用户忘了细节时先看这句）。

## 正文小节……

## 出处

- 原始文档：`docs/xxx.md` §N
- 代码：`DeltaUnlimited/.../Xxx.cs`
- 数据：`data/xxx.json`
- Git：提交 `abcdefg`（一句话）
```

**硬性要求**：
1. 读者是**非程序员/初学者**：术语第一次出现必须用一句话解释（可链到 `知识点-*` 笔记）。
2. **不编造事实**。不确定的地方写 `❓待确认`，不要猜。
3. 每篇必须有 `## 出处`，列出你依据的文件路径/章节（这样以后能回查）。
4. 结构里提到"为什么这么决策"时，写成"当时的取舍"，不要写成教条。
5. 中文标点；代码块用 ``` 围栏；表格优先于长段落。

## 3. 可用的 Obsidian 特性（鼓励使用）

| 特性 | 写法 | 用途 |
|---|---|---|
| 双向链接 | `[[笔记名]]` 或 `[[笔记名\|显示文字]]` | 所有关联都写链接，不要只写文字 |
| 标签 | `#红线` `#踩坑` `#标定` 行内 | 快速筛选 |
| 属性 | YAML front-matter | 状态/日期/关联 |
| 提示框 | `> [!warning] 标题` / `> [!tip]` / `> [!bug]` | 强调红线、技巧、坑 |
| 折叠 | `<details><summary>展开</summary>…</details>` | 长推导/大段日志 |
| 任务 | `- [ ] 待办` / `- [x] 已完成` | 待办清单 |
| 嵌入 | `![[图片名.png]]` 或 `![[笔记名#小节]]` | 嵌图/嵌片段 |
| 图 | `![[assets/xxx.png]]` | 图片都放 `vault/assets/` |

## 5. 语气示例

✅ 好：
> 为什么先做这个？因为进场链路每局都要跑一次，它坏了后面全废——先把必经之路修好，比先做花哨的功能划算。

❌ 差：
> 本模块实现了基于有限状态机的可配置化流程编排引擎。（用户看不懂，且没讲为什么）
