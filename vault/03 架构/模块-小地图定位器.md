# 模块-小地图定位器

> [!info] 一句话
> 把左上角那块圆形小地图抠出来，当成"模板"去官方大地图上找最像的位置——**因为小地图就是大地图的一小块**；找到就相当于知道了玩家站在地图的哪里（不读内存、不注入进程，纯图像分析）。

## 1. 它负责什么、为什么需要它

跑刀要回答"我在哪、往哪走"。游戏里没有坐标数字可读，但有**小地图**：它是官方地图的一块实景缩略图。于是最省事的定位方式是地形匹配：

```
小地图（圆形面板，约 240×240 像素）
  → 灰度 → 多尺度模板匹配（CCoeffNormed）→ 在 4096×3072 官方底图上找最相似的位置
  → 输出：底图坐标 + 命中尺度 + 分数
```

红线：**纯离线图像分析**（读图、匹配、输出坐标），不读内存、不注入进程、不碰游戏运行时（`MinimapLocalizer.cs:52`）。

## 2. 配置（`LocalizerConfig` 默认值）

| 参数 | 默认 | 说明 |
|---|---|---|
| `MapImage` | `screenshots/mapoverview/zero_dam_tiles_z4.png` | 官方底图 4096×3072（本机素材，不入库） |
| `Downscale` | 2 | 底图缩小倍数（4096→2048），兼顾速度与精度 |
| `ScalesPx` | 150/180/210/245/285/330/380/440 | 小地图内容对应到底图上的正方形边长（缩放未知 → 多尺度） |
| `MinScore` | 0.50 | 最低有效分（2026-10-21 校准：用户确认的最弱命中样本 0.515@380） |
| `MiniCenterX/Y` | 165 / 185 | 小地图圆形面板圆心（设计分辨率坐标，用户口述四点定圆） |
| `MiniRadius` | 120 | 半径 |
| `TopK` | 3 | 返回候选数 |

## 3. 算法四步

`Localize(frame, prior?)`（`MinimapLocalizer.cs:85-141`）：

1. **裁圆形面板**：以 (165,185) 为心、r=120 裁正方形（越界自动夹取），转灰度。
2. **构造模板**：每个尺度把面板缩放到 `scale / Downscale`，然后**圆外像素填模板均值**——模拟圆形掩膜，让 HUD 边角在 CCOEFF 里贡献接近 0（`BuildTemplate`，`MinimapLocalizer.cs:165-175`）。
3. **匹配**：`Cv2.MatchTemplate(src, tpl, CCoeffNormed)`，取最大值；`src` 是缩小后的灰度底图（有先验时只取先验附近的 ROI）。分数 < `MinScore` 或 NaN 跳过。
4. **汇总**：候选中心 = `(ROI偏移 + 最大值位置) × Downscale + scale/2`；按分数降序取 TopK。

两个重要工程细节：

- **永不抛异常**：整体 `try/catch`，任何失败返回 `LocalizeResult.Miss`（上层按"没定位"处理，不打断流程）。
- **先验局部搜索**：`LocalizePrior(CenterX, CenterY, ScalePx?, RadiusPx=400)` 给出后，只在附近窗口找，且**只在最接近的 3 个尺度**里找（`SelectScales`）——从"几百 ms/帧"降到"几十 ms/帧"，同时大幅减少误报。

## 4. 轨迹过滤：`LocalizerTrack`

单帧结果**绝对不能直接信**。真实踩过的两个坑（`docs/小地图定位P0验证.md` §7）：

- 小地图被 UI 面板遮挡时，NCC 仍给 0.6+ 分但位置**全错**（实测 2 秒瞬移 1394px）；
- 首帧低分（0.520）被当锚点后，正确位置反而全被判"超速"。

所以加了三条物理/统计规则（`LocalizerTrack.cs:14-124`）：

| 规则 | 参数 | 说明 |
|---|---|---|
| **首锚需双帧确认** | `InitTolerancePx = 120` | 首帧候选先挂起，第二帧候选与之一致才锁定位置；不一致就用新候选重新等 |
| **速度门** | `MaxSpeedPxPerSec = 30`（冲刺约 18px/s，留余量）、`MaxGapMs = 30000` | 只接受"从上一次确认位置出发、速度 ≤ 上限"的候选；长空档按 30s 封顶算允许位移，防放大瞬移 |
| **重锚定** | `ReanchorAfter = 3`、`ReanchorTolerancePx = 100` | 连续 3 帧被拒但候选彼此一致 → 认定锚点漂了，重新锚定并报出原因 |

返回 `TrackResult(Accepted, Held, Position, Note)`：`Accepted=false && Held=true` 表示"这帧被拒，沿用上次位置"。

## 5. 前置门：`HudStateGate`（背包/地图/结算没有小地图）

按 Tab 打开背包、开地图、结算界面时，左上角**不是小地图**（是背包 UI/面板），定位器会把 UI 纹理当小地图匹配 → 高分但完全错误（[[坑-背包界面不是小地图]]）。

`HudStateGate.IsNormalHud(frame, screens, root, out uiScreen)`（`HudStateGate.cs:14-43`）：

- 用 `ScreenDetector.Detect(frame, screens, group: "match")` 只扫**局内**界面表；
- 命中 `match_backpack / match_map / match_settlement_success / match_settlement_fail` → 判定"无小地图"，跳过定位；
- 识别不到界面时**fail-open**（按正常 HUD 处理，交给轨迹过滤兜底）。

`localize` / `localizetrack` 都已接入（`LocalizeCommand.cs:55-61`、`LocalizeTrackCommand.cs:81-89`）。

## 6. 两个 CLI 命令

### 6.1 `localize`：单帧诊断

```
dotnet run -- localize <截图> [--map 底图] [--scales 150,180,...] [--minscore 0.5] [--topk 3] [--prior x,y[,scale[,r]]]
```

输出：面板参数、全部候选（分数/尺度/中心）、以及在底图上画好候选框的预览图 `screenshots/captured/localize_<图名>.png`。多候选分数接近时会打印"勿单帧采信"的警告。

### 6.2 `localizetrack`：整段轨迹

```
dotnet run -- localizetrack "2026-10-12 00:28:20" "2026-10-12 00:30:30" [--maxspeed 30] [--map 底图] [--scales ...]
```

- 输入是 `ai-training/datasets/record/record_manifest.csv` 里该时间段的帧（按 `created` 时间戳过滤）；
- 每帧：HUD 状态门 → 带先验定位（先验半径随帧间隔放大：`300 + gap秒×40`，夹在 300-1600px）→ `LocalizerTrack.Accept`；
- 输出 CSV `logs/localizetrack_<起>_<止>.csv`（`created,accepted,score,scale,cx,cy,note`）+ 接受/沿用/UI 跳过统计；
- 配套 `ai-training/src/track_plot.py` 可以把 CSV 画成底图轨迹图（[[工具-Python脚本清单]]）。

## 7. 效果与已知局限（诚实版）

已验证（`docs/小地图定位P0验证.md` §7.6、§9）：

- 真机标注回归集 **6 对 0 错**；
- 同一时间段 67 帧：修复前 40 接受/27 沿用 → 修复后 **60 接受/4 沿用**（4 帧都是真实误定位）；
- 两局全量：常规局接受 70%、机密局 54%；拒绝帧集中在"刚落地未绘制小地图 / UI 前后 / 室内地下 / 少量瞬移误报"，都可解释。

已知局限：

| 局限 | 说明 |
|---|---|
| **分数 ≠ 置信度** | 重复地形会高分误报（实测 0.904 却是错的位置）——必须叠加跨帧/尺度约束 |
| 室内/地下 | 小地图显示楼层平面图，与室外底图不匹配 → 需要分层图层（`daba_0f/1f/2f`，已挖通但楼层判别未解决，[[标定-分层图层]]） |
| 尺度跳动 | 相邻帧最佳尺度在 150/210/380 之间跳 → 用先验限制到最近 3 个尺度缓解 |
| 长空档 | 30s 上限下仍可能漏过一次瞬移误接受（常规局最大 46.92 m/s 就是这种） |
| 实时性 | C# 版带先验是几十 ms/帧；全图 8 尺度仍是几百 ms，8Hz 实时伺服需进一步收窄搜索 |

## 8. 它和导航的关系

定位是"我知道自己在哪"，不等于"我知道往哪走"。当前导航主路线是 [[决策-小地图定位导航]]：**地图标点 + 跟 HUD 标记**（让游戏引擎算路径）；定位器负责"验证/纠偏/路线对齐"，点位表见 [[标定-出生点与撤离点]]。
