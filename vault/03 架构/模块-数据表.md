# 模块-数据表

> [!info] 一句话
> 界面认哪几个字、按钮在哪、路怎么走、参数多少——全部写在 `data/*.json` 和 `workflows/*.json` 里，代码只负责"读表"；所以**加界面 = 加标记，加按钮 = 加元素，换识别方式 = 改一个字段**，不用重新编译。

## 1. 为什么这么做

游戏会更新：按钮挪位置、文案改一个字、活动弹层插进来。如果这些写死在代码里，每次更新都要改 C#、编译、跑测试。数据驱动把"**变化快的部分**"（坐标/文案/流程/阈值）和"**变化慢的部分**"（识别算法/输入模拟/安全网）分开：

```
算法与安全网（代码，稳定）  ←  读  ←  数据表（天天改：标记/坐标/阈值/流程）
```

代价是：数据表是**唯一真相**，写错了程序不会提醒你"这不合理"，只会在真机上等不到界面。所以有个 `smoke` 命令专门做数据层冒烟，`chain` 还有加载期校验（[[模块-chain引擎]] §7）。

## 2. 全表速查（12 个 JSON）

| 文件 | 管什么 | 谁在读 |
|---|---|---|
| `screens.json` | 界面识别表：界面名 → 标记（模板/OCR）+ 动作 + 分组 + 自动关闭键 | `ScreenDetector`、`HudStateGate`、chain 的界面校验 |
| `elements.json` | 元素表：语义名 → 识别策略 + 参数（坐标/模板/关键词） | `ElementClicker`（click/chain）、`annotate` |
| `zones.json` | 具名区域表：`zone_bottom_right` 之类的 `[x,y,w,h]` | `ScreenDetector`、`ElementClicker` |
| `runtime.json` | 本机标定：窗口关键字、转向标定、设计分辨率、轮询间隔、拟人化参数、伺服参数、会话限额 | `Program`、`ChainCommand`、`InputService`、`patrol`/`drill` |
| `game_ops.json` | 键位映射 + 复合动作（拾取/开背包/静步…） | `CommandUtil.ResolveKey`、chain（伺服取 `move_forward`/`sprint`）、`patrol`/`drill` |
| `zero_dam_points.json` | 零号大坝出生点 14 个 + 撤离点 4 个（世界坐标 + 底图像素坐标） | `DataStore`（`smoke` 统计）、后续路线规划 |
| `item_catalog.json` | 物品库（字段已定、`items` 仍为空）+ 拾取门槛 | `EconomyAgent`（含单测） |
| `ai_vision.json` | AI 感知配置：模型/EP/ROI/滤波/门禁/日志 | `AiVision`、`airecord`、`ailabel`、`aiprobe`、`roitune`、`aieval` |
| `operator_presets.json` | 干员选择：地图 → 类型+序号；类型标签/头像锚点 | chain 的 `pick_operator`、`click_operator` |
| `loadout_preset.json` | 配装预设（`presets` 空）+ 策略 `source/max_tier` | 预留（`smoke` 统计） |
| `item_values.json` | 材料价值占位表（示例数据） | 预留（`smoke` 统计） |
| `gui_settings.json` | 本机个人设置：上次工作流/模式/窗口位置 | `MainForm` 读写（[[模块-GUI]]） |

> 每个文件"改了会影响谁 / 属于哪一类（可改配置 / 标定结果 / 个人设置）"的完整表格见 [[数据-数据表清单]]。

## 3. screens.json：界面怎么认出来

结构：`screens.<界面名>.{ markers[], actions[], note, dismiss?, group?, enabled? }`

| 字段 | 含义 | 注意 |
|---|---|---|
| `markers[]` | 识别标记数组，**任一命中即判定该界面** | 语义见 [[模块-视觉识别]] §4（与老文档不同！） |
| `markers[].type` | `template`（图标/美术字）/ `ocr`（关键词） | `color` 仍待实现 |
| `markers[].require_all` | ocr 标记要求区域内**全部**关键词命中 | 防串台：`配装` 会命中配装界面的"确认配装"，必须连 `出发` 一起要求 |
| `markers[].region` / `region_name` | 只在区域内找 / 引用 `zones.json` 的具名区 | 全帧 OCR 会丢字（如"确认配装"丢"装"），区域更稳 |
| `actions[]` | 人能看懂的操作提示（`detect` 会打印） | 纯展示，不执行 |
| `dismiss` | 自动关闭键（如 `space_continue` → `"space"`） | 等待/分流时检测到就按键关掉再重识 |
| `group` | `lobby`（默认）/ `match`（对局内） | 链路只扫本组，省一半 OCR；局内 unknown 绝不能按 Tab 兜底 |
| `enabled` | `false` = 显式禁用 | 识别器跳过 |

当前 17 个界面：大厅组 13 个（lobby / mode_select / space_continue / plaza_first / plaza_ready / map_pool / map_select / loadout / preset_select / deploy_reminder / settlement / matching / char_select）+ 局内组 4 个（match_backpack / match_map / match_settlement_success / match_settlement_fail）。

写标记的经验（都来自真机踩坑，`note` 字段里留了痕）：

- **不要用会变化的内容做标记**：世界聊天频道、地图卡片名（美术字 OCR 读成乱码）、地图名条（广场/匹配界面也有）。
- 一个界面尽量配"主标记 + 兜底标记"：主标记稳（模板），兜底救（关键词）。
- 界面越像，越要 `require_all` 或加 `region`。

## 4. elements.json：按钮怎么点

结构：`elements.<语义名>.{ strategy, params{...}, note }`，strategy 四选一：

| strategy | 参数 | 用法 |
|---|---|---|
| `ocr` | `keywords[]` + 可选 `region`/`region_name` + **坐标兜底 `x/y`** | 主力：OCR 命中词的中心点去点；读不到就用坐标兜底并告警 |
| `template` | `template`（相对路径）、`threshold`（缺省 0.85）+ 坐标兜底 | 美术字/纯图标专用 |
| `coord` | `x`、`y` | 兜底：坐标直点，没有任何视觉校验 |
| `color` | `r/g/b/tolerance/min_ratio` | ❓待实现（字段已预留） |

流程只引用**元素名**（`click_element` 的 `element` 字段），所以"这个按钮从 OCR 改成模板"只需要改 `elements.json` 里的 `strategy` 和 `params`，链路一行都不用动。这也是这张表存在的核心理由。

降级链在 `ElementClicker` 里（`ElementClicker.cs:45-93`）：`ocr/template 命中 → 否则用坐标兜底（打警告）→ 都没配 → 报错`。

## 5. zones.json：把常用区域起个名

```json
{ "zones": {
  "zone_bottom_right": [1300, 880, 620, 200],
  "zone_center_bottom": [500, 850, 920, 230],
  "zone_right_mid": [1200, 540, 720, 180],
  "zone_left_mid": [0, 350, 450, 200]
}}
```

设计分辨率坐标。`screens.json` 与 `elements.json` 都能用 `region_name` 引用；解析顺序是"显式 `region` 优先，其次 `region_name`，最后全帧"，且具名区缺失只告警一次（[[模块-视觉识别]] §4）。

## 6. runtime.json：本机标定与参数总闸

| 字段 | 现值 | 说明 |
|---|---|---|
| `window_keyword` | 三角洲行动 | 所有命令默认用它找窗 |
| `px_per_90deg` | 4500 | 转 90° 需要的鼠标像素；**0 = 未标定，启动会警告**（[[标定-转向灵敏度]]） |
| `poll_interval_ms` | 300 | 等待界面的轮询间隔；有变更门后从 600 降到 300 |
| `design_width/height` | 1920×1080 | 所有坐标/区域/模板的基准 |
| `ocr_engine` | windows | `paddle` 未接入，指定会回退 |
| `humanizer.*` | 16 个通用键 + `mouse` 子段 10 个键 | 全部是随机范围（[[模块-输入拟人化]]） |
| `servo.*` | 8 个键 | 8Hz 伺服的控制参数（[[模块-伺服循环]]） |
| `session_limits` | 240 分钟 / 0 局 | 每日累计上限；0 = 不限（[[决策-会话限额与风控]]） |

## 7. game_ops.json：键位别写死在代码里

- `按键映射`：18 条语义键 → 实际键（`move_forward: w`、`sprint: shift`、`interact: f`、`quick_pickup: ctrl+left`、`knife: 3` …）；
- `复合动作`：7 个（`pick_up` / `quick_pickup_in_bag` / `open_inventory` / `open_map` / `auto_run_toggle` / `silent_move` / `close_popup`），每个是一串步骤，步骤 op 支持 `move_to | key | key_combo | key_down | key_up | move_hold | wait`；
- **注意**：界面坐标已迁到 `elements.json`，本表只留键位与动作（文件里的"界面坐标点说明"字段写着这件事）；还没实现"执行复合动作"的运行时，目前是数据储备。
- 改名/换键只改这里：伺服取 `move_forward`/`sprint`，`hold` 命令可用语义名（`hold move_forward 1500`）。

## 8. zero_dam_points.json：点位底库

- `spawn_points` 14 个（S1-S14）、`extract_points` 4 个（E1 东区隧道/常规、E2 西区公路口/常规、E3 坝顶/丢包、E4 维修通道/条件-负重要求）；
- 每条有两个坐标：世界坐标 `x/y`（与官网地图工具一致）+ `map_px`（官方底图 4096×3072 像素）；
- **约束写在 `说明` 里**：路线是计划、感知是裁判——点位表不得当盲执行脚本；物资点 `loot_points` 仍不恢复（[[决策-点位表恢复与路线规划]]、[[决策-禁止预设路线与反转]]）。

## 9. item_catalog.json / ai_vision.json

- `item_catalog.json`：条目字段 `name/ocr_keywords/type/tier/grid_w/grid_h/value/pick/note`，`min_tier_to_pick`（默认 2=绿）、`extract_deadline_min`（0=禁用）；`items` 现在是空数组（增量录入，[[模块-经济决策]]）。
- `ai_vision.json`：`enabled/model/ep/runtime_threads/roi/input_size/min_confidence/filter/avoid/drift/log`；两个"会自己改自己"的特殊点：`roitune` 保存 ROI 时写回它，`AiVision` 自动禁用时把 `enabled` 写回 false（[[模块-AI视觉感知]] §6）。

## 10. 改数据的三条守则

1. **坐标系只有一个**：所有坐标/区域/模板都按 1920×1080 写，运行时会缩放。别按当前窗口实际尺寸写。
2. **改完先冒烟**：`dotnet run -- smoke` 能把所有表加载一遍并打印统计；涉及链路的用 `chain` 启动——加载期校验会先把"引用了不存在的元素/界面/模板"挑出来。
3. **留 `note`**：这张表最宝贵的不是数值，是"这个值是怎么来的、哪一局截的图"。别人（和未来的你）只能靠它判断能不能改。
