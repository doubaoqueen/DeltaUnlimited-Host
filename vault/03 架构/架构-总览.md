# 架构-总览

> [!info] 一句话
> 整个程序就是一条流水线：**看清楚屏幕（感知）→ 判断现在该干什么（决策）→ 用手把键鼠按下去（执行）**；三层之间靠 `data/*.json` 数据表和 `workflows/*.json` 链路解耦，所以加界面/换按钮/改流程大多只改数据，不改代码。

![[project_overview.png]]

## 1. 三层 + 两条支柱

| 层 | 一句话职责 | 主要代码 | 对应笔记 |
|---|---|---|---|
| 感知层 | 把屏幕变成"我现在在哪个界面、前面能不能走、脚下有没有货" | `Capture/`、`Vision/` | [[模块-截图与窗口]]、[[模块-视觉识别]]、[[模块-AI视觉感知]]、[[模块-小地图定位器]]、[[模块-感知信号]] |
| 决策层 | 决定下一步做什么；**只做判断，不碰键鼠** | `Cli/Commands/ChainCommand.cs`、`Vision/Servo/ServoController.cs`、`Data/EconomyAgent.cs` | [[模块-chain引擎]]、[[模块-伺服循环]]、[[模块-经济决策]] |
| 执行层 | 把"点这个元素 / 转这个角度 / 按这个键"变成真实的 SendInput 事件 | `Input/`、`Vision/Servo/ServoActors.cs` | [[模块-输入拟人化]] |
| 数据支柱 | 界面长什么样、按钮在哪、键位是什么、参数多少 —— 全部存 JSON | `data/`、`workflows/`、`Data/` | [[模块-数据表]]、[[数据-数据表清单]] |
| 工具支柱 | 人（我）用来标定、诊断、标注、训练的一堆命令与脚本 | `Cli/`、`ai-training/` | [[工具-CLI命令速查]]、[[工具-Python脚本清单]]、[[模块-GUI]] |

程序入口只有一个：`DeltaUnlimited/Program.cs`。它只做四件事——找仓库根、初始化日志、把 `runtime.json` 的拟人化参数与 OCR 引擎装好、按命令行第一个词分发命令。**不带参数或 `gui` 就是图形面板**，其余全是 CLI 诊断后门（`Program.cs:21-71`）。

## 2. 一次进场的实际数据流

```
游戏窗口（窗口化，标题含"三角洲行动"）
   │  CaptureService：BitBlt 截客户区 → BGRA Mat（不落盘）
   ▼
FrameTools.Normalize：缩放到设计分辨率 1920×1080
   │
   ├─ ScreenDetector.Detect ── 用 screens.json 的标记判断"当前是哪个界面"
   │       └─ OCR（Windows.Media.Ocr）+ 模板匹配（TemplateMatcher）+ 具名区域（zones.json）
   ▼
ChainCommand：switch_screen 查表分流 → 该界面对应的分支步骤
   │       ├─ click_element：ElementClicker 定位（ocr→template→coord 降级）→ ClickAt 安全网
   │       ├─ key：EnsureForeground → PressKey
   │       └─ follow_marker / wait_screen / if_ocr …（见 [[模块-chain引擎]]）
   ▼
ScreenDetector 再识别 → 进/没进预期界面 → 决定重试、软跳转还是留证据中止
```

对局内则是另一条节奏更快的链：`patrol` 或 `follow_marker` 跑一个 8Hz 的伺服循环（[[模块-伺服循环]]），AI 可通行性模型只往循环里塞一句"前面可能不能走"的预警（[[模块-AI视觉感知]]），动不动手仍由控制器和状态机决定。

## 4. 三条规矩贯穿全项目

1. **不盲点**：任何点击之前都要么 OCR/模板严格命中，要么坐标兜底 + 落点校验；校验不过就**放弃点击**（fail-open），绝不"大概在这儿点一下"。见 [[模块-输入拟人化]]、[[坑-ClickAt点到光标位置]]。
2. **伺服不下点击**：`ServoAction` 类型里只有转向/前进/冲刺三个动作字段，**没有点击字段**——这一点用反射测试钉死（`tests/DU.Tests/ServoControllerTests.cs:214`），谁想加点击进去测试会红。见 [[决策-双引擎架构]]。
3. **预测层不夺权**：AI 模型永远只是"传感器"，`enforce=true` 的语义是"提前拉动**既有**守卫"，不是新增决策；失败一律 fail-open 回退原始守卫。见 [[决策-AI视觉observe-only]]、[[决策-红线与边界]]。
