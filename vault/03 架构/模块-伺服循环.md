# 模块-伺服循环

> [!info] 一句话
> 对局内"跟着导航标记走"这件事不能靠一条条死步骤，得靠一个**每秒看 8 次、每次只微调一点**的闭环：看一帧 → 算一个动作（转向/前进/冲刺）→ 交给键鼠执行 → 再等 125ms 看下一帧。

## 1. 它负责什么、为什么需要它

进场是"界面流转"，慢一点无所谓；局内走位是"连续控制"，必须快而且能随时刹车。两者的失败代价也不同：点错按钮只是白跑一局，走位失控会直接把角色送进墙角或敌人面前。

所以这里做了两层分离：

- **`ServoLoop`（编排层）**：管节奏、管收尾、管急停。感知和动作都是**委托注入**的（`Func<ServoFrame> perceive` + `Action<ServoAction> act`），意味着不用开游戏就能用假实现跑单测（`ServoLoop.cs:33-41`）。
- **`ServoController`（控制层）**：**纯函数**，输入一帧感知 + 随机源，输出本周期动作。没有 IO、不注入输入、不做决策裁决（`ServoController.cs:32-36`）。

## 2. 一个周期里发生什么（顺序很重要）

`ServoLoop.Run` 的循环体（`ServoLoop.cs:52-112`）：

| 顺序 | 检查 | 命中后 |
|---|---|---|
| 1 | 急停 `stopped()`（默认 `CommandUtil.StopRequested`） | 返回 `Stopped`，**不动手** |
| 2 | `perceive()`（异常 → 返回 `Error`，**不抛出**） | — |
| 3 | 记录本帧帧差进滑动窗口 | — |
| 4 | 到达 `IsArrived`（距离可读且 ≤ 12m） | 发一个 `Idle` → 返回 `Success` |
| 5 | 卡死 `IsStuck`（最近 3 周期帧差都 < 4.0） | 发 `Idle`（松手） → 返回 `Stuck` |
| 6 | AI 可通行性预警连续 ≥10 周期 | 发 `Idle` → 返回 `Danger`（交人工，**不自动绕行**） |
| 7 | `Decide()` 算动作 → `act()`（异常 → 返回 `Error`） | — |
| 8 | 超时（默认 180000ms） | 发 `Idle` → 返回 `Timeout` |
| 9 | `sleep(125ms)` 进下一周期；跑满 `MaxCycles`（10000）也返回 `Timeout` | — |

> [!tip] 为什么"松手"是发 `Idle` 而不是直接 Release
> 因为动作执行器（`KeyboardMouseActor`）自己知道"从按下到松开"的状态，发一个 `HoldForward=false` 的 `Idle` 就会走它正常的"状态变化才动键"路径。真正的兜底释放由 `FollowMarkerOp` 的 `finally` 做（见 §6）。

## 3. 四道收尾判据（+1）

| 判据 | 阈值来源 | 语义 |
|---|---|---|
| **急停** | `CommandUtil.StopRequested`（GUI 按钮/Ctrl+C/暂停面板中止三路同源） | 每周期都查，最高优先级 |
| **到达** | `servo.arrive_meters = 12` | 距离可读且 ≤12m 视为到点 |
| **卡死** | `StuckNeedLow = 3`、`StuckDiffThreshold = 4.0` | 连续 3 个周期画面几乎不动 = 贴墙/被卡住 |
| **超时** | `TimeoutMs = 180000`、`MaxCycles = 10000` | 未达成但过程安全 |
| **危险**（第 5 条，见下） | `BlockedGiveUpCycles = 10` | AI 连续 10 周期说"不可通行" → 交人工 |

结局枚举是 6 个值（`ServoOutcome`：`Success / Timeout / Stopped / Stuck / Danger / Error`），chain 侧按小写名字进 `branches`。

## 4. ServoController：比例控制 + 死区 + 抖动 + 钳制

参数全部来自 `data/runtime.json → servo`，代码里另有同值默认（`ServoController.cs:7-30`）：

| 参数 | 值 | 作用 |
|---|---|---|
| `turn_gain_min/max` | 0.35 / 0.55 | 比例增益：像素偏差 × 增益 = 本周期转向像素（**每次随机取**） |
| `deadzone_px` | 40 | 死区：偏差在 ±40px 内不转，避免来回抖 |
| `max_turn_per_cycle` | 260 | 硬钳制：单周期最多转 260px，防失控 |
| `turn_jitter_px` | 12 | 叠加在转向量上的随机抖动（±12） |
| `arrive_meters` | 12 | 到达判定 |
| `sprint_until_meters` | 60 | 距离 >60m 才冲刺（近了不冲，防冲过头） |
| `search_forward_ratio` | 0.6 | 标记不可见时"走走停停"的前进概率 |

决策顺序（`Decide`，`ServoController.cs:39-81`）：

1. **转向**：`偏移 × 随机增益 + 随机抖动` → 钳到 ±260；如果钳完正好是 0，给一个 ±1 的最小方向量（"钳到 0 也要给一个最小方向量，避免僵住"）。
2. **前进**：标记可见就前进；不可见时按 `search_forward_ratio` 概率前进（不盲目狂奔错过标记）。
3. **冲刺**：`forward && 标记可见 && (距离未知 || 距离 > 60)`。
4. **AI 预警优先**：`HitBlocked = true` → 立刻 `forward = false, sprint = false`，转发一句"可通行性预警：松前进键"。

`IsArrived` 要求"距离可读"（`DistanceMeters >= 0`），距离不可读时返回 false，交给上层用超时/其它判据——这条约束在当前实现里有个副作用，见 §7。

## 5. 红线：ServoAction 里没有"点击"

`ServoAction` 只有四个字段（`ServoTypes.cs:44`）：

```csharp
public sealed record ServoAction(int TurnDx, bool HoldForward, bool Sprint, string Note);
```

没有 Click/X/Y，也**不允许**有。理由写在类型注释里：点击永远回 chain 层走 `ClickAt` 的落点安全网，移动永远只受急停与钳制约束，**两类风险不混在一起**。

这条红线用反射钉死（`tests/DU.Tests/ServoControllerTests.cs:214-223`，`Loop_OnlyEmitsMovementActions`）：断言属性名里不含 `Click/ClickX/ClickY`、但含 `TurnDx/HoldForward`。以后谁想加点击进去，测试先红。

## 6. 三个实现件：感知器、执行器、薄壳

### 6.1 `TemplateMarkerPerceiver`（真实感知器）

每周期：抓帧 → `FrameTools.Normalize` 到设计分辨率 → 算 `FrameDiff`（顺手给卡墙守卫用，不另起采样）→ 导航标记模板匹配（默认阈值 0.8，可传 `searchRegion` 限定搜索区域省时抗干扰）→ 输出：

- `MarkerVisible = 模板命中`
- `MarkerOffsetPx = 命中中心 X − 设计宽/2`（正 = 偏右）
- `DistanceMeters = -1`（**距离暂时不可读**）
- `HitBlocked = false`（AI 预警 K1 后接，observe-only 起步）

（`TemplateMarkerPerceiver.cs:37-54`）

### 6.2 `KeyboardMouseActor`（真实执行器）

- 转向：`InputService.MoveRelative(TurnDx, 0)`（自带缓动/抖动拟人化）
- 前进/冲刺：**只按 W 与 Shift**，且**状态没变就不动键**（`if (forward == _forwardDown && sprint == _sprintDown) return;`）
- 状态切换时先 `ReleaseAllHeldKeys()` 再按（防连按抖动），按键用 `PressKeys`（持续按住不自动松）
- `Release()`：`ReleaseAllHeldKeys()` + 清零内部状态
- 键位**不写死**：构造时注入，chain 里从 `game_ops.json` 的 `move_forward` / `sprint` 取（默认 `w` / `shift`）

（`ServoActors.cs:26-63`）

### 6.3 `FollowMarkerOp`（chain 的薄壳，只做三件事）

```
接线（注入感知/动作/停止检查） → try { ServoLoop.Run(...) } finally { act.Release(); }
```

薄壳里**没有任何逻辑**：不判断、不等待、不记录。它存在的唯一理由是"任何结局都保证松键"——`finally` 是最后一道保险（`FollowMarkerOp.cs:11-27`）。

chain 侧的接线（`ChainCommand.cs:125-158`）：

```csharp
var actor = new KeyboardMouseActor(ops.KeyMap.GetValueOrDefault("move_forward","w"),
                                  ops.KeyMap.GetValueOrDefault("sprint","shift"));
var perceiver = new TemplateMarkerPerceiver(() => CaptureService.CaptureWindowMat(winKeyword),
                                           Path.Combine(repoRoot, tpl), designW, designH);
var servo = FollowMarkerOp.Run(perceiver, actor, runtime.Servo,
                              new ServoLoop.Options { TimeoutMs = s.TimeoutMs ?? 180_000 },
                              new Random(), stopped: () => CommandUtil.StopRequested);
```

结局 → `branches["success"|"timeout"|"stopped"|"stuck"|"danger"|"error"]`；只有 `servo.Ok`（Success）会顺序落到下一步，否则用 `default` 兜底，两者都没有就中止链路。

## 7. 现状与已知缺口（诚实版）

| 项 | 状态 |
|---|---|
| 伺服骨架 + 控制器 | ✅ 已实现，纯逻辑单测覆盖（假时钟/假感知） |
| `follow_marker` op | ✅ 已接进 chain，加载期会校验模板与分支 |
| 导航标记模板 | ❓待标定（K0 之后裁） |
| 距离/到达判定 | ❌ `DistanceMeters` 恒为 -1，因此 `IsArrived` 永远 false，`Success` 当前**走不到**——实际结局只会是 `Timeout / Stuck / Stopped / Danger / Error`。方案是"距离数字可 OCR → 数字阈值；不可 → 模板尺寸阈值"，尚未实现 |
| 真机验收 | ❌ K1 尚未跑通；`enter_match.json` 里也还没有 `follow_marker` 步骤 |
| AI 预警接线 | ❌ `HitBlocked` 恒 false（等 K1 后接 observe-only） |

> [!warning] 别把"有代码"当"能用"
> 伺服这一套现在的定位是**骨架已就绪、真机未验收**。`ServoLoop` 的急停/卡死/超时收尾是可信的（单测覆盖），但"能不能真的跟着标记走到撤离点"还没人验证过。
