# 模块-输入拟人化

> [!info] 一句话
> 所有键鼠动作都走同一个出口 `InputService`：鼠标要沿随机贝塞尔弧线"甩"过去而不是瞬移，按键要有随机停顿，点击前**先读回光标实际落点**，偏了就不点——拟人是降低机械感，落点校验才是防误操作。

## 1. 它负责什么、为什么需要它

决策层算出"点 (1738, 966)"这种数字，真正把它变成游戏里的一次点击要靠 `SendInput`。这个模块解决两类问题：

- **像人**：直线瞬移 + 精确到毫秒的固定间隔，是最容易被识别为脚本的特征。所以轨迹、时长、停顿、按压时长全部带随机范围。
- **别点错**：游戏抢光标、窗口抖动、移动末点丢失，都可能让点击落在错误位置（最惨的是点在"取消/放弃"上）。所以每次点击前都要校验落点，**宁可这一下不点**（fail-open），交给链路的等待/重试接管。

> [!warning] 铁律：拟人化参数必须保持随机范围
> `runtime.json → humanizer` 里每一项都是 `min/max` 或概率，`Code` 里也一律用 `Rand(min, max)` / `rng.NextDouble()` 取样。**禁止为了"好调试"把它们改成固定值**——固定参数会让连续操作出现一模一样的轨迹与节奏，拟人化就白做了（`data/runtime.json:3` 的说明字段写死了这条）。

## 2. 两套移动方式，别混用

| 方式 | 用途 | 实现 | 特点 |
|---|---|---|---|
| **绝对移动** `MoveHumanized(x,y)` / `ClickAt` | 点 UI 元素（屏幕坐标已知） | `MousePathPlanner.Plan` 生成路径点 → 逐点 `SendAbsolute` | 随机弧线 + smoothstep 缓动 + 过冲 + 抖动，**末点严格等于目标** |
| **相对移动** `MoveRelative(dx,dy)` | 转视角（游戏内鼠标增量） | 分段正弦权重 + 抖动，重新归一化 | 保证总和**精确等于** (dx,dy)，不受系统指针加速影响 |

### 2.1 绝对移动：路径规划（`Input/MousePathPlanner.cs`）

参数来自 `runtime.json → humanizer.mouse`：

| 参数 | 值 | 作用 |
|---|---|---|
| `min_duration_ms` / `max_duration_ms` | 250 / 650 | 移动总时长范围（按距离缩放后夹取） |
| `per_pixel_ms` | 0.5 | 每像素追加时长：远一点就慢一点 |
| `step_interval_ms` | 12 | 每步间隔（实际按 ±30% 随机） |
| `curvature_max_px` | 90 | 弧线最大曲率（法向偏移，实际取 `min(90, 距离×0.35)` 再乘随机正负） |
| `jitter_px` | 2 | 途中逐点抖动（**只加在途中，末点不加**） |
| `overshoot_probability` | 0.18 | 过冲概率 |
| `overshoot_px_min/max` | 5 / 22 | 冲过头再收回的幅度 |

生成逻辑（`MousePathPlanner.cs:17-73`）：

1. 距离 ≤ 6px → 只返回终点（人也常常只微移一次）；
2. 控制点 = 中点 + 法向随机偏移（弧线方向/幅度每次不同，不重样）；
3. 步数 = 时长 / 步间隔（最少 6 步）；
4. 每步用 **smoothstep** `e = t²(3-2t)`（起步慢→中途快→收尾慢）在二次贝塞尔上取点；
5. 途中加抖动，**末点精确**;
6. 按概率追加"过冲点 + 回终点"两帧（人甩鼠标常见动作）。

### 2.2 相对移动：转视角（`InputService.cs:168-211`）

```csharp
int steps = Math.Clamp(dist / 70 + Rand(Config.StepExtraMin, Config.StepExtraMax), 4, 28);
double s = Math.Sin(Math.PI * t);                 // 正弦缓动：慢-快-慢
weights[i] = s * (0.8 ~ 1.2 随机抖动);
accX += dx * weights[i] / wsum;                   // 重归一化 → 总和精确
```

距离 ≤2px 直接一次 `SendRelative`（"鼠标微调"）。每步之间 `sleep(Rand(mouse_step_delay_min, mouse_step_delay_max))`（3-11ms）。

## 3. 点击安全网：ClickAt 的落点校验

`ClickAt`（`InputService.cs:58-91`）是**所有点击的唯一入口**：

```
MoveHumanized(x, y)                          // 拟人弧线，末点=目标
sleep(Rand(click_pause_min, click_pause_max)) // 到达后自然停顿 150-320ms
VerifyLanding(tol)                           // GetCursorPos 读回，|dx|<=tol && |dy|<=tol ?
  ├─ 通过 → 按下左键（DOWN 先登记进急停释放清单）
  │           sleep(Rand(press_hold_min, press_hold_max))  // 100-220ms
  │           finally → UP
  └─ 不通过 → MoveAbsoluteTo(x, y)（硬钉正，无拟人无过冲） → sleep(10ms) → 再校验
               ├─ 通过 → 点击，并打印"首次落点偏离，已直接钉正"
               └─ 仍偏 → ⛔ 不点击，返回 false
```

- 容差 = `humanizer.mouse.verify_tolerance_px`（默认 **6px**，代码再 `Clamp(2, 30)` 防手滑填 0 或 500）。
- 返回 `bool`：调用方必须看。`ElementClicker` 拿到 false 会 `Logger.Warn("点击被安全网拦截")` 然后由链路的等待/重试逻辑接管（`ElementClicker.cs:95-96`）。
- **DOWN 先登记再 try/finally UP**：中间任何异常（SendInput 被拒/焦点突变）都会补发 UP，急停时 `ReleaseAllHeldKeys` 也放得掉这颗键，防"左键卡死"（`InputService.cs:76-88`）。

## 4. 按键：只释放自己按过的键

这是踩过坑之后的修正（评审 P2-10）。

| 方法 | 语义 | 释放策略 |
|---|---|---|
| `PressKey(key)` | 短按（支持 `"ctrl+left"` 组合串、鼠标键 token `left/right/middle`） | `finally` 里**只释放本次按下清单里的键**（逆序），不会误放"正在长按的 W" |
| `PressKeys(keys)` | 持续按住**不自动松开**（连续移动用） | 调用方必须配 `ReleaseAllHeldKeys()` |
| `HoldKey` / `HoldKeys` | 按住一段时间后松开，时长 × `hold_jitter`（0.92-1.08 随机） | `finally` → `ReleaseAllHeldKeys()`（兜底全释放） |
| `ReleaseAllHeldKeys()` | 释放所有仍按下的键/鼠标键 | 可重复调用，急停/异常/退出都用它 |

细节：

- `TokenDown` 会把按键登记进 `HeldKeys`（`HashSet<ushort>`，加锁），**已在按下状态则返回 false**，避免重复 DOWN（`InputService.cs:318-341`）；
- 鼠标键的 UP = DOWN << 1（left `0x0002`→`0x0004`、right `0x0008`→`0x0010`、middle `0x0020`→`0x0040`）；
- 组合串按 `+` 拆分（`SplitCombo`），每个 token 之间 `sleep(Rand(key_gap_min, key_gap_max))`（15-30ms），模拟人手顺序；
- 修饰键归一化成**左侧键码**（`VK_SHIFT→VK_LSHIFT` 等），因为部分引擎不认通用 VK（`InputService.cs:373-379`）；
- 键盘事件自动补扫描码（`MapVirtualKey`），`INPUT` 结构体按 x64 显式 40 字节布局。

## 5. 绝对定位的坐标系与限制

- `SendAbsolute` 用 `SendInput` 的**归一化绝对坐标**（0-65535），不受系统"提高指针精确度"加速影响；
- 归一化以**主屏**尺寸计算，负坐标或超出主屏会被钳回并打印告警——**多显示器越屏定位未支持**（`InputService.cs:132-158`）；
- `Configure()` 会顺带 `CaptureService.EnsureDpiAwareness()`，保证"读回光标位置"与"发送绝对坐标"在同一个物理像素坐标系里；
- `EnsureForeground(hwnd)`：先模拟一次左 Alt 让本进程获得前台权限，再 `SetForegroundWindow`，失败重试一次，睡 150ms 后核对 `GetForegroundWindow`。**FPS 必须有键盘焦点才能收到移动输入**，详见 [[模块-截图与窗口]]。

## 6. 一次性验证命令

| 想验证什么 | 命令 |
|---|---|
| 轨迹像不像人（不点击，可反复跑看随机性） | `mousetest <x> <y>` |
| 落点校验有没有生效 | `clickat <x> <y>`（会打印"✅ 已点击 / ❌ 被安全网拦截"） |
| 按键/长按是否到达游戏 | `hold <键名> <毫秒>`（帧差验证） |
| 转视角标定 | `turn <dx> [dy]`（配合 [[标定-转向灵敏度]]） |

## 7. 已知限制

| 项 | 说明 |
|---|---|
| 多显示器 | 绝对坐标按主屏归一化，窗口在副屏会被钳回并告警 |
| 管理员权限窗口 | 目标进程以管理员运行时，普通权限的 `SendInput` 可能被 UIPI 拦掉 → ❓待确认（未实测记录） |
| 过冲 | 只在路径点数 ≥2 且有末段方向时触发；极短距离不会过冲（合理） |
| 点击失败的处理 | `ClickAt` 返回 false 只是"这一下没点"，**要不要重试是链路的事**（`retries`/`expect_screen`） |
