# 决策：声音感知立项，但暂不投入

> [!info] 一句话
> 技术上完全做得到"听到游戏里的枪声和脚步"——用 **WASAPI 回环**录下"耳机里正在响的声音"，性质跟截图一样，不读内存也不注入。但 2026-10-22 用户决定：**先立项留档，暂不投入**。

## 一、能做：把"听的"变成"看的"

`WASAPI Loopback`（Windows 回环采集）= 捕获**声卡正在播放的混音**，也就是玩家耳机里听到的一切。

- 不碰游戏进程、不注入、不改音频设备——**和截屏是一个级别的侵入性**（零）；
- 现成实现：`NAudio` 的 `WasapiLoopbackCapture`，或 `Windows.Media.Audio`；
- 延迟约 **30-80ms**（回环缓冲 + 分析），做"告警级"决策够用，做不了瞄准级。

> [!note] 术语：WASAPI / 回环
> WASAPI 是 Windows 的音频接口。**回环（loopback）**指"把输出当输入录回来"——你不用麦克风，也不用挂钩子，就能拿到系统正在播放的声音。

已知风险：如果游戏用 **WASAPI 独占模式**输出，回环可能拿到静音。这个要在 A0 阶段先用代码探测。

## 二、难的是"方向"，不是"有没有"

| 想知道什么 | 难度 | 原理 |
|---|---|---|
| 左边还是右边 | ⭐ 容易 | 立体声两个声道的能量差，直接可读 |
| 前面还是后面 | ⭐⭐⭐ 难 | 游戏用 **HRTF**（头相关传输函数）把前后差异编码进频谱细节里；简单能量分析无效，需要机器学习，还依赖耳机与空间音频设置 |
| 精确方位角 | ⭐⭐⭐⭐ 很难 | 需要大量"已知方向"的标注数据训练，标注成本高 |

如果输出是 5.1/7.1，或者开了 Windows Sonic / Dolby Atmos，方向就显式分布在多声道里，**难度各降一档**。

## 三、边界：只做避让，不做交战

这是红线②在声音上的延伸：

**可以做**（"遇险即停 / 避战"原则内）：

1. 枪声检测 → 提前告警（比"受击红屏"早数秒），触发暂停或改道；
2. 脚步声 → 附近有人 → 停 / 绕（跑刀的核心就是避战）；
3. 方向辅助避让：左边有枪声 → 后续路径避开左侧；
4. 事件音校验：撤离倒计时、开门、拾取音，作为状态机的额外确认信号。

**不做**（禁止）：

- ❌ 用声音**定位敌人并引导瞄准/交火**；
- ❌ "声呐透视"式的敌人精确位置显示。

> [!important] 一句话记住
> **声音只做"感知 → 避让/暂停/改道"，不做"感知 → 交战"。**

## 四、2026-10-22 的决定：暂不投入

用户的原话被记在文档里：**"这是我还没有了解到的领域"**。

所以这个提案的状态是"**未来待办 / 仅参考**"——只留可行性分析、技术路径、边界与验证计划，**当前没有任何代码**，也不影响 K1 路线。

为什么先不做（从文档能读出的理由）：

1. **不在关键路径上**。K1 现在缺的是"知道自己在哪、往哪走"，不是"听声音"。多开一条线只会分散注意力；
2. **它对用户是新领域**。音频信号处理（频谱、HRTF、事件检测）的门槛比截图匹配高，学习成本要先算进去；
3. **它的价值依赖别的模块**。"左边有枪声 → 后续路径避开左侧"这句话，前提是**已经有路径/定位**。定位还没跑通，这条收益拿不到。

## 五、A0-A3 计划（都还没开工）

| 阶段 | 内容 | 预估 |
|---|---|---|
| **A0 录音采集器** | 新命令 `airesound`（或 `airecord --audio`）：WASAPI 回环录 WAV，并与帧时间戳对齐写 manifest | 1-2 小时 |
| **A1 实证分析** | 用录音验证：枪声/脚步事件能不能检测、左右能量差可靠否、前后可辨否、队友/敌人能否区分（可用已有两局的已知事件时刻对照：00:08:19 受击、00:11:38 击杀播报、00:40:24 被淘汰） | 2-4 小时 |
| **A2 事件检测器** | mel 频谱 + 轻量 CNN 或阈值法 → 输出"事件 + 方向 + 强度" | 1-2 天（需标注数据） |
| **A3 接入决策** | 作为伺服循环的危险信号（与红屏检测并列）→ 危险 / 暂停 / 改道；不参与任何交战逻辑 | 半天 |

> [!tip] A0 是最划算的一步
> 只写一个录音器，就能把"声音到底能不能用"这件事变成**可以听、可以看频谱**的实证问题——不用先训模型。

## 六、已知限制（要实测才知道有多严重）

- **队友和敌人的脚步/枪声很可能是同一套音效**。若如此，"脚步声"只能得出"附近有人"，分不出敌友。对跑刀够用（一律当敌人避开），但精细决策受限；
- 音效受玩家设置影响（HRTF 开关、音量平衡、声卡虚拟化），得按本机标定；
- 64 人混战下事件会重叠，多事件分离（声源分离）很难。

## 七、如果以后要做，怎么接进现有架构

| 层 | 做法 |
|---|---|
| 采集层 | 与 `Capture/` 平行新增 `Audio/`（WASAPI 回环），**不动截图链路** |
| 决策层 | 作为伺服循环的廉价危险信号（与红屏检测同级，`Vision/Signals/Signals.cs`） |
| 数据层 | 录音与 `airecord` 的帧时间戳对齐，方便"音画同帧"分析与标注 |

## 八、开工前要先确认的三件事

1. 音频输出形态：耳机还是音箱？有没有开 Windows Sonic / Dolby / DTS？游戏内是 stereo 还是 5.1/7.1？
2. 游戏是否使用 WASAPI 独占模式（决定回环能不能录到声音）；
3. 红线再确认一遍：声音只用于避让/暂停/改道。
