# 决策：红线与边界

> [!info] 一句话
> 这个项目最先定下的不是"做什么"，而是"**绝不做什么**"：不读内存/不注入、不做任何战斗击杀瞄准辅助、数据不出机器。功能可以砍，这三条不能谈。

## 背景

要做游戏自动化，技术上有很多"更省事"的路：读内存直接知道敌人位置、注入 DLL 拿到游戏内部状态、抓包看服务器消息。这些路都能让程序变准变快——但**一旦走上去，项目就不是同一件东西了**。

所以第一份文档（`docs/项目大纲.md`）里，"不做的"比"要做的"写得更早、更硬。

## 三条红线

| 红线 | 具体含义 | 为什么不让 |
|---|---|---|
| **① 不读内存、不注入、不封包** | 只用屏幕截图当"眼睛"、用 SendInput 模拟键鼠当"手"；程序看到的世界 = 玩家屏幕上看到的世界 | 读内存必须绕过反作弊，从此进入"检测 vs 绕过"的军备竞赛；而且它会让你**看到人不该看到的信息**，这在任何规则下都叫作弊 |
| **② 不做战斗/击杀/瞄准辅助** | 不自动开枪、不自动瞄准、不自动找敌人；对局里遇到危险一律停 | 这是项目从第一天就写在 README 里的红线；一旦沾战斗，"自动化助手"和"外挂"就没有区别了 |
| **③ 数据不出机器** | 模型本地跑（ONNX），素材、截图、录像都留在本机；不接云端 API | 素材里有别人的昵称、队伍信息；上传即违背承诺，也踩了"数据不出机器"这条自定线 |

> [!warning] 三条红线的作用不一样
> ①是**技术路线**的红线（决定了整个架构长什么样：截图 + 键鼠，所以慢、所以要做识别降级链）；
> ②是**伦理**的红线（决定了功能清单的天花板：跑刀可以，打架不行）；
> ③是**隐私**的红线（决定了 AI 只能本地小模型，这也直接导致了 VLM 预标注只能上 8B、不能换 32B）。

## 对局内新增的一条边界：遇险即停给人

进场链路做的是"点按钮"，风险低。到了对局内，情况变了——**局内战斗无法也绝不应该自动化**。

所以 2026-09-26 的跑刀方案里补了一条：检测到受击红屏、可通行性预警持续过久、连续卡死这类危险信号 → **暂停链路，交给人**。

特别注意：**不是自动逃跑**。因为在交火里"跑路"本身也是战斗行为（走位、绕枪线、判断掩体），自动化它等于自动化战斗的一半。文档把这条写成了"设计边界，不是缺陷"。

## 自制：不让它在别人眼里变成"挂机脚本"

红线之外还有一组"自律"条款，它们不是道德问题，是**让这个项目保持"辅助"量级**的约束：

| 条款 | 具体做法 | 依据 |
|---|---|---|
| **低频** | 单局节奏远慢于真人高手是正常的，不追求极限速度 | 跑刀方案 §9 |
| **拟人** | 鼠标贝塞尔轨迹、随机停顿、随机转向幅度、随机漫游方向——**所有参数必须是随机范围，禁止固定值**（这是入库的铁律） | `runtime.json → humanizer/servo`；2026-09-22 提交 `4ff3bcf` |
| **会话限额** | 默认每日累计 240 分钟自动化，到限应自动停；局数上限可配（0 = 不限） | `runtime.json → session_limits`；见 [[决策-会话限额与风控]] |
| **人必须在场** | K1-K5 全部是"人盯"形态；GUI 有急停按钮与暂停面板 | 跑刀方案 §9 |
| **急停优先** | 每周期都查急停；任何异常路径都释放所有按键 | [[模块-输入拟人化]]、[[模块-伺服循环]] |

## 风险自担

这一点必须说清楚：**以上所有手段只是降低风险，不保证不被风控识别**。任何游戏自动化都可能违反用户协议、导致封号。项目文档里这句话出现在 README、项目大纲、跑刀方案三处，不是客套话。

> [!danger] 不要因为"做得像人"就以为安全
> 拟人化只提高成本，不改变性质。低频、少量、有人看着用，是唯一诚实的建议。

## 为什么红线比功能重要

四个理由，按重要性排：

1. **红线决定"这是什么东西"**。同一个代码库，去掉红线就是作弊器，守住红线才是"看得见的自动化助手"。功能是加减法，红线是乘法——归零就全没了。
2. **有些线越过去就回不来**。读内存要持续对抗反作弊更新，投入只会越来越大，最后整个项目被这条线绑架。
3. **红线是唯一能在"加个功能很爽"时说"不"的东西**。项目里已经有过两次这样的时刻：VLM 预标注想上 32B（显存不够）、想调云端 API（违反红线③）——两次都是红线先否决，然后才去想别的办法。
4. **红线让"停"变得正当**。遇险停、认不出停、限额到停，这些"停"在别的项目里像 bug，在这里是设计。

## 红线靠什么机制守住（不是靠自觉）

| 红线 | 落地机制 |
|---|---|
| 不读内存/不注入 | 采集只走 GDI 截屏（`CaptureService`）；输入只走 SendInput；代码里检索不到任何进程内存读写或注入相关的 API 调用（`ReadProcessMemory` / `WriteProcessMemory` / `OpenProcess` / `CreateRemoteThread` 等） |
| 不做战斗辅助 | 伺服循环**只允许"转向 + 冲刺 + 停"三种动作，禁止任何点击**；点击一律退回 chain 层走落点校验；声音/视觉模块都只做"规避/暂停"，不做交战 |
| 数据不出机器 | ONNX 本地推理（DirectML/CPU）；VLM 用本地 vLLM 服务；素材目录 gitignore |
| 遇险即停 | `CommandUtil.StopRequested` 每周期检查；`Escalate`/暂停面板/急停按钮三路同源 |
