# 决策：AI 视觉只做感知（observe-only）

> [!info] 一句话
> 神经网络只当"传感器"——它输出"前面能不能走"，**走不走由确定性状态机决定**。上线不是"训练完就开"，而是过三档门禁：金标 ≥0.85 才允许干预，0.60-0.85 只能观察，<0.60 直接禁用。当前 v1 在金标集上 **0.695**，所以它在观察档里待着。

## 一、模型只做感知，不做决策

当前接进链路的模型只有一个：**可通行性三分类**（`passable` 可走 / `blocked` 不可走 / `no_ground` 没有地面）。

| 谁 | 负责什么 | 出错会怎样 |
|---|---|---|
| 模型（ONNX） | 看 ROI 里那一小块地，"像不像能走" | 分错一类，只是少一条参考信息 |
| C# 状态机 | 决定往前/绕/停/交人工 | 出错的后果由确定性代码兜 |

关键设计：

- `enabled: false` → 完全回退到原来的守卫逻辑，程序行为**分毫不变**；
- `avoid.enforce: false`（默认）→ 模型只记录、只统计，不影响动作；
- `enforce: true` → 预警才走既有的 `Escalate`（暂停/交人工）路径，**不会直接接管移动**。

> [!note] 术语：observe-only
> "只观察"。模型每帧都给判断、都写日志、都算矛盾率，但它的输出不参与任何动作决策。这是灰度上线的最低档。

## 二、三档门禁

启动时若金标集存在（`assets/ai/golden/labels.csv` 且 ≥10 张有效图），先在金标集上跑一遍：

| 金标 macro-F1 | 判定 | 效果 |
|---|---|---|
| **≥ 0.85** | 可执行 | 允许 `enforce`（仍需人工开） |
| **0.60 - 0.85** | **仅观察** | 本会话强制 `enforce` 失效，只记录 |
| **< 0.60** | 禁用 | 自动写回 `enabled=false`，模块整个关掉 |

阈值在 `data/ai_vision.json → drift`：`min_macro_f1 = 0.85`、`min_macro_f1_observe = 0.60`。

> [!important] 为什么是"自动降级"而不是"报警让人处理"
> 赛季更新会让模型**悄悄失能**：它还在输出、分数还挺高，但判断已经偏了。等人发现往往已经跑了几十局。所以门禁做成**每次启动自动判定**，宁可误关，不可漏关。

## 三、第二道防线：运行期矛盾率

离线门禁只能测"过去"，运行期还要测"现在"：

- 贴墙守卫触发 = 免费的噪声真值（守卫说撞墙了，模型却说可走 → 一次矛盾）；
- `DriftMonitor` 统计 10 分钟窗口内的矛盾率，**> 25%** 且样本 ≥20 → 自动禁用并写回配置。

这是全项目最省钱的一个设计：**不用人工标注就能拿到"模型可能错了"的信号**。

## 四、金标集必须独立

金标集是门禁的尺子，尺子歪了后面全歪。规矩写在 `assets/ai/golden/README.md` 里：

| 规矩 | 原因 |
|---|---|
| 必须**独立于训练集** | 否则测的是"背题能力" |
| **绝不可用 VLM 判断当标签** | VLM 自己也判不准（见 [[决策-VLM预标注探索与收尾]]），用它当标准答案等于自欺 |
| 每赛季**重建** | 赛季更新会换地图/光照，旧金标会失效 |
| 分层抽样（`make_golden.py --quota passable:45,blocked:35,no_ground:20`） | 极不平衡的数据集里，全猜"可走"也能有高分 |
| 全帧大图 gitignore | 游戏素材不出库 |

现状：376 张 ROI 图 + `labels.csv`（377 行含表头），类别分布 `passable 250 / blocked 106 / no_ground 20`。

## 五、当前状态：0.695，观察期

| 指标 | 数值 | 说明 |
|---|---|---|
| 训练集 val macro-F1 | **0.8722** | v1 训练时的 429 帧快照 |
| 金标集 macro-F1 | **≈ 0.695** | 376 张独立金标；落观察档 |
| 主短板 | blocked 召回 | 该停下的时候没停 |
| v2 候选 | 0.657 | 金标未过执行线，配置保持 v1 |

**两个分数差这么多，不是模型突然变差**：09-30 查出训练/验证切分的"会话键"取错了时间戳（用了裁剪导出时刻而不是采集时刻），同一段采集的相邻帧跨了 train/val → val 偏乐观。修好之后，金标仍是 0.695——**这才是真实水平**（见 [[坑-验证集泄漏]]）。

## 六、为什么这么保守

1. **错一帧的代价不对称**：模型多报一次"可走"可能就撞墙/掉沟/暴露，而它带来的收益只是"少看一帧"；
2. **决策权必须在确定的代码手里**：纯函数可以单测、可以复现；模型的输出不能；
3. **可回退是硬要求**：`enabled=false` 一行就回到"没有 AI"的世界，这条路径必须永远可用；
4. **人必须在场**：观察期就是给人看日志、看矛盾率的窗口。

## 七、要开 enforce，还差什么

- [ ] 金标 macro-F1 ≥ 0.85（当前 0.695）；
- [ ] 用新数据重训（当前已标注 1736 帧 vs v1 的 429 帧）；
- [ ] 金标集改成**独立采集**（现在是同一批素材分层抽的）；
- [ ] 按地图/赛季分组评估（避免"平均分掩盖某张图崩了"）；
- [ ] observe-only 跑够局数，看预警精确率与矛盾率；
- [ ] 真机验证"预警 → Escalate → 人工"这条路不误触。
