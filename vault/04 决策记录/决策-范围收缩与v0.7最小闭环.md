# 决策：范围收缩与 v0.7 最小闭环（2026-11-07 方向锚定）

> [!info] 一句话
> 三件事同时到门口（应战焦虑 / 自动售卖死线 / 进场链路不完美），用户一度觉得"迷失方向"。决策是**不扩功能、先收缩**：v0.7 锚定成一句话——**一键一局：进场（允许 ≤1 次人工救场）→ 走到撤离点 → 撤离 → 结算 → 停；卖货手动**。其他一切（auto-sell、多路线、楼层深化）都是这之后的加法。

## 背景

2026-11-07 用户自述"迷失方向"，三个压力同时挤进来：

1. **应战焦虑**：局内大量"疑似人机"干员会攻击玩家，用户觉得"不得不应战"与"不打真人"的理念冲突，很烦；
2. **自动售卖压力**：用户感觉"不做 auto-sell，帮没有哈夫币的玩家低成本攒钱的想法就不成立"，并给自己加了一个"一周内必须完善"的死线，但精力不够；
3. **进场链路不完美**：偶发广告无法应对、干员选择超时等，感觉"很多功能没做到位"，且"类似问题还有更多，懒得一次性说完"。

## 备选方案

| 方案 | 优点 | 缺点 |
|---|---|---|
| A. 按原样全速推（K1 全项 + auto-sell 一周完善） | 覆盖全面 | 精力不够；卖货 UI 未侦察就设计 = 空中楼阁；三线并行 = 三线都慢 |
| **B. 收缩锚定 v0.7 最小闭环（本篇）** | 精力集中到一条线；经济闭环最快成立；理念焦虑被拆成可回答的问题 | auto-sell 推迟；进场链路接受"救场模式"而非"完美自动" |
| C. 暂停开发，先"玩明白游戏"再继续 | 游戏知识更扎实 | 丢掉两个月积累的动量；而且"玩"和"做"并不互斥（见下文侦察周） |

## 最终选择与理由

选 B。三个痛点逐一拆解：

### ① 澄清：应战 ≠ 违背理念（最重要的一条）

> [!important] 三层分清
> 1. **工具红线不变**：不做战斗辅助。遇到交火 = 受击红屏信号触发 → 停 → 交人（[[标定-危险信号阈值]]、[[决策-红线与边界]]）。这就是工具在战斗话题上的**全部**行为，永远不参战——它不需要分清人机还是真人，眼里只有"危险→停"。
> 2. **用户本人手动应战人机，不违背"不打真人"**：人机不是真人。真正的顾虑是"误把真人当人机"——这个压力只存在于手动玩法，工具侧不存在。
> 3. **"不得不应战"是待验证的假设，不是事实**：裸装跑刀死了不亏东西，最优解往往是**脱离**（走掉/断视线）而不是接战。用几局"全程不接战"实验验证实际死亡率/丢包率，不靠猜。

避战是**路线问题**不是战斗问题：游戏知识用"每局 2 分钟记录热区"的方式攒（哪里遇到人/人机、哪里开阔没得躲、哪个撤离点人多），两周形成自己的避战热力图，直接喂给 `routes_zero_dam.json` 的危险区标注——与 [[决策-自动跑图实验v1]] 的"实验产侦察数据"是同一个思路。**游戏知识是攒出来的，不是先修完学分才能开工。**

### ② 自动售卖：降级为"数据驱动的半自动"，死线作废

- **现状核对（2026-11-07）**：`data/item_catalog.json` 标注"预留未启用"、`data/item_values.json` 是示例占位表、`Data/EconomyAgent.cs` 骨架+单测未接线（[[模块-经济决策]]）——售卖本来就是 K2 计划中、**未启动**，不存在"落后"。
- **它不是经济闭环的必要条件**：撤离成功 → 手动卖货 2 分钟，"跑刀攒钱"闭环已成立。auto-sell 是便利倍增器，不是使能器。
- **动手前先做 K0**：真机录一次完整卖货流程，回答"卖货 UI 长什么样、能否按价值排序、能否多选批量卖"，再定 v1 范围。**不在没见过 UI 的情况下设计。**
- **策略做成数据不做成代码**：`sell_rules.json` = 保留清单（任务道具 + 本周兑换所需低价值物）+ 品质/价值阈值；"每周刷新"= 花 5 分钟人工改 keep-list，不是改程序。**决策归人，机器只执行**——与 [[决策-禁止预设路线与反转]] 的"路线是计划，感知是裁判"同一哲学。
- **"一周必须完善"死线作废**：它与项目自己的 K0-K6 分期方法论矛盾（[[02 时间线]] 里两次"停下来砍掉错误路线不算失败"就是证据）。

### ③ 进场链路：目标从"完美"换成"失败便宜"

- 屏幕自动化**永远**会撞上新界面（广告、UI 改版、加载时序）——这是领域规律，不是实现缺陷。架构里 `mark_unknown` 留证 + `pause` 等回车 + GUI 急停**本来就是为"人救场"设计的**（[[模块-chain引擎]]）。
- 换可收敛指标：**连续 10 局，每局人工干预 ≤ 1 次**。"有很多问题"是没底的黑洞；干预次数是能画曲线、能按频率排队消灭的。
- 偶发广告、回车能过 → **人工放行本来就是设计内行为，不修**。干员选择超时这类高频卡点 → 一个坑 = `screens.json` 加标记 + 链路加一步（[[决策-识别分层降级链]]），遇到才修，不开专项。

### 推进顺序（每步约一周，随时可停）

| 步 | 内容 | 产出 |
|---|---|---|
| ① 侦察周 | autorun_walk 真机多跑收轨迹 + 手动玩记避战热区 + 录一次卖货流程——三个动作全是"玩"顺带做的，不是开发任务 | 轨迹数据 + 热区笔记 + 卖货 UI 答案 |
| ② 单路线 | `navigate_route` 伺服 + `routes_zero_dam.json` v0（只连一条：一个出生点→一个撤离点） | 第一次"定位带路"完整走通 |
| ③ 卖货 | 分析卖货 K0 素材 → 定 auto-sell v1 范围（大概率**半自动**：机器按规则选中，人按一下确认） | 卖货链路 v0 |

## 后续影响

- 带来的好处：精力集中到一条线；"迷失"变成一张三行表；应战理念焦虑被拆成三层各自可回答的问题；另外两条附带原则——**先把"没有哈夫币的玩家"定义成用户自己**（给别人用 = 支持成本与风险翻倍，等闭环在自己机器上稳定再说），以及**一次会话只推一条线，收尾写回 vault**（[[跨会话交接]]）。
- 代价/限制：auto-sell 推迟（接受手动卖货 2 分钟）；进场链路接受"救场模式"；受击信号接进 autorun_walk 之前，实验局必须人盯（红线照旧，见 [[决策-自动跑图实验v1]]）。
