# 决策：到达判据 = "撤离倒计时出现"，不用距离、不用 [F]

> [!info] 一句话
> 撤离点**没有交互键**——站进撤离区等 10 秒自动撤离，顶部出现倒计时卡片；这个卡片**只有人在区内才画**，所以"看到它 = 到了"。这是游戏引擎亲手给出的权威到达信号，比任何我们自己算的判断都硬。

## 领域事实（用户 2026-10-24 口径，推翻了此前的 [F] 假设）

| 撤离点类型 | 机制 |
|---|---|
| 常规（E1 东区隧道 / E2 西区公路口） | 站区内 10s 自动撤离，无任何按键 |
| 条件（E4 维修通道：负重要求） | 满足条件 + 站区内 10s |
| 丢包（E3 坝顶）/ 电梯（点位表外） | 同样有倒计时 UI，逻辑一致 |

## 判据三层（2026-10-24 技术债修复定稿）

1. **权威：`ArrivalPrompt`**——倒计时卡片角标模板匹配（见 [[标定-撤离倒计时角标]]）。workflow 里 `follow_marker` 步骤配 `prompt_template` / `prompt_region` 两字段。
2. **辅助：距离 OCR**——HUD 米数文字，未标定（恒 -1）；只做进度显示，不参与到达判定。
3. **兜底：`MarkerLost` 结局**——标记曾可见后持续消失 ≥25 周期 → 疑似到点上方，chain 走"确认"分支而不是当失败。

> [!warning] 为什么当初必须重做
> 旧代码 `DistanceMeters` 恒 -1 而 `IsArrived` 要求 ≥0——**Success 结局是永远走不到的死代码**，伺服只能以超时/卡死收场。

## 到达之后的行为（2026-10-26 闭环）

- 任意撤离区倒计时出现（**含电梯等点位表外撤离点**）→ 松键**站定**，只监视画面等 10s；
- 倒计时消失（被挤出/中断）→ 恢复导航；
- **撤离成功结算 = 终局收工**；撤离失败/死亡结算 = 终局交人；
- 走到目标点 250px 半径内但 **30s 未见倒计时** → 点位标偏或条件未满足，明确报告交人。
