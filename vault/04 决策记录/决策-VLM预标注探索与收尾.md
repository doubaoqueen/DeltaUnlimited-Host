# 决策：VLM 预标注探索与收尾

> [!info] 一句话
> 想用本地 Qwen3-VL-8B 先帮人画标注框，结果两轮实测都不合格——**框画不准、类别分不清、置信度还全是 0.95+ 没有区分度**。2026-10-11 当天判定"图标类不可用"，UI 模板线退回纯人工、GUI 暂停、YOLO 线关闭。

## 一、想解决什么

标注是 AI 训练里最贵的环节：裁 UI 模板、画检测框，全靠人一张张点。如果 VLM 能先"粗标"一遍、人只做"确认/微调/驳回"，成本能降一个量级。

计划里的两个出口：

| 出口 | 产出 | 谁受益 |
|---|---|---|
| UI 元素模板 | 裁好的小图 + `elements.json` 条目 | 界面自动化（进场链路、局内 UI） |
| 检测数据集 | 框 + 类别（YOLO 格式） | 将来的"搜/打"相关识别 |

模型跑在本机 vLLM 服务上（Qwen3-VL-8B-AWQ），**离线工具、不进运行时**，模型只出候选，入库必须人工审批。

## 二、P0：单图整帧直问（失败）

2026-10-11，40 帧金帧优先样本（`seed=42`），36 帧出框、共 73 框。三个失败模式：

| # | 症状 | 量化证据 | 根因 |
|---|---|---|---|
| 1 | **小图标框严重偏大** | extract 框中位 **143×213px**，真图标只有 25-40px，大了 **5-8 倍**；96% 的框中心落在左上角小地图区 | **网格粒度**：Qwen3-VL 对 1280×720 只有约 **46×26** 的感知网格，30px 的图标约等于 1 格，模型只能画"这一带" |
| 2 | **队友图标被误标成撤离点** | extract 出 **27 框**，远超每帧真实撤离点数 | 提示词没排除"带数字 1/2/3"的队友图标；8B-AWQ 对小图标的语义区分能力存疑 |
| 3 | **conf 没有区分度** | 全部 **0.95-0.98**，错的框和对的框一样高 | AWQ 4bit 小模型"不自知"——和初筛 v2 的观察一致，这次彻底实锤 |

我方设计失误（文档里自己认了三条）：

1. **单图整帧直问是 VLM 定位最弱的用法**，一开始就该设计"两步缩放"；
2. 提示词没排除队友图标（已知的盲区没写进去）；
3. 把初筛阶段已知的"conf 不可信"缺陷，带进了"高置信度自动通过"的设计里。

## 三、P0.5：两步缩放（还是失败）

对策是"粗定位 → 裁图放大 ≥4 倍 → 紧贴细框 → 映射回原图"。同一批 40 帧（seed 可复现）重跑：35 帧、99 框。

| 问题 | P0.5 实测 | 判定 |
|---|---|---|
| 框太大 | ✅ 解决：extract 中位 **24×23px**（P0 是 143×213px） | 通过 |
| **类别区分** | ❌ 失败：72 个 extract 框里仍混入**带数字队友图标 / 红色 X / 橙色救援 / 蓝色标记**；模型"**自相矛盾地附和**"——理由里明写"内含数字 1""此处为橙色"，照样输出"符合撤离点定义"，排除条款压不住 | **能力不合格** |
| 定位精度 | ❌ 结构性受限：30px 图标在送图里约 81px ≈ 3 个感知格，输出精度 ±1-2 格 ≈ 原图 **±10-20px**——框在图标附近，但打不中 | 结构性受限 |

中途还踩了一个工程坑：窄高裁图放大后（296×462 → 1280×1998）图片 token 2764 超过服务端 2048，每帧报 400。修法是"送图三约束"：宽 ≤1280、高 ≤2048、面积 ≤100 万 px，并写进自检回归。

## 四、结论与退路（当天执行）

**8B-AWQ 对细粒度图标检测不可用。** 按事先写在方案里的退路（"若放大后仍分不清，就退回人工"）：

1. **UI 模板线退回手动五步**：`capture` → `crop` → `tplprobe` → 写 `elements.json`/`screens.json` → `annotate` 复验。模板只有几十张，一次性成本，比折腾模型便宜；
2. **VLM 线收缩**：保留"粗定位（大区域找得准）+ 世界物体粗框"作为实验能力，**暂停 `aiground` 审批 GUI 的投入**；
3. **YOLO 线关闭**（用户当日判定）：这一轮世界物体召回很弱——enemy / corpse / prompt 均 **0 框**，container 22、loot 5；而且用户肉眼判定 container 框大多落在"没有白色高光的普通箱子"上 → **容器类别定义从一开始就错了**；
4. **换更大模型不可行**：32B AWQ 需约 18GB 显存（本机 12GB）；云端 API 违反"数据不出机器"红线。

## 五、教训（比结论更值钱）

| 教训 | 后续影响 |
|---|---|
| **单图整帧直问 = VLM 定位最弱用法** | 以后再用 VLM 做事，先想"能不能裁小再问" |
| **模型会"自相矛盾地附和"** | 提示词里的排除条款不等于约束；判据要放在代码里，不能交给模型自觉 |
| **conf 不能当自动通过的依据** | 方案里"≥0.9 自动通过"这条，对框类候选直接作废；分类型任务可保留 |
| **类别定义错了，标注全是白干** | "容器 = 带白色高光、需要 F 键搜索的物体"，不是"所有箱子"。**这条视觉线索转进了跑刀 K1 的搜刮识别**——错误路线的唯一回报 |
| **先写退路再开跑** | 方案里事先声明"不合格就退回人工"，所以收尾只花了一次判定，没有反复拉扯 |

## 六、留下了什么

- ✅ `prescreen.py` 的 VLM 初筛（分流素材、给建议标签）仍在用——它做的是"选帧/分类"，不是"画框"，属于能力范围内；
- ✅ `tplprobe` / `annotate` / `crop` 这套人工标注流程被验证为可靠的默认路径；
- ✅ "白色高光 = 可交互容器"这一条写进了跑刀感知设计；
- ❌ `aiground` 审批 GUI：方案成型但未投入（❓待确认是否有半成品代码）；
- ❌ YOLO 检测线：关闭，等有正确的类别定义和足够素材再说。
