# 决策：禁止预设路线，以及 10-21 的反转

> [!info] 一句话
> 2026-09-26 定的是"**全流程禁止预设路线**"（连点位表一起废弃）；2026-10-21 用户把它反转成"**允许「出生点 → 撤离点」的计划路线**"。反转的是"能不能有路线"，没变的是那条铁律——**路线是计划，感知是裁判**。

## 一、2026-09-26：禁止预设路线

### 当时的场景

跑刀的核心问题是"**去哪捡、怎么找到能捡的东西**"。最直觉的做法是做一张点位表：把每个容器/物资点的坐标记下来，进图按表跑过去开。

用户当时的决定是：**不做**。全流程禁止预设路线，同时把 `loot_points`（物资点位表）也废弃掉，`data/zero_dam_points.json` 只保留撤离点锚点。

### 文档里能读出的两条理由

文档没有逐条列理由，但从后续写法能看出两条：

1. **背表 = 盲执行**。点位表一旦写死，程序就不再"看"游戏了——它只是按坐标跑。地图改版、赛季更新、落点随机，表就废了，而且废得很隐蔽（还在跑，只是跑错）。
2. **现场感知更准，也更像人**。游戏自带的**交互提示**（准星旁出现"F 拾取"这类键位 + 名称提示）是"游戏自己声明这里能交互"的信号——免去世界理解、误报最低。按交互提示找东西，就是"进屋看见什么捡什么"，而不是"背地图跑路线"。

> [!note] 术语：交互提示
> 不是图像识别猜的，是游戏 UI 主动告诉你的。这类信号在自动化里最值钱，因为它把"识别问题"降级成了"读 UI 问题"。

### 连带影响

- `loot_points` 废弃 → 点位表文件只留撤离点；
- K2（搜刮原语）的设计被定成"随机漫游 + 交互提示检测"，不是"点位巡游"；
- 决策层（拾取判断）被要求做成**纯函数 + 白名单**，不依赖地图信息。

## 二、2026-10-21：反转为"允许计划路线"

### 变了什么

用户依据自己对地图的理解（并结合攻略与实测）判断：**跑刀应该有「出生点 → 撤离点」的计划路线**。这条路线由用户规划，规划好之后进数据表。

同时新增了一个配套的技术提案：**用局内小地图和官方底图做地形匹配的实时定位**（见 [[决策-小地图定位导航]]）。

### 反转的理由

| 理由 | 说明 |
|---|---|
| **"不知道自己在哪"是当时最大的浪费** | 没有定位时，只能在出生点附近随机漫游；有了"出生点 + 撤离点坐标 + 定位"，才谈得上"往某个方向走" |
| **路线只到"骨架"级别** | 只规划出生点 → 撤离点这一段，不规划物资点、不规划每一个房间——骨架路线不会替你"看见"东西，只替你别在开阔地瞎跑 |
| **定位能力让"计划"第一次可执行** | 点位表要有意义，前提是程序知道自己的位置。2026-10-21 的 P0 定位验证通过，这个前提才成立 |

### 没变的是什么

> [!important] 铁律：路线是计划，感知是裁判
> 走位**必须**由实时感知兜底：受阻、危险、出现交互提示 → 停或交人工。路线表**不得作为盲执行脚本**。

这句话被写进了三处，防止以后有人（包括 AI）把它当脚本用：

- `docs/跑刀方案.md` §1：执行铁律；
- `docs/跑刀工程提案.md` 开头：2026-10-21 决策变更；
- `data/zero_dam_points.json` 的 `说明` 字段：数据文件自己带约束，谁读数据都会看到。

另外：**`loot_points` 仍然不恢复**。这次放开的是"从哪进、从哪出"，不是"去哪捡"。

## 三、代价：维护成本

反转不是白拿的，成本主要有这几项：

| 代价 | 具体表现 | 现在怎么处理 |
|---|---|---|
| **每张图一份路线表** | 零号大坝一张，以后每张图都要人工规划一遍 | 只规划骨架路线（出生点 → 撤离点），工作量可控 |
| **会随版本/赛季过期** | 地图改版、撤离点规则变化，路线可能失效 | 路线表只作为"方向建议"，失效时感知还是会兜底；点位数据带 `note` 与来源 |
| **诱惑：路线表很容易变成脚本** | 写表的人（和 AI）天然想把"计划"写成"必须" | 铁律写进文档 + 数据文件 + 每次讨论都复述；执行层保留"感知优先" |
| **路线 × 感知冲突要先定规则** | 路线说往东、感知说有墙/有人，听谁的？ | 听感知：停 / 绕 / 交人工，路线让位 |
| **测不出"路线有没有用"** | K1 还没真机跑通，路线收益没有数据 | ❓待确认：等 K1 验收后再评估路线是否真的省时间 |

## 五、这次反复留下的经验

1. **"禁止"和"允许"之间要留一句不变的原则**。这次能顺利反转，是因为当初就把"路线是计划、感知是裁判"写成了原则，而把"禁止路线"写成了策略——策略可以改，原则不用改。
2. **决策的可行性前提要写下来**。当初禁路线，一部分原因是"没有定位，路线没法执行"；这个前提变了，决策就该复核。
3. **数据文件自己带约束**。`zero_dam_points.json` 的说明字段比文档更难被忽略——改数据的人一定看得见。
