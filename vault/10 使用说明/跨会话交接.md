# 跨会话交接（新开对话怎么接上）

> [!info] 一句话
> 新开会话 = **记忆清零，但磁盘上的东西都在**。所以规则只有一条：**想让下一次记住的，必须写进文件**。

## 1. 为什么新会话"上下文不会变复杂"

每个对话是一个独立的"工作台"：

| | 同一个会话（聊很久） | 新开会话 |
|---|---|---|
| 上下文 | 越堆越多，到一定程度会被**自动压缩成摘要**（细节会丢） | 从零开始，干净、便宜、反应快 |
| 记忆 | 只记得摘要里剩下的 | **不记得任何对话**，只认文件 |
| 适合 | 一件事的连续深挖（当天） | 换任务、换项目、隔天继续 |

所以"新会话不会让上下文变复杂"——对，它更干净。代价是：**它不会自动知道上次聊到哪**，除非你告诉它去哪里读。

## 2. 那"之前的待办"怎么办：写在三个地方

| 位置 | 存什么 | 谁维护 |
|---|---|---|
| `vault/路线图与待办.md` | **项目级待办总表**（做什么、做到哪、卡在哪） | 每次收尾更新 |
| `vault/02 时间线.md` | 大事记（何时做了什么决定） | 每次收尾补一行 |
| 各项目的 `TODO.md` / `docs/` | 该项目的工程待办与契约 | 项目内自己维护 |

> [!warning] 不写下来 = 一定会丢
> 会话里的"我们等会儿再做 X"、临时结论、为什么选 A 不选 B——**不落盘，下一个会话完全不知道**。

**不跨会话的东西**（要特别注意）：
- 我在会话里设的**定时提醒**（到点提醒=会话级，关掉就没了）；
- 会话目标（goal）——它是"这个会话的长期目标"，不是文件；
- 对话里的口吻、权衡过程（只有结论写下来才留下）。

## 3. 两个可以照抄的句子

**开工时**（新会话第一句，贴这段就行）：

```
先读 D:\MeineArbeit\DeltaUnlimited\vault\00 开始这里.md 和 路线图与待办.md，
再看 02 时间线.md 最后两行，然后告诉我：上次做到哪、下一步该干什么、有什么坑别踩。
```

**收尾时**（当天最后一句）：

```
把今天的进展、新踩的坑、变更的待办写回 vault（路线图与待办 + 02 时间线 + 对应笔记），
并在 路线图与待办 顶部更新"上次做到哪/下一步"两行。
```

## 4. 交接单格式（5 行，够用）

```markdown
- 上次做到：<一句话，含关键数字/提交号>
- 卡在哪：<具体现象；没有就写"无">
- 下一步：<第一条具体动作，别写"继续优化"这种>
- 别踩的坑：<链接到 坑-XXX 笔记>
- 相关文件：<路径/提交>
```

## 5. 什么时候该换新会话

- ✅ 换项目 / 换主题（比如从跑刀切到量化）；
- ✅ 隔了一天以上（旧上下文压缩后细节不可靠）；
- ✅ 当前会话开始"绕圈"、反复问同一件事（说明上下文已被压缩得不够用）；
- ❌ 同一件事的连续深挖（比如正在调一个 bug）——别换，换了要重建现场。
