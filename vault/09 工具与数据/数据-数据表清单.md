# 数据-数据表清单

> [!info] 一句话
> `data/` 下 12 个 JSON，每一个都有人读、也基本都有人写（有的人是你，有的是 `roitune` 或 GUI）；这张清单回答三个问题：**它管什么、谁在读它、改坏了会怎样**。

## 1. 先分清四类数据（决定你敢不敢手改）

| 类别 | 含义 | 手改风险 | 涉及文件 |
|---|---|---|---|
| **用户可改的配置** | 策略/开关/键位/白名单——改的是"我想怎么玩" | 低（改完 `smoke` 能过就行） | `game_ops.json`、`item_catalog.json`（条目）、`loadout_preset.json → policy`、`ai_vision.json`（`enabled`/`avoid.enforce`）、`operator_presets.json → map_operators`、`runtime.json`（`window_keyword`/`humanizer`/`session_limits`） |
| **标定结果** | 从真机截图/实测量出来的数（坐标/阈值/像素比），换机器/换分辨率/换赛季就要重标 | 中高：写错不会报错，只会在真机上等不到界面 | `runtime.json → px_per_90deg`、`screens.json`（标记与区域）、`elements.json`（坐标/模板路径）、`zones.json`、`zero_dam_points.json`、`ai_vision.json`（`roi`/`input_size`）、`operator_presets.json → layout`、`runtime.json → servo` |
| **本机个人设置** | 只跟"这台电脑上的我"有关，不入库 | 极低（删掉自动回默认） | `gui_settings.json` |
| **预留/未启用** | 结构已定、内容为空或占位，等实现 | 目前无影响，但别当真数据用 | `item_catalog.json`（`items: []`）、`loadout_preset.json`（`presets: []`）、`item_values.json`（示例 3 条） |

## 2. 总表（12 个文件）

| 文件 | 用途 | 关键字段 | 谁读它 | 改错会怎样 |
|---|---|---|---|---|
| `screens.json` | 界面识别表（17 个界面） | `markers[]`（type/template/keywords/require_all/region/region_name/threshold）、`actions`、`dismiss`、`group`、`enabled`、`note` | `ScreenDetector.Scan/Detect`；`HudStateGate`（group=match）；`ChainCommand.ValidateChain` | 认不出界面 → 链路在 `switch_screen` 打转直到熔断；认出两个 → `Alternatives` 告警但会取优选 |
| `elements.json` | 元素识别表（12 个元素） | `strategy`（coord/template/ocr/color）、`params`（x/y/template/threshold/keywords/region/region_name/rgb/tolerance/min_ratio） | `ElementClicker`（`click` 命令与 chain 的 `click_element`）、`annotate`、`ValidateChain` | 点不到 → `expect_screen` 超时 → 重试 → 软跳转人工。coord 策略写错会**直接点错位置**（有落点校验，但校验只管"到没到那个坐标"） |
| `zones.json` | 具名区域表（6 个） | `zones.<名>` = `[x,y,w,h]`（设计分辨率） | `ScreenDetector.ResolveRegion`、`ElementClicker.ResolveRegion` | 区域错 → OCR 采样到错误地方 → 命中率掉；区域不存在 → 回退全帧并告警一次 |
| `runtime.json` | 本机标定 + 全部参数总闸 | `window_keyword`、`px_per_90deg`、`poll_interval_ms`、`design_width/height`、`ocr_engine`、`humanizer`（16+10 个参数）、`servo`（8 个参数）、`session_limits` | `Program`、`ChainCommand`、`InputService`、`patrol`/`drill`、`CaptureService.LogWindowAnchor` | 窗口关键字错 → 所有命令"找不到窗口"；`px_per_90deg=0` → `turn`/`drill`/`patrol` 直接报错；humanizer 改成固定值 → 拟人化失效 |
| `game_ops.json` | 键位映射 + 复合动作 | `按键映射`（18 条）、`复合动作`（7 个，op: move_to/key/key_combo/key_down/key_up/move_hold/wait） | `CommandUtil.ResolveKey`、chain（伺服取 `move_forward`/`sprint`）、`patrol`/`drill` | 键位错 → 按了没反应（帧差验证会告诉你）；伺服会跟着按错键 |
| `zero_dam_points.json` | 零号大坝点位底库 | `spawn_points`（14）、`extract_points`（4）：`id/name/location/type/x/y/map_px` | `DataStore`（`smoke` 统计）、后续路线规划（当前无运行时消费者） | 目前只影响统计与将来的路线；改错坐标不会立刻坏事，但会误导以后的自己 |
| `item_catalog.json` | 物品库 + 拾取门槛 | `items[]`（name/ocr_keywords/type/tier/grid_w/grid_h/value/pick/note）、`min_tier_to_pick`、`extract_deadline_min` | `EconomyAgent`（目前仅单测） | 目前无运行时影响；`min_tier_to_pick` 语义是"低于此档不捡" |
| `ai_vision.json` | AI 感知配置 | `enabled`、`model`、`ep`、`runtime_threads`、`roi`、`input_size`、`min_confidence`、`filter`、`avoid`、`drift`、`log` | `AiVision`；`airecord`（JPEG 质量）、`ailabel`、`aiprobe`、`roitune`、`aieval` | `enabled=false` → 完全回退原始守卫；`roi` 错 → 模型永远看到 HUD/半空（`no_ground`）；`input_size` 与模型不符 → 会话创建失败 |
| `operator_presets.json` | 干员选择预设 | `map_operators`（地图→type/index）、`layout`（头像锚点/间距/标签区域/类型锚点） | chain 的 `pick_operator`、`click_operator` 命令、`OperatorPicker` | 未配置 → 跳过不选（保持当前干员，安全）；锚点错 → 点到别的干员或空处 |
| `loadout_preset.json` | 配装预设（预留） | `presets[]`、`policy.source`（preset/warehouse）、`policy.max_tier`（0-6） | `DataStore`（`smoke` 统计）；GUI 选项预留 | 目前无运行时影响 |
| `item_values.json` | 材料价值占位表 | `materials[]`（name/value/slots） | `DataStore`（`smoke` 统计） | 目前无运行时影响（示例数据） |
| `gui_settings.json` | 本机 GUI 设置 | `last_workflow`、`auto_mode`、`window_x/y/w/h` | `MainForm`（读写）、`DataStore.LoadGuiSettings` | 删掉/写坏 → 回默认（居中、半自动、`enter_match.json`），不影响任何自动化逻辑 |

## 3. 哪个文件会被程序**自己写**

| 文件 | 谁写 | 什么时候写 | 后果 |
|---|---|---|---|
| `gui_settings.json` | `MainForm` | 点"开始"时记工作流/模式；真正退出时记窗口位置 | 纯个人偏好 |
| `ai_vision.json` | `roitune` 保存 ROI；`AiVision.Disable()` 自动禁用 | 回车保存 / 矛盾率超限 | 会被**自动改成 `enabled: false`**——发现 AI 突然不工作时先看这里 |

其余 10 个都是"人写代码读"。所以改完一定要跑一次冒烟（见 §6）。

## 4. 逐表要点（只写容易踩的）

### screens.json

- 标记语义是"**任一命中即判定**"，不是"全部命中"（[[模块-视觉识别]] §4）；
- `require_all: true` 是防串台的唯一手段：`plaza_ready` 必须 `配装`+`出发` 同时在场，否则会被配装界面的"确认配装"骗；
- `group` 默认 `lobby`，局内界面必须显式写 `group: "match"`（否则大厅链路会扫到它，[[决策-局内界面分表group]]）；
- `dismiss` 只给"按键就能关掉"的通用弹层（现在只有 `space_continue → "space"`）；给错会让链路反复按不该按的键。

### elements.json

- `ocr` 策略的 `x/y` 是**坐标兜底**，不是主路径；主路径永远是 OCR 命中的文字中心；
- `template` 的 `threshold` 缺省 0.85；模板图放 `assets/templates/`，路径写相对仓库根；
- `coord` 策略没有任何视觉校验，是最后手段——能 OCR 就别用 coord（`wf_mode_card`、`preset_balanced_button` 是因为美术字/无文字才直点）。

### runtime.json

- `px_per_90deg = 4500` 是**这台机器 + 这套灵敏度**的标定值，换鼠标/换灵敏度必须重标（[[标定-转向灵敏度]]）；
- `poll_interval_ms = 300` 依赖"变更门"才敢这么快，别在没变更门的循环里照抄；
- `humanizer` 全部是随机范围，**禁止改成固定值**；
- `session_limits.max_minutes_per_day = 240`，`max_matches_per_day = 0`（不限局数）——这是风控红线的一部分（[[决策-会话限额与风控]]）。

### ai_vision.json

- `roi = [592,656,648,324]`、`input_size = [112,224]` 是 `roitune` 标定出来的（[[标定-可通行ROI]]）；
- `avoid.enforce = false` 是 observe-only 的总开关之一（另一个是门禁降级）；
- `drift.golden_set_dir` 指向 `assets/ai/golden`，里面有 `labels.csv` 才算金标集可用。

## 6. 改数据的安全流程

1. **备份/想清楚**：`git diff data/` 看看改了哪几行；标定类字段要记下是哪一局截的图（写进 `note`）。
2. **冒烟**：`dotnet run -- smoke` —— 能加载全部 JSON 并打印统计（元素数/按键数/物品数/点位…）。
3. **单点验证**：
   - 改 `screens.json` 标记 → `ocr` / `tplprobe` 在真机截图上验；
   - 改 `elements.json` 元素 → `annotate <元素名>` 看框画得对不对，再 `click <元素名>` 实测；
   - 改 `zones.json` → 用 `ocr --region` 对比区域内外命中率。
4. **链路级**：`chain enter_match.json`（半自动），加载期校验会先挑出"引用了不存在的元素/界面/模板"。
5. **提交**：只提交确定有效的改动；`gui_settings.json` 是 gitignore 的本机文件，不要提交。
