# K0 采集清单（上号照抄版）

> 用途：为 **K1 撤离直通**标定所需素材。**不采路线、不采点位表**（跑刀方案 §1 强制约束）——
> 只采"界面长什么样、图标长什么样、交互提示在哪"这类**感知素材**。
> 采完交给我，我负责标定 `screens.json`(match 组) / `elements.json` / 各类模板，然后把 K1 接通。

## 0. 怎么采（三种方式，按场景挑）

| 方式 | 命令 | 适合 |
|---|---|---|
| 连续录制 | `dotnet run -- airecord --map 零号大坝 --season s6` | 正常打一局，全程自动存帧（1-2s 随机 + 帧差去重），**最省事** |
| 定点截屏 | `dotnet run -- capture 三角洲行动 k0_xxx` | 需要"就这一张、要清晰"的关键画面 |
| 裁剪模板 | `dotnet run -- crop <x> <y> <w> <h> <源图> assets/templates/xxx.png` | 从已有截图裁出模板小图（K0 之后我来做，你也可以先粗裁） |

产物统一放 `screenshots/k0/`（已在 gitignore，本地留存）；`airecord` 的产物在 `ai-training/datasets/record/full/`。

> ⚠️ 游戏必须**窗口化**（独占全屏抓不到画面）；采之前先关掉旧的 ailabel/roitune/GUI（会锁 exe）。

## 1. 落地与 HUD（判断"已经进局了"）

| # | 采什么 | 为什么 |
|---|---|---|
| 1.1 | 干员选择之后 → 落地之前的**每一个画面**（部署确认/出生点地图/加载/购买，若有） | 决定 chain 在局内的第一段怎么写 |
| 1.2 | 出生点选择界面（若有）+ 你固定选的那个点 | 能固定就标定，不能就人工点 |
| 1.3 | **落地后裸 HUD**：朝向三个方向各 1 张（左/正前/右） | 找"永不消失"的锚点（准星/小地图/血条）做"已落地"判据 |
| 1.4 | 低血/红屏残留/开小地图时的 HUD 各 1 张 | 区分"正常 HUD"与"异常状态" |

## 2. 地图屏（撤离标定的核心）

| # | 采什么 | 为什么 |
|---|---|---|
| 2.1 | **打开地图的按键** + 地图全貌 1 张 | 标定地图屏识别 + 打开方式 |
| 2.2 | 撤离点图标：**左侧固定点 / 右侧固定点 / 随机开放点** 各 1 张（清晰特写 + 全屏各一） | K1 靠模板识别撤离点图标 |
| 2.3 | 撤离点图标的**三种状态**：可撤离（亮）/ 未开放（灰）/ 锁定 | 判断"现在能不能去" |
| 2.4 | **标点操作全过程**：点图标 → 确认（右键？左键？）→ 地图上出现标记 → 关闭地图 | 这是 K1 唯一需要点击的环节，要把交互摸清 |
| 2.5 | 关闭地图后的画面（标记已生效） | 确认标点成功 |
| 2.6 | 地图屏上的**全部图标**（你说的全量提取）：撤离点/物资点/载具/队友/自己位置…每个 1 张特写 | 一次性把地图图标库建起来（可用 VLM 辅助框选 + tplprobe 验证） |

## 8. 采集节奏建议

- **一局录像 + 关键画面定点截屏**即可覆盖 1-4 项（约 20-30 分钟）；
- 5-7 项可以下一局顺手补齐；
- 采完把 `screenshots/k0/` 目录名和 `record/full` 的批次告诉我，我开始标定。

1. `screens.json` 加 match 组界面（已落地/HUD/地图屏/拾取面板/背包/死亡/结算变体）；
