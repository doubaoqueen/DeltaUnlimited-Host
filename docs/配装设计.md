# 自动配装设计（制式套装方案 v1）

状态：**设计定稿，链路已接通**。界面/元素/链路全部入库；preset_select 标记与均衡卡消耗按钮均经真机截图验证（`screenshots/captured/capture_20260922_184254.png`）；待真机实测。

## 方案选型

用游戏内置「制式套装」预设实现自动配装，替代全槽位逐一标注方案：

- 流程：配装界面点「制式套装」卡片 → 装备预设界面选卡 → 自动回配装界面 → 点「确认配装」。
- 成本：**确认配装时才真正消耗制式装备券**（新兵券 ≈ 5 万哈夫币/局）；确认前随时可点 X 取消、不扣券 —— 天然安全，适合迭代测试。
- 预算上限字段 `budget_cap` 已在 `data/loadout_preset.json` 预留（schema 1，presets 空）；将来想换方案只改数据不动链路。

## 真机流程（2026-09-22 标定，见 docs/配装场景问题清单.md）

1. **配装界面**点「制式套装」卡片（(1660,880)-(1730,898)，美术字，模板已裁 `standard_set_card.png`）→ 进入**装备预设界面**。
2. **装备预设界面**：
   - 顶部 5 个方向标签：新兵/标准/精锐/特种/定制，各带 [卡片数量]；**悬停=方块底部变绿，点击选中=整体边框变绿**；点击切换推荐列表。零号大坝-常规模式下默认即「新兵」→ **MVP 不点标签**。⚠️ 实测（区域 OCR）：五个标签文字均可读。
   - 中部 3 张预设卡：**均衡/生存/火力** —— ⚠️ 实测为美术字，全帧/区域 OCR 均读不出（"户外全刀到"类乱码），**界面识别不能依赖卡名**。每卡底部"消耗券"按钮：无 OCR 文字（区域仅读到券数"1"），**坐标直点**；点击直接回配装界面，无二次确认。均衡卡消耗按钮点击区已标定：**(266,902)-(567,965)**，中心 (416,933)。
   - 右上额度标识：4 张券图（新兵/标准/精锐/特种制式装备券；定制券已取消），计数可读（如"拥有：9/10 3/5 1/5"）。
   - **失败分支**：点卡后若不符合地图/等级/模式规则，**顶部提示约 1.5 秒**："xx制式装备券 无法进入零号大坝-常规"（券名黄色、后半白），画面停留在预设界面。
3. **回到配装界面**：底部出现预设弹框（X = 取消当前预设装备）。**弹框不自动消失、不挡「确认配装」按钮** → 不点 X，直接点确认配装。
4. 点「确认配装」→ 真正扣券 →（入局提醒）→ 出发。

## 识别与链路设计

- **新界面 `preset_select`**（screens.json 已入库）：主标记 = 顶部标签带 **require_all(新兵+精锐+特种)** region [120,40,640,70]（真机截图验证；卡名为美术字不可用作标记）。
- **元素**：
  - `standard_set_card`（elements.json 已入库）：template 主定位 + 坐标兜底 (1695,889)。
  - `preset_balanced_button`（均衡卡消耗按钮）：coord (416,933) ✅（点击区 (266,902)-(567,965)，用户标定）。生存/火力卡按钮待 GUI 选项时再标定。
- **成败判断（难点 2 对策）**：不追 1.5s 的瞬态提示，用**状态迁移**判断——点消耗按钮后 2.5s 内识别"回到配装界面"=成功；超时仍在预设界面=失败 → 走失败分支。
- **链路插入点**（enter_match.json v6，已实现）：
  ```
  loadout 分支 → apply_standard_set：点 standard_set_card (expect preset_select, 失败→preset_entry_fail)
  preset_select 分支 → preset_apply：点 preset_balanced_button (expect loadout, 2.5s, 不重试防双击, 失败→preset_apply_fail)
  preset_apply_fail → detect → loadout?→confirm_loadout（慢过渡兜底）
                              → preset_select?→preset_apply_manual（人工：可能券不足/不符合规则）
                              → 其他→detect_start
  成功后 → confirm_loadout（既有：点确认配装→真正扣券→入局提醒/出发）
  ```
- **额度图标 4 张券**：识别用途（可选优化），暂不实现；优先级低于链路打通。

## GUI 选项预留

三套预设（均衡/生存/火力）后续在 GUI 中做成玩家可选（下拉/单选），链路只认数据：

- 数据槽：`data/loadout_preset.json` 的 presets（现为空，schema 已建）；
- 实现时给每张卡补充消耗按钮坐标（生存/火力卡待标定），GUI 选择写入 presets，链路读该值点击对应按钮。
