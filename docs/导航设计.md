# 导航设计 v1：地图标点 + HUD 标记伺服

> 目标：烽火地带"搜打撤"跑刀流程的寻路与撤离，不依赖预设路线、不依赖出生点。

## 1. 调研结论（2026-09）

| 路线 | 代表 | 结论 |
|---|---|---|
| 经典 CV + 图搜索 | BetterGI [地图追踪](https://www.bettergi.com/feats/autos/pathing.html)、[Game-Map-Tracker](https://github.com/761696148/Game-Map-Tracker)、MMO 找色+A星 | 主航道，被长期验证；本项目的备选路线 |
| 深度学习（YOLO/ONNX） | 目标检测直连世界物体 | 有力但标注成本高；后置为"避战层" |
| **游戏辅助导航（本项目选定）** | 地图标点 → 跟随 HUD 标记 | 让游戏引擎自己算路径，工作量最低、鲁棒性最好 |

## 2. 核心架构

```
搜刮/撤离目标选择（EconomyAgent，后期）
        ↓
① 开地图（M）→ 模板匹配定位撤离点图标（地图屏布局固定，屏幕坐标 = 常量）
        ↓
② 点击图标位置 → 游戏标点（用户已确认：烽火地带支持地图标点）
        ↓
③ 关地图 → HUD 出现导航标记（方向/距离由游戏实时绘制）
        ↓
④ 视觉伺服跟随标记：
   - 标记偏左/右 → 左/右转（px_per_90deg 标定已有）
   - 标记接近屏幕中心 → 冲刺前进
   - 贴墙/横移 → patrol 双守卫转向（已验证）
        ↓
⑤ 到达（标记距离归零/到达提示）→ F 交互 → 等待撤离倒计时 → 结算识别
```

关键点：**地图屏固定布局 + 游戏内标点 = 绝对定位与 A* 全部外包给游戏引擎**。
不依赖：出生点、数字图、坐标 OCR、YOLO。

## 3. 为什么不是其他方案

- **预设路线**：伪随机出生 × 多图 × 多变目标 → 路线表爆炸。否决。
- **自研 A\*（BetterGI 同款）**：需要数字道路图 + 地图屏玩家定位（无坐标显示 → 只能检测玩家箭头，风险高）。保留为**标点功能失效时的退路**。
- **YOLO 全感知**：标注成本高，且本场景不需要"理解 3D 世界"——UI 已提供全部导航信息。后置为避战/世界物体识别层。

## 4. 待采集数据（下一步）

1. 地图屏截图（含撤离点图标）→ 标出撤离点图标的屏幕坐标常量（每图一次）
2. 标点后 HUD 导航标记截图 ×3-5（不同距离/角度）→ 裁模板 + 定阈值
3. 到达撤离点时的提示截图 → 到达判定（模板/OCR）
4. 撤离倒计时界面截图 → 等待判定

## 5. 里程碑

| 阶段 | 内容 | 验收 |
|---|---|---|
| N1 | 视觉伺服原语（转向跟随屏幕标记） | 靶场固定参照物：转→正对 |
| N2 | 地图标点动作（开图→点撤离点→关图） | 标点成功，HUD 出现标记 |
| N3 | 标记跟随闭环（伺服装配双守卫） | 从出生点走到撤离点（人盯） |
| N4 | 撤离闭环（F 交互→倒计时→结算→回大厅） | 完整一局半自动跑通 |
| N5（可选） | YOLO 避战层 | 看见敌人绕行 |

## 6. 风险与退路

- HUD 标记样式随距离/条件变化 → 多模板 + 阈值校准；失效则退回 BetterGI 式图搜索路线。
- 撤离点条件开放（付费/倒计时）→ 先只标默认开放点；EconomyAgent 阶段再处理。
- 合规红线不变：低频、人工盯、风险自担（见 docs/项目大纲.md §7）。
