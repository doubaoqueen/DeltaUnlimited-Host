# 跑刀工程提案 v0.1：对局内自动化的技术解决模式（我的草案）

状态：**方案稿（未动代码）**。配套 `docs/跑刀方案.md`（玩法拆解/分期/风控，用户 v1）——本文只回答"用什么技术手段、怎么实现"。所有结论待与用户讨论后定稿。

---

## 0. 一句话总览

对局内自动化 = **一个 5-10Hz 伺服循环**（移动/感知/危险检测）+ **既有 2Hz chain 引擎**（界面流转/决策）+ **一张对局内识别分表** + **一个纯函数决策层**（可单测）。

发现机制不背路线表：核心感知信号是**游戏自带的"交互提示"**（准星旁出现键位+名称提示 = 游戏声明"这里可交互"）——这是免世界理解、误报最低的现场信号，与用户"禁止预设路线"的决策天然契合。

## 1. 双引擎怎么接（工程接口，跑刀方案 §3 的落地）

- chain 新增两个**薄 op**：`follow_marker`（撤离伺服的壳）与 `loot_roam`（搜刮伺服的壳）。op 内部**同步阻塞**跑伺服循环，返回 `ServoResult`（枚举：成功/超时/危险/急停/卡死），chain 按返回值走 JSON 分支——引擎保持纯界面流转，伺服只做调用。
- `ServoLoop.Run(context, config)`：context 提供捕获/输入/感知三件套；**每个周期必查 `CommandUtil.StopRequested`**（复用 G2 协作式急停，GUI 急停按钮/暂停面板全程有效）。
- **线程模型：伺服跑在链路线程内同步执行**，不另起线程——避免并发输入/GUI 复杂度；GUI 不卡（链路线程本来就是后台 Task）。
- 周期预算（每周期允许干什么，防止超预算）：
  - 廉价档（每周期可算）：全帧截取 30-50ms + ROI 模板匹配 5-10ms + 颜色统计 1-2ms + FrameDiff 1-2ms；
  - 中等档（按需，~2Hz）：区域 OCR 150-250ms（只在需要读字时）；
  - 昂贵档（事件触发）：全帧 OCR/全图搜索（仅未知界面 dump、标定诊断）。

## 2. 感知层：信号分三档（按成本与可靠性）

| 档 | 信号 | 技术 | 判定与防抖 |
|---|---|---|---|
| 廉价 | 受击红屏 | 屏幕边缘 ROI 红色像素占比（零训练） | 阈值带随机余量 + 连续 N 帧确认窗口，防误触；确认 → AbortToPause 人工接管 |
| 廉价 | 卡墙/低效移动 | FrameDiff 双守卫（复用 patrol 已验证） | 贴墙=连续低变化；横移=长时间无高速样本 |
| 廉价 | 可交互提示图标 | 准星附近 ROI 模板（键位图标/提示框） | 命中即触发"走近"子流程 |
| 廉价 | 容器高光/物资光柱 | HSV 颜色统计（金/紫光柱）起步，YOLO 留后期 | 颜色统计带现场标定容差（显卡色彩/亮度设置会偏色） |
| 中等 | 交互提示文字/距离数字/拾取面板物品名 | 区域 OCR（≤1700px 分段，吃 1.5x 放大——干员标签已验证该手法） | 严格层词匹配才行动 |
| 中等 | HUD 导航标记 | ROI 多模板 + 屏幕位置 | 标记 x 偏移 → 伺服转向；到达判定见 §3 |
| 昂贵 | 未知界面 | 全帧 OCR dump + mark_unknown 留证 | 局内兜底 = 停住+人工（**不是按 Tab**，见跑刀方案 §3 分表理由） |

每个信号落数据表时固定五要素：检测区域、阈值、防抖窗口、失败回落、真机出处（沿用 screens.json 的实测注释文化）。

## 3. 伺服控制（核心工程点）

- **标记跟随 = 比例控制 + 死区 + 随机抖动**：`turn = clamp(k * (markerX - centerX) + noise, -maxTurn, maxTurn)`；k、死区、noise 全部**随机范围**（项目铁律）；每周期最大动作量钳制（防失控）。
- **到达判定**（两条路，K0 截图后定）：距离数字可 OCR → 数字阈值；不可 → 模板尺寸阈值（标记变大=近了）。
- **动作约束**：伺服周期内只允许"转向 + 冲刺 + 停"，**禁止任何点击**；需要点击（开门/撤离 F）时退回 chain 层走 `ClickAt` 安全网——点击永远有落点校验，移动永远有急停检查，两类风险不混在一起。
- 输出兜底：每个动作块 try/finally `ReleaseAllHeldKeys`；周期开始先查急停。

## 4. 数据契约（新增/变更清单）

| 文件 | 变更 |
|---|---|
| `data/screens.json` | 加 `group` 字段（"lobby"/"match"）——链局内只扫 match 组（省一半 OCR；局内 unknown 兜底语义与大厅不同） |

| `data/zero_dam_points.json` | 按 2026-09-26 用户决定：**废弃 loot_points**，只留撤离点锚点 |
| `tests/fixtures/` | K0 采集截图进 fixtures（已 gitignore，本地回归素材） |

## 5. 决策层 = 纯函数（可单测，不碰 IO）

`EconomyAgent` 全静态纯函数：`ShouldPick(itemName, quality, backpackState)`、`ShouldDiscard(...)`、`TimeToExtract(...)`。白名单起步、不做价值函数（与用户方案 §6 一致）。每个规则一行 JSON 数据 + 一个 xUnit 钉住。

## 6. 测试策略

- 伺服控制器（P 控制+死区+噪声钳制+最大动作量）——纯函数单测；
- 感知信号用 fixtures 帧回归（记录帧 → 期望输出，tests/fixtures 不进 git）；
- 危险检测阈值随机化的边界测试（红屏确认窗口）；
- 每次链路/伺服改动：99+ 全绿 + 真机半自动验收，缺一不上线。

## 7. 风险清单（我的诚实排序，从最致命到最次要）

1. **K0 标定质量决定一切**：HUD 锚点/导航标记/交互提示的截图质量与覆盖度不够，后面全是空中楼阁；
2. **地图屏"标点"交互未知**（点哪里？确认键？退出键？）——跑刀方案开放问题 4/5，上号才能定；
3. **导航标记形态未知**（箭头/菱形？距离数字可读否？）——决定"到达判定"的实现难度；
4. **交互提示小字 OCR 可靠性**——若不稳，退回"图标模板主 + OCR 辅"；
5. **窗口截图的颜色偏色**（显卡色彩/亮度设置影响品质色判定）——色统计必须现场标定容差；
6. **风控**：局内高频移动是最敏感行为——会话限额 + 全参数随机 + 人盯（与用户方案 §9 一致，从第一天就写进 servo 段）；
7. **伺服参数失控**：每周期最大动作量钳制 + 急停贯穿是最后防线。

## 8. 里程碑（工程视角，对齐跑刀方案的 K0-K6）

| 工程阶段 | 内容 | 验收 |
|---|---|---|
| S0（≈K0） | ServoLoop 骨架 + 控制器/决策层单测 + fixtures 管线 + screens 分表 | 单测绿；K0 素材入库 |
| S1（≈K1） | `follow_marker` op 接通 chain + 撤离直通 | 落地→标点→跟随→撤离→结算→回大厅，空手半自动 |
| S2（≈K2） | `loot_roam` op + 交互提示感知 + 拾取面板白名单 | 地图内自动发现并捡到背包+白名单物 |
| S3（≈K3/K4） | 背包管理 + 危险/死亡兜底 | 背包满自动丢；挨枪可靠暂停；死局正常回大厅 |
| S4（≈K5/K6） | 节奏打磨 + 会话限额 + 经济闭环 | 全自动（人盯）连跑 3 局收益为正 |

与用户方案的节奏一致：**K1 跑通前不写任何搜刮代码**。

## 9. 待拍板的技术分叉点（讨论时逐条过）

1. 分表方式：screens.json 加 `group` 字段（我倾向，校验逻辑改动最小）vs 独立 screens_match.json；
2. 伺服频率：8Hz 起步（我建议，标定后可调）；
3. 交互提示检测：图标模板主 + OCR 辅（我建议，K0 截图后再定）；
4. 撤离"到达判定"：距离数字可 OCR 则数字阈值，否则模板尺寸阈值；
5. 会话限额默认值（每日局数/时长）——需要你定数；
6. GUI 是否需要"对局模式"状态页（伺服心跳/危险告警/剩余限额显示）——建议 S1 后加。
