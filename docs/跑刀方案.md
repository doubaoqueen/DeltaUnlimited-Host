# 跑刀方案 v1：对局内自动化总体设计

状态：**方案稿**（未动代码）。继承 `docs/导航设计.md`（标点+HUD 伺服，已选定不推翻）、`docs/仓库交互手册.md`（交互机制存档）、`docs/配装设计.md`（进场链路已通到干员选择）。本文回答：从干员选择之后到回大厅的整段"搜打撤"怎么自动化。

## 1. 定位与红线（继承 + 对局内新增一条）

- 继承：**不包含任何战斗/击杀/瞄准辅助**；只截图+键鼠的"看得见的自动化"；拟人化、低频、人工在场。
- **对局内新增：遇险即停给人。** 局内战斗无法也绝不应自动化——检测到受击/危险信号 → 暂停链路人工接管（不是自动逃跑：交火中跑路本身是战斗行为）。这是设计边界，不是缺陷。
- **强制约束（2026-09-26 用户定）：全流程禁止预设路线。** 搜/打/撤三环节都不背路线表、不背物资点位表：撤离靠"地图标点+游戏引擎算路"（导航设计 v1 既有选型），搜刮靠"现场感知发现"（见 §6）。`zero_dam_points.json → loot_points` 点位表方案**废弃**，生产链路不得引用。
- 跑刀裸装死亡成本 ≈ 0（只有安全箱保底），死亡是**正常终态**而非链路失败——方案按"死了就回大厅再来"设计，不追求每局必成。

## 2. 玩法拆解 → 自动化映射

| 游戏环节 | 人的玩法 | 自动化做什么 | 难度 | 依据 |
|---|---|---|---|---|
| 干员选择 | 选干员 | ✅ 已实现（pick_operator，未配置则等倒计时） | 已通 | enter_match v7 |
| 部署/出生点 | 选出生点、（可买装备） | 跳过购买；出生点选择**暂人工**（或固定点标定） | 低 | 待标定 |
| 落地开局 | 跑向第一个物资点 | 识别"已落地"（HUD 出现）→ 进入搜刮/撤离流程 | 中 | HUD 标定 |
| **搜刮** | 找容器/尸体→F 交互→拾取面板筛选 | **现场感知驱动**：随机漫游 → 捕捉游戏交互提示/容器高光 → 走近交互 → 拾取面板 OCR+品质色 → 查 item_catalog.pick 决策 | **高** | 本方案核心 |
| 背包管理 | 满了丢低价值 | 背包界面：按品质/白名单丢弃；先拾背包扩容 | 中 | 仓库交互手册 |
| **撤离** | 开地图标点撤离点→跟随 HUD 标记→F→倒计时 | ✅ 导航设计 v1 全套（标点外包给游戏引擎） | 中 | 导航设计 N1-N4 |
| 死亡/观战 | 放弃/等结算 | 识别死亡界面 → 结算 → 回大厅（正常终态） | 低 | 待标定 |
| 结算回大厅 | 空格跳过 | ✅ settlement/space_continue 已有 | 已通 | screens.json |
| 卖货回存 | 商人出售/仓库整理 | ❌ 本期不做（人工），衔接仓库交互手册后续 | — | 排 K6 之后 |

## 3. 执行架构：双引擎，各管一段

```
chain 引擎（2Hz 界面流转，进场已验证的模式）
  管：部署确认 → 落地识别 → 决定"搜刮 or 直撤" → 各菜单界面流转 → 结算回大厅
        │ 新增 op（薄壳，只做调用不做逻辑）
        ▼
伺服循环（patrol 式专用紧循环，5-10Hz）
  管：HUD 导航标记跟随（转向/冲刺/贴墙双守卫）、随机漫游与交互扫描
  复用：px_per_90deg 标定、patrol 双守卫、拟人化输入、FrameDiff
```

- **为什么分两层**：chain 的 2Hz 轮询撑不起移动伺服；patrol 已验证"专用循环管移动"的形态。chain 只加 `follow_marker`（撤离导航：跟随 HUD 标记）/ `loot_roam`（搜刮：随机漫游+交互扫描）两个 op（内部跑紧循环，返回结果继续走链路），引擎保持纯界面流转。
- **对局内识别分表（关键）**：对局内界面（地图/背包/拾取面板/死亡/结算）与大厅界面**分开一张表**（screens.json 加 `group` 字段或独立 screens_match.json）。原因：① 链路只扫本组界面，省一半 OCR；② **对局内 unknown ≠ 按 Tab**——v7 的 `unknown_tab` 兜底是特勤处专属（局内按 Tab 是计分板/无效），局内 unknown 的兜底是"停住等待/暂停人工"，**这是进场链路不能直接复用到局内的最重要一条**。

## 4. 对局内状态机

```
[chain] 干员选择(已通) → 部署/出生点(人工或标定) → 落地识别(HUD出现)
   │
   ├─ 模式A 撤离直通（K1 验收形态）：标点撤离点 → [伺服]跟随 → F → 倒计时 → 撤离成功
   │
   └─ 模式B 搜刮循环（K2+）：
        [伺服] loot_roam 随机漫游 → 检测交互提示/容器高光 → 走近交互 → [chain] 拾取面板 → pick 决策 → 关面板
          ↑                                      │ 背包满 → [chain] 背包界面 → 丢弃
          └────── 继续漫游 ←──────────────────────┘
        退出条件：背包满且无可丢 / 时间窗（撤离倒计时前 N 分钟，攻略共识：最后 2 分钟不捡边缘杂物）
   │
   ├─ 危险检测（伺服循环内并行）：受击红屏/血条骤降 → AbortToPause（人工接管）
   ├─ 死亡分支：死亡界面 → 观战跳过 → 结算 → 回大厅（正常终态）
   └─ 超时兜底：局内单状态超时 → mark_unknown 留证 → 人工
```

## 6. 决策层：EconomyAgent 最小版

- **发现机制（"禁止预设路线"的落地）**：不背点位表。拾取目标由**现场感知**发现：随机漫游（继承 patrol 移动原语+双守卫，方向/停留全程随机化）→ 交互提示（主信号）/容器高光（辅）→ 走近 → OCR 提示词/物品名 → 白名单决策。穿门（门本身也是交互提示）自然扩大房间覆盖——像人一样进屋拾荒，而非背地图跑路线。

- **白名单起步，不做价值函数**：拾取决策 = `item_catalog.pick=true` 的白名单匹配（OCR 命中即捡），其余跳过。仓库手册已预留 `pick` 字段，item_catalog 目前空表——**起步先录 20-30 种零号大坝常见材料/背包/胸挂**（增量录入：打游戏看到什么录什么）。
- 背包/胸挂**永远优先捡**（扩容优先级最高）；药品按白名单。
- 丢弃规则：品质 ≤ 绿 且 非白名单 → 满--时丢；数值价值决策（value 字段）等 catalog 积累够再做，防止过早优化。
- 撤离时机：全局时间窗触发（对局剩余时间 OCR 或局内计时标定，起步用"固定搜刮时长 + 人工兜底"）。

## 9. 风控与安全对策（对局内强化）

- **对局内连续移动是风控最敏感区**：伺服参数全部随机化（速度/转向幅度/停顿节奏/漫游方向与停留）——项目铁律已有，伺服循环从第一天就按此写。
- **会话限额**：每日局数/时长上限（GUI 配置项），到限自动停——防止"挂机一整天"这种最容易被风控也最违反初衷的用法。
- **人必须在场**：K1-K5 全部"人盯"形态；GUI 已有急停/暂停面板，正好是人工接管入口。
- **低频**：跑刀自动化单局节奏远慢于真人高手是正常的，不追求极限速度。
- 合规红线与风险自担声明见 `docs/项目大纲.md §1/§7`，不变。

## 10. 开放问题（下次上号确认，风格同配装场景问题清单）

1. 干员选择之后到落地之前到底有几屏？（部署确认/出生点地图/购买/加载）——决定 chain 在局内的第一段怎么写。
2. 出生点能否固定选同一个（如靠近某个撤离点/物资点）？能固定就标定，不能就人工点。
3. 落地后 HUD 有哪些元素永不消失（做"已落地"锚点）？准星/小地图/血条位置坐标。
4. 地图屏上撤离点图标长什么样？固定撤离点与随机开放点如何区分（亮/灰/锁）？
5. 标点后 HUD 导航标记的形态（箭头/菱形/距离数字）？距离数字是否可 OCR（可读则"到达判定"简单得多）。
6. 撤离是"站进圈自动倒计时"还是需要 F 激活？两种都可能，实测定。
7. 拾取面板：物品名是否 OCR 可读？格子品质色是否明显？F 拾取与面板拾取的交互差异？
8. 死亡后是直接结算还是先进观战？放弃按钮位置。
9. 局内"取消匹配/退出对局"之类的逃生口在哪（链路卡死时的人工退出路径）？
