## 1. 五点自评裁决

| # | 自评 | 裁决 | 修正与拓展性 |
|---|---|---|---|
| 1 | 放弃 ComfyUI 式 GUI，工作流模式不适合目的性固定的项目 | ✅ 正确 | 精确表述：放弃的是**节点图执行引擎**，保留的是**数据驱动工作流**（chain JSON + 数据表）。本项目唯一保留的"图"是导航拓扑图（P4）。拓展性：chain（简单流程）→ C# 任务类（复杂逻辑）→ 脚本层（用户编辑，远期），表达力三级递增，无损失 |
| 2 | 漏掉了游戏社区参考，未能将"开源"攻略写入工程 | ✅ 重要缺口，但需划界 | 纳入的是社区**知识**（跑刀路线、点位、物价 = 事实数据，走数据管线）；**不纳入**社区"三角洲辅助类项目"作代码参考——多数含战斗/透视功能，越过红线。数据管线要解决三件事：时效性（交易行价格波动）、来源记录（provenance 字段）、许可（事实数值可用，整图/整文复制需授权） |
| 3 | 技术未落地，边做边学，没学过游戏脚本开发思想，一些技术选择有问题 | ⚠️ 半对，自我批评过头 | 已有选择大多**正确**：数据表驱动、设计分辨率归一化、拟人化、急停、帧差探针——这些恰好是成熟项目（BetterGI/MAA）的标准做法。真正的教训不是"选错了"，而是"写引擎前没先读别人的答案"。补课路径见 §9 |
| 4 | 兜底缺失；截图由 BitBlt 兜底，文字识别用 OCR 做主力没兜底 | ⚠️ 概念需纠正 | 现状 BitBlt **不是兜底，是唯一实现**；正确目标是 WGC 主 + BitBlt 兜。OCR 做主力方向正确，其兜底 = 多引擎（Windows OCR ↔ PaddleOCR）+ 关键关卡模板备份 + 未知界面人工 pause。**"兜底"应升级为全层设计原则**：每个能力必须有 主方案→兜底→最终人工出口 三级（§3） |
| 5 | 图片实时分析完全没做，性能未考虑 | ✅ 正确，但注意阶段 | 进场链路（0.8s 轮询）**不需要**实时分析；实时管线是触发器宿主（P2）和 HUD 伺服（P4-N1）的前置。性能原则：先插桩测量（耗时日志），后优化（§8） |

## 3. 降级链设计表（"兜底"的正式化：每能力三级）

| 能力 | 主方案 | 兜底 | 最终出口（必须有人工路径） |
|---|---|---|---|
| 画面采集 | WGC（P3 起） | BitBlt | 提示改窗口化/无边框 |
| 界面识别 | OCR 关键词标记 | 模板 / 颜色占比 | 未知界面 → pause 人工 |
| 按钮定位与点击 | OCR 找文字中心（检测即点击，须严格确认层命中） | 模板匹配中心（模板入库分发）→ coord 坐标表 | detect 诊断 + 人工 |
| 文字识别引擎 | Windows.Media.Ocr | Sdcb.PaddleOCR（游戏字体） | 关键关卡模板备份 |
| 自定位（导航） | 地图屏玩家箭头检测 | ORB 地标库（仅届时实现） | 重开地图/人工 |
| 寻路 | 拓扑图全局 + HUD 伺服局部 | 图引导转向（卡住朝下一节点转） | 双守卫巡逻 + 人工 |
| 动作生效验证 | expect_screen 轮询 | 帧差（InputProbe） | 证据帧 + 中止 |
| 链路异常 | 超时重试 | jump 分支恢复 | pause 人工兜底 |

原则：**最终出口必须通向人**（半自动模式天然满足）。任何新能力先补齐这一行再开发。

## 5. 技术清单（按层，"所需功能→所需技术"）

### 采集层
- Windows.Graphics.Capture：Win10 1903+；TFM 需 `net10.0-windows10.0.19041`；常驻帧流（专用线程 + **latest-wins 丢帧**策略：处理慢就丢旧帧，永远处理最新帧）；Win11 可申请无边框采集（IsBorderRequired）
- BitBlt 兜底：现有实现；限制（不能截独占全屏、每次置顶 +250ms 侵入性）使其只配做备份
- DXGI Desktop Duplication：备选，截全屏（含游戏之外的画面），暂不引入

### 识别层
- `IOcrEngine` 抽象 + 双实现：Windows.Media.Ocr（零依赖，先接）/ Sdcb.PaddleOCR 或 RapidOcrNet（游戏艺术字体，后补）；启动时检测 zh-Hans 识别语言包（Windows OCR 无中文包时静默返回空结果，必须显式报错，diagnose 检查项）
- OCR 预处理（必做项，非可选）：灰度 → 深底浅字反色（Windows OCR 对浅底深字敏感，反色常使艺术字识别翻盘）→ 二值化 → 小字体放大 → 按 region 裁剪（降开销 + 提精度）
- **OCR 两级匹配（ADR #11）**：宽松候选层（关键词任 1-2 字命中 = 疑似，仅供 diagnose 报告与界面识别辅助证据，单独不构成命中、更不得触发点击）→ 严格确认层（完整关键词/正则命中）；误召回可容忍、误点击不可容忍
- **区域两级（ADR #12）**：命名区域库（zone_bottom_right / zone_top_center 等 UI 惯例区，数据表按名引用）+ 未知界面全帧 OCR（仅限 2Hz 链路轮询，触发器/HUD 伺服禁全帧）；全帧命中的包围盒回填收紧 region（同 annotate→回填 coord 的既有循环）
- 模板匹配（NCC/CCoeffNormed）失效条件：换皮、位移、光照剧变 → **只用于纯图标**（撤离点标记等无文字元素）
- 颜色占比策略（color）：加载屏/黑屏/血条类判定，零图片依赖
- ORB 特征匹配：**仅**导航定位兜底（ILocalizer 第二实现），不进识别主链
- 正则/关键词匹配 OCR 结果（学 MAA 的 expected 语义，比"包含"更精确）

### 输入层
- SendInput 拟人化（已有，保持）；**管理员同权**：游戏若以管理员运行，本程序必须同等提权否则输入被拒
- 输入队列串行化（P2）：所有键鼠动作过单队列，杜绝触发器与任务并发打架
- 键位漂移：游戏改键后 game_ops.json 失配——加"改键检测"诊断（P1 diagnose 项）

### 任务层（P2 核心）
- 触发器（帧驱动，随采集常驻）：`ITrigger.OnFrame(frame, ctx)`，每触发器自带节流
- 独立任务（步骤驱动，互斥槽）：`TaskBase.RunAsync(ctx, ct)`，chain 包成 ChainTask
- 全局 CancellationToken + 急停事件（现 InstallEmergencyStop 升级）；异常恢复靠**重入**：任何步骤可从"当前界面 detect"重新定位到链路安全点

### 导航层（P4）
- 拓扑图 JSON（节点/边/热区权重）+ Dijkstra；ILocalizer（箭头检测主 / ORB 兜底）；HUD 伺服（纯模板，15-30Hz，无 OCR）；卡死检测 v2（转向历史记忆，发现绕圈→重规划）
- **前置：两个 10 分钟游戏内实验**（决定架构分支）：① 地图能否标任意点（非仅撤离图标）② 地图屏玩家箭头是否稳定显示

### 数据层（P1）
- 加载期交叉校验：workflow 引用的 screen/element 必须存在且 markers 非空（把 4 分钟超时变 1 秒报错）
- schema_version 迁移策略（有版本号、无迁移器——补一个"版本不符即报错并给出升级说明"的最小方案）
- provenance：每张数据表加 `来源/采集日期` 元字段；item_values 市场价波动 → 定义刷新周期与人工确认流程

### 安全层（P5，红线不变：无战斗/无内存读写/低频/人工可介入）
- 会话限额（每日时长/次数）；操作节奏预算与随机化（**消灭代码里所有固定 sleep**，全部走 humanizer 参数）
- 异常中止：连续识别失败/状态不明 N 次 → 停机并留证据，不硬撑

### 可观测层
- 耗时插桩（capture/detect/ocr 各段毫秒，进日志）；识别置信度历史
- 环形证据帧缓冲（最近 N 帧常驻内存，失败时落盘）
- `diagnose` 命令（P1）：对当前实况逐个跑 elements/screens 全量识别，报告哪些失效——**每次游戏更新后跑一遍**，这就是"防改版"的运营答案

## 6. 盲区清单（本轮评审新增，此前未考虑）

| # | 盲区 | 风险 | 对策（归属阶段） |
|---|---|---|---|
| 1 | 步骤幂等与重入：click 失败重试可能双击 | 状态错乱 | 每步从 detect 恢复的设计约定（P0 约定、P2 落实） |
| 2 | 改版回归：无"补丁后体检"机制 | 全链路静默失效 | diagnose 命令（P1） |
| 3 | 风控层：限额/随机化散在文档未成层 | 封号风险叠加 | 安全层独立（P5），固定 sleep 先清理 |
| 4 | 数据时效：物价/点位无更新流程 | 收益决策失真 | 社区数据管线 + provenance（P1） |
| 5 | 回放测试：视觉改动只能上游戏验证 | 迭代慢 | 帧序列回放回归（P5；素材 = 压缩 fixture） |
| 6 | 窗口句柄漂移：游戏重启/掉线重连 | host 失联 | 窗口监视触发器：句柄失效→重找→失败报人（P2） |
| 7 | 异常态界面：断线弹窗/更新公告/维护提示 | 链路卡死 | 全部做成触发器（公告跳过是第一个，P2） |

| 10 | 热键冲突（急停键被游戏占用） | 急停失效 | 可配置急停键 + 启动时探测冲突（P2） |
| 11 | 发布形态：config 与仓库数据未分离 | 用户机覆盖错数据 | user/ 本机配置目录（机器标定不入库）（P6 前） |
| 12 | 许可证纪律：GPL/AGPL 传染 | 开源合规风险 | §4 纪律列，引入任何代码前查许可 |
| 13 | LLM/Agent 层去留悬而未决 | 注意力分散 | 显式决定：**保持空壳搁置**（决策记录 #7），跑通全流程前不投入 |

## 7. 落地路线（按当前进度排序：从现在 → 跑刀全流程落地）

> 排序原则：先解锁当前卡点，再补架构，最后谈 GUI 与生态。每阶段标注 所需功能 / 所需技术 / 参考 / 验收。

### P0 识别闭环——进场链路解锁（**当前卡点，立即做**）
- 功能：char_select 等界面可识别；按钮点击抗改版；链路加载校验；素材治理
- 技术：`IOcrEngine` + Windows OCR 接入（含 zh-Hans 语言包检测、必做预处理）；ScreenMarker 加 keywords（ocr 标记）；ClickElementStep 支持 ocr 策略（严格确认层命中才点击，ADR #11）；chain 加载期交叉校验；命名区域库 + 全帧包围盒回填（ADR #12）
- 素材双轨（ADR #8 修订）：模板小图入库提交（OCR 兜底 tier，README 记录所属界面与添加日期）；基准整图 gitignore + 本地压缩 fixture 修复测试
- 参考：MAA pipeline 的 OCR expected 语义
- 验收：`enter_match.json` 全自动跑通；加载期能报出"引用了无标记界面"；五个进场按钮文案（Tab 开始游戏 / 行前战备 / 配装|出发 / 取消匹配 / 当前干员）的 Windows OCR 实测严格命中率有结论——≥4/5 则 Windows OCR 上线，<4/5 则 Paddle 提前接入（ADR #10 门控点）

### P1 数据与校验加固
- 功能：改版体检；数据新鲜度；加载校验完备化
- 技术：diagnose 命令（全量元素/界面实况识别报告）；schema 迁移最小方案；provenance 字段 + item_values 刷新流程；改键检测
- 验收：模拟改版（改一个关键词）后 diagnose 能定位失效项

### P2 常驻宿主与触发器（实时分析在此落地）
- 功能：host 进程；公告/断线弹窗触发器；任务调度；全局急停
- 技术：ICaptureSession 帧流（latest-wins）；ITrigger + 节流；TaskScheduler 互斥槽；输入队列串行化；窗口句柄监视；SetThreadExecutionState；急停热键可配置
- 参考：BetterGI 任务模型
- 验收：host 内跑进场链 + 公告自动跳过；触发器延迟达标（§8）
- 性能落地：耗时插桩先行（若 P0 已加则此处校准预算表）

### P3 采集升级
- 功能：不置顶、不抢焦点的连续采集
- 技术：WGC 主 + BitBlt 兜（ICaptureSession 双后端可切）；支持矩阵声明（16:9/SDR）
- 验收：全程采集零置顶，触发器循环稳定 ≥10 分钟

### P4 导航与撤离闭环（= 跑刀全流程落地）
- 前置：两个游戏内实验（标任意点？箭头稳定？）——10 分钟，决定走"逐节点标点"还是"图引导转向"分支
- 功能：HUD 伺服原语（N1）→ 地图标点动作（N2）→ 拓扑图 + ILocalizer + 闭环（N3）→ 撤离交互与结算识别（N4）
- 技术：拓扑图 JSON + Dijkstra；箭头模板检测；卡死检测 v2；OCR（倒计时/到达提示）；颜色策略（加载屏）
- 参考：导航设计 v1；Game-Map-Tracker（届时细读）
- 验收：出生 → 搜刮 → 撤离 → 结算 → 回大厅，一局半自动跑通（人盯）

### P5 稳定化与安全层
- 功能：会话限额；异常中止；随机化清理；回放回归
