# 声音感知提案（未来开发 · 未投入）

> 状态：**仅参考 / 未来待办**（2026-10-22 用户决定：暂不投入，作为未来能力立项；用户："这是我还没有了解到的领域"）。
> 本文只记录可行性分析、技术路径、边界与验证计划——**当前没有任何代码**，也不影响现行 K1 路线。

## 0. 一句话

**可以做到"听到游戏声音"，且不需要读内存/注入**（WASAPI 回环采集 = 捕获系统正在播放的混音，性质与截图相同）；但"方向"要分层次：左右容易、前后困难。

## 1. 技术路径（采集）

- **WASAPI Loopback**（Windows 回环采集）：捕获"声卡正在播放的内容"，即玩家耳机里听到的混音。
- 不碰游戏进程、不注入、不改音频设备（与截屏同级）：`NAudio` 的 `WasapiLoopbackCapture` 或 `Windows.Media.Audio` 均可。
- 延迟约 30-80ms（回环缓冲 + 分析），足够"告警"级决策（不需要瞄准级实时性）。
- **风险点**：若游戏使用 WASAPI **独占模式**输出，回环可能拿到静音——需要先探测（代码侧可检测）。

## 2. 方向信息的三档难度

| 方向 | 难度 | 原理 |
|---|---|---|
| 左/右 | ⭐ 容易 | 立体声双声道能量差，直接可读 |
| 前/后 | ⭐⭐⭐ 难 | 游戏用 HRTF 把前后编码进频谱细节；简单能量分析无效，需要机器学习，且依赖耳机/空间音频设置 |
| 精确方位角 | ⭐⭐⭐⭐ 很难 | 需大量"已知方向"标注数据训练，标注成本高 |

若输出为 5.1/7.1 或开启了 Windows Sonic / Dolby Atmos，方向会显式分布在多声道里，难度降一档。

## 3. 边界（红线，沿用项目总红线）

**可以做**（"遇险即停 / 避战"原则内）：
1. 枪声检测 → 提前告警（比"受击红屏"早数秒），触发暂停/改道；
2. 脚步声 → 附近有人 → 停/绕（跑刀核心就是避战）；
3. 方向辅助避让：左侧枪声 → 后续路径避开左侧；与定位轨迹结合可做"热点区"记忆；
4. 事件音校验：撤离倒计时/开门/拾取音，作为状态机的额外确认信号。

**不做**（禁止）：
- ❌ 用声音**定位敌人并引导瞄准/交火**（战斗辅助）；
- ❌ "声呐透视"式的敌人精确位置显示。

一句话：**声音只做"感知→避让/暂停/改道"，不做"感知→交战"。**

## 4. 已知限制（需实测验证）

- 游戏内**队友与敌人的脚步/枪声很可能是同一套音效**——若如此，"脚步声"只能得出"附近有人"，无法区分敌友。对跑刀够用（一律当敌人避开），但对精细决策有限制。
- 音效受玩家设置影响（HRTF 开关、音量平衡、声卡虚拟化），需要按本机标定。
- 64 人混战环境下事件会重叠，多事件分离（声源分离）难度高。

## 5. 分阶段计划（均未开工）

| 阶段 | 内容 | 预估 |
|---|---|---|
| **A0 录音采集器** | 新命令 `airesound`（或 `airecord --audio`）：WASAPI 回环录制 WAV + 与帧时间戳对齐写 manifest | 1-2 小时 |
| **A1 实证分析** | 用录音验证：枪声/脚步事件检测可行否、L/R 能量差可靠否、前后可辨否、队友/敌人可区分否（可用已有两局的已知事件时刻做对照：00:08:19 受击、00:11:38 击杀播报、00:40:24 被淘汰） | 2-4 小时 |
| **A2 事件检测器** | mel 频谱 + 轻量 CNN 或阈值法：枪声/脚步/其他 → "事件 + 方向 + 强度" | 1-2 天（需标注数据） |
| **A3 接入决策** | 作为 `ServoLoop` 的危险信号（与红屏检测并列）→ Danger/暂停/改道；不参与任何交战逻辑 | 半天 |

## 6. 开工前需确认（A0 之前）

1. 音频输出形态：耳机/音箱？是否开启 Windows Sonic / Dolby / DTS？游戏内是 stereo 还是 5.1/7.1？
2. 游戏是否使用 WASAPI 独占模式（影响回环是否能录到声音）；
3. 红线边界再确认：声音仅用于避让/暂停/改道。

## 7. 与现有架构的关系

- 采集层：与 `Capture/` 平行新增 `Audio/`（WASAPI 回环），不改动截图链路；
- 决策层：作为 `ServoLoop` 的廉价危险信号（与红屏检测同级，见 `Vision/Signals/Signals.cs`）；
- 数据层：录音文件与 `airecord` 的帧时间戳对齐，便于"音画同帧"分析与标注。
