## 1. 当前性能瓶颈分析

### 1.1 截图开销（最大瓶颈）

**问题**：每次 `click_element` 都要截图，链路有 8-10 次点击
```csharp
// ElementClicker.cs 每次都要截图
using var frame = CaptureService.CaptureWindowMat(winKeyword, raiseAndWait: false);
```

**影响**：
- 截图 + 归一化耗时约 50-100ms
- 10 次点击累计 500-1000ms
- 占总时间的 60-70%

### 1.2 等待时间设置保守

**问题**：链路中等待时间偏长
```json
{ "op": "key", "key": "tab", "wait_ms": 1500 }        // Tab 切换
{ "op": "click_element", "wait_ms": 2000 }           // 点击后等待
{ "op": "wait_screen", "timeout_ms": 240000 }         // 匹配等待 4 分钟
```

**影响**：
- 不必要的等待时间累计 2000-3000ms
- 影响用户体验

### 1.3 重复界面检测

**问题**：某些地方重复检测界面
```json
{ "op": "detect" },
{ "op": "if_screen", "screen": "plaza_first" },
{ "op": "key", "key": "tab" },
{ "op": "detect" },
{ "op": "if_screen", "screen": "plaza_first" }
```

**影响**：
- 重复的截图和检测
- 累计增加 100-200ms 开销

### 1.4 OCR 全帧扫描

**问题**：当前 OCR 是全帧扫描，没有充分利用区域限制
```csharp
var found = Ocr.FindStrict(norm, region, def.Params.Keywords);
```

**影响**：
- 全帧扫描比区域扫描慢 3-5 倍
- 50% 的计算资源浪费在无关区域

## 2. 优化方案与预期收益

### 2.1 截图缓存优化

**方案**：在 ChainCommand 中添加截图缓存机制
```csharp
private static Mat? _cachedFrame;
private static DateTime _lastCaptureTime;
private static readonly TimeSpan CacheTimeout = TimeSpan.FromMilliseconds(100);

private static Mat GetCachedFrame(IntPtr hwnd, string winKeyword, int designW, int designH)
{
    if (_cachedFrame == null || DateTime.Now - _lastCaptureTime > CacheTimeout)
    {
        _cachedFrame = CaptureService.CaptureWindowMat(winKeyword, raiseAndWait: false);
        _lastCaptureTime = DateTime.Now;
    }
    using var fresh = _cachedFrame.Clone();
    return FrameTools.Normalize(fresh, designW, designH);
}
```

**预期收益**：
- 减少 50-70% 的截图次数
- 节省 250-700ms 总时间

**实施难度**：⭐⭐☆☆☆（简单）

### 2.2 自适应等待时间

**方案**：根据界面类型动态调整等待时间
```csharp
private static int GetAdaptiveWaitTime(string screenName, int baseWait)
{
    var fastScreens = new Dictionary<string, int>
    {
        ["plaza_ready"] = 500,    // 广场界面响应快
        ["map_select"] = 1000,    // 地图选择稍慢
        ["loadout"] = 1500        // 配装界面最慢
    };
    return fastScreens.TryGetValue(screenName, out var fast) ? fast : baseWait;
}
```

**预期收益**：
- 减少 30-50% 的等待时间
- 节省 600-1500ms 总时间

**实施难度**：⭐⭐☆☆☆（简单）

### 2.3 预加载策略

```csharp
private static void PreloadResources(Chain chain, ElementsTable elements, string repoRoot)
{

            using var img = Cv2.ImRead(path, ImreadModes.Color);
            // 缓存到内存
        }
    }
}
```

**预期收益**：
- 减少运行时文件读取开销
- 提升 10-15% 的响应速度

### 2.4 智能区域裁剪

**方案**：根据历史 OCR 结果自动收紧区域
```csharp
private static int[]? AutoTightenRegion(OcrFindResult result, int[]? currentRegion)
{
    if (currentRegion == null || result.W == 0 || result.H == 0)
        return currentRegion;
    
    // 收紧 10% 的边距
    var margin = 0.1;
    var newX = (int)(result.X + result.W * margin);
    var newY = (int)(result.Y + result.H * margin);
    var newW = (int)(result.W * (1 - 2 * margin));
    var newH = (int)(result.H * (1 - 2 * margin));
    
    return new[] { newX, newY, newW, newH };
}
```

**预期收益**：
- 提升 OCR 速度 20-30%
- 减少 40-60% 的 OCR 计算量

**实施难度**：⭐⭐⭐☆☆（中等）

### 2.5 并行处理优化

**方案**：并行处理多个界面的检测
```csharp
private static ScreenGuess? DetectScreensParallel(Mat frame, ScreenTable table, string repoRoot)
{
    var candidates = new List<Candidate>();
    
    var options = new ParallelOptions
    {
        MaxDegreeOfParallelism = Environment.ProcessorCount
    };
    
    Parallel.ForEach(table.Screens, options, (screenDef) =>
    {
        if (screenDef.Value.Enabled == false) return;
        
        // 检测逻辑
        var hit = DetectScreen(frame, screenDef.Value, repoRoot);
        if (hit.HasValue)
        {
            lock (candidates)
            {
                candidates.Add(new Candidate(screenDef.Key, hit.Value.Value, hit.Value.Value > 0.8));
            }
        }
    });
    
    return candidates.OrderByDescending(c => c.Confidence).FirstOrDefault()?.Matched == true 
        ? new ScreenGuess(candidates.First().Name, candidates.First().Confidence, table.Screens[candidates.First().Name].Actions) 
        : null;
}
```

**预期收益**：
- 界面检测速度提升 2-4 倍（多核情况下）
- 特别适合界面数量多的场景

**实施难度**：⭐⭐⭐⭐☆（较难）

## 4. 瑕疵问题修复

### 4.1 OCR 候选提示功能未实现

**问题**：`ElementClicker.cs` 调用了 `Ocr.FindCandidateHint`，但该方法未实现

**修复方案**：
```csharp
// 在 Ocr.cs 中添加
public static string? FindCandidateHint(Mat frame, int[]? region, IReadOnlyList<string> keywords)
{
    if (Engine is null || !Engine.IsAvailable || keywords is not { Count: > 0 })
        return null;
    
    var words = Engine.Recognize(frame, region);
    if (words.Count == 0) return null;
    
    foreach (var kw in keywords)
    {
        var m = OcrTextMatcher.Match(words, kw);
        if (m.CandidateHit)
        {
            var matchedWords = words.Where(w => w.Text.Contains(kw.Substring(0, 1))).Select(w => w.Text);
            return $"候选命中：'{kw}' 可能与 '{string.Join(" ", matchedWords)}' 混淆";
        }
    }
    return null;
}
```

### 4.3 链路状态跳转可能造成死循环

**问题**：`detect_start` 循环可能无限重试

**修复方案**：
```json
{ "op": "pause", "message": "两次识别仍未到广场..." },
{ "op": "jump", "jump_to": "detect_start" }
```

添加重试计数器：
```csharp
int retryCount = 0;
const int maxRetries = 3;
while (i < chain.Steps.Count)

    // 检测是否为重试循环
    if (s.Op == "jump" && s.JumpTo == "detect_start")
    {
        retryCount++;
        if (retryCount > maxRetries)
        {
            throw new InvalidOperationException($"检测重试超过 {maxRetries} 次，请检查游戏状态");
        }
    }
    // ... 其他逻辑

```

## 总结

当前 DeltaUnlimited 的性能瓶颈主要集中在截图开销和等待时间上。通过实施截图缓存、自适应等待时间等优化，预计可以将进场时间从当前的 10-15 秒减少到 5-8 秒。

建议先完成核心功能，修复已知瑕疵，然后在功能稳定后再逐步实施性能优化。开发期的慢节奏是好事，能保证功能的稳定性。
