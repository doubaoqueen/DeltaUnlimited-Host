状态：**侦查结论**（2026-09-27，基于 feat/ai-vision 分支现状盘点 + 业界调研）。回答："以计算机视觉识别的能力完成自动跑刀，应该如何训练？需要什么训练素材？"

## 0. 结论（TL;DR）

**仓库已经把"训练铁轨"铺好了（采集→训练→导出→门禁→回流全链路在），当前缺的不是训练代码，而是三样东西：素材、标注纪律、以及为第二阶段（目标检测）扩展管线的准备。** 复核 `docs/跑刀方案.md §5` 与 `docs/导航设计.md` 后确认：跑刀闭环里大部分感知信号用模板/颜色统计/OCR 就能零训练解决，**现阶段真正需要训练的只有 2 个模型**：

1. **可通行性三分类**（管线已建好，当前 `assets/ai/models/passability_v0_placebo.onnx` 是占位模型，就差喂料）；
2. **YOLO 避战检测**（"看见敌人绕行"，对应导航设计 N5，排在 K5 之后）。

- **防泄漏切分（2026-09-30 二次修正）**：`ad9b5c1` 已把切分改成"按采集会话整段"，但**会话键取错了时间戳**——`dataset.py` 从 ROI 文件名解析时间，而 `ailabel` 写的文件名时间是**裁剪导出时刻**（采集时刻在 manifest 的 `created` 列，`load_manifest` 当时丢弃了它）。实测 1736 条标注里 **47/71 个采集分钟被旧键打散成多个"会话"**，同一采集 burst 的相邻帧仍可能跨 train/val → val 仍偏乐观（与金标 0.695 vs val 0.8722 的差距一致）。**已修复**：会话键改用 `created`（采集时刻），实测会话数 66→71、最大会话 74→32 帧（与 1-2 秒采集节奏吻合）。后续仍建议：金标集独立采集 + 赛季切片评估 + **按 map/season 分组报告**（§4.1 第 1 条，尚未实现）+ 用新数据重训（当前 1736 帧标注 vs v1 训练时的 429 帧）。

## 2. 需求分解：哪些要训练、哪些不要

对齐跑刀方案 §5 感知表逐项标注：

| 感知信号 | 推荐方案 | 要训练吗 | 阶段 |
|---|---|---|---|
| 可通行性（前方能不能走） | 三分类小 CNN（已有管线） | **要** | 现在（K1 前不阻塞） |
| 可交互目标（准星附近键位提示） | 游戏 UI 自带提示，模板/颜色检测 | 不要 | K2 |
| 容器高光 / 金光柱 | 颜色/亮度统计起步，不够再上 YOLO | 二期才要 | K2 → N5 后 |
| HUD 导航标记（撤离伺服） | 多模板 + 距离阈值 | 不要 | K1 |
| 受击红屏 / 血条骤降 | 屏幕边缘红色像素占比 | 不要 | K4 |
| 拾取面板物品 | OCR 名称 + 格子品质色 + 模板/ORB 兜底 | OCR 先评测，可能换引擎 | K2 |
| 撤离点图标状态（亮/灰/锁） | 地图屏模板（布局固定） | 不要 | K1 |
| 死亡 / 结算 / 已落地 | OCR + 模板（`screens.json` 已有大半） | 不要 | K1/K4 |
| **避战：看见敌人/AI/尸体袋绕行** | YOLO 目标检测 | **要** | N5（K5 后） |
| 可通行性 v2（远端预警） | 双带 ROI 复用同一分类器 | 要（便宜） | 远期 |
| 小地图自定位、VLM 场景理解 | — | 现在不做（见 §4.5） | — |

核心原则（项目文档已定，本报告复核后同意）：**模型只做感知传感器，不持有决策权；能靠 UI 信号就不理解 3D 世界；标注成本高的能力一律后置。**

## 3. 训练素材：从哪来、要多少、怎么标

### 3.1 三条素材线

**线 1：aicollect 边玩边标（分类主粮）。** 已有工具，4Hz 按键打标。关键纪律是**别只站在好地方按 1**——要专门去"难走的地方"按 2，去"没地面的地方"按 0（见 §3.2 覆盖矩阵）。每局跑刀本身就是采集机会。

**线 2：对局录像离线挖掘（素材复用率最高，强烈建议建立习惯）。** 用 OBS 以 60fps 录整局（含搜刮、死亡、结算全程），之后离线抽帧（每秒 1-2 帧）就是取之不尽的素材库：同一段录像既能喂可通行性分类、又能喂未来的 YOLO 检测（敌人/容器/光柱）、还能建 OCR 评测集和金标集。**一次录像，喂所有模型。** 这条线不需要写任何 C# 代码，是当前性价比最高的素材来源。

**线 3：运行日志回流（已有机制，坚持执行）。** `logs/ai` JSONL + 背景负样本池 → `import_jsonl.py` 复标队列；`RecordGuardFired` 的守卫矛盾既是漂移信号也可以回流成训练样本（"模型平静但守卫触发"的帧 ≈ 免费 blocked 真值）。

### 3.2 采集覆盖矩阵（分类与检测通用）

模型只需要对**运行时分布**鲁棒，所以以跑 bot 的那套画质设置为主，留 10-20% 其他条件做泛化：

| 维度 | 覆盖要求 |
|---|---|
| 地图 | 零号大坝先采到饱和 → 长弓溪谷 → 巴克什/航天基地，每图至少一个完整"采集夜" |
| 时段/天气 | 白天 / 黄昏 / 夜战图 / 雾天（dataset.py 的 ColorJitter 已为此铺垫，但真素材不可省） |
| 角色状态 | 平地跑 / 站定 / 冲刺 / 蹲 / 贴墙 / 门内外 / 楼梯 / 坡道 / 水边 / 集装箱顶 / 楼顶边缘 / 跳落前 |
| HUD/界面状态 | 裸 HUD / 低血 / 红屏残留 / 开小地图 / 拾取面板覆盖 / 背包打开（这些多数应进 no_ground 类） |
| 难例主动采集 | **贴脸墙（准星怼墙）、UI 遮挡、加载瞬间、天空**——这些是 no_ground 的主粮，不主动采就永远缺 |

实用建议：aicollect 的 `--season` 参数可以顺便编码条件（如 `s5_night_fog`），manifest 不用改结构就能记录环境维度。

### 3.3 数据量建议（看门禁指标，别教条）

| 模型 | 起步量 | 建议目标 |
|---|---|---|
| 可通行性三分类 | 每类 1500 张（总计 6000-8000） | 每类 3000+，且每张地图都有覆盖 |
| YOLO 避战 | 每类 800-1500 个实例，1500-3000 张带框帧 | 真机误报率达标为止 |
| 容器/物资检测（如做） | 每类 500-1000 实例 | — |
| OCR 评测集 | 100-300 张拾取面板裁剪 + 真值 CSV | 微调才需要 2000-5000 文本行 |
| 金标集 | 100 张分层抽样（ai-training README ⑥ 流程） | 每赛季重建 |

按 aicollect 4Hz 的节奏，一个两小时的采集夜能出几千张，3-5 个晚上就能把分类 v1 喂到门槛。

### 3.4 标注工具与半自动管线

- **分类**：保持现状（aicollect + 直接改 manifest.csv）。工具越简单纪律越容易坚持，不建议为此引入新工具。
- **检测（YOLO）**：本地工具首选 **X-AnyLabeling**（桌面端、内置 SAM / Grounding DINO 辅助、直接导 YOLO 格式）或自建 CVAT。视频素材可用 **SAM2 的记忆传播**：关键帧标一次，mask/框自动扩散到相邻几十帧，标注成本降一个量级。
- **预标注的"土办法"往往更灵**：Grounding DINO 这类开放词汇模型对"游戏 UI 小图标"零样本效果很差，别指望它；但仓库现成的 `TemplateMatcher`/`TplProbe` 对图标类目标（光柱、撤离点图标）预标注非常准——**用自家模板匹配先预标，人工只做修正**，比通用大模型实用得多。
- **数据管理**：manifest 的 `map/season` 字段要当真——每个赛季留一片 val 切片专做漂移评估；`images/` 保持 gitignore（README 已约定另盘备份），manifest 快照随版本提交。
- **隐私**：录屏素材可能含队友昵称/聊天等他人信息，数据集不要外传或上传云端标注服务（这也是推荐本地标注工具的理由之一）。

## 4. 各模型训练方案

### 4.1 可通行性分类 v1：管线已建，直接喂料

现有 `train.py`（MobileNetV3-Small，~0.8ms/帧 @4 线程 CPU）不要推翻，补四个小件：

1. **分组评估**：val 按 map/season 分组报告 macro-F1，防"只在零号大坝好"的地图过拟合；
2. **增广补强**：加 JPEG 压缩/轻微噪声增广（对齐采集 q80 与实况码流），现有 ColorJitter + 翻转保留；
3. **阈值标定**：`min_confidence=0.70` 别拍脑袋，用 val 的 P-R 曲线选弃权阈值；
4. **上线流程照 ai-training README ①-⑦ 走**：train → export → 同步 `data/ai_vision.json` + `assets/ai/models/manifest.json` → `aieval` 门禁 → **observe-only 先跑 N 局**看 `SnapshotStats` 与矛盾率 → 再考虑开 enforce。"预测层提前拉动既有守卫"的灰度设计是仓库里最值钱的部分之一，不要跳步。

### 4.2 YOLO 避战层（N5）：第二场主战役

- **选型**：Ultralytics 线，YOLO11s 或 **YOLO26s**（2026 年初发布：NMS-free 端到端推理、CPU 快 43%、小目标检测改进——NMS-free 对 C# 部署特别友好；注意 YOLO12/13 不是 Ultralytics 官方线，官方编号从 11 → 12（社区线）→ 26）。从 COCO 预训练微调，imgsz 640。
- **类别第一版宁少勿杂**：`enemy_player` / `enemy_ai` / `corpse_bag`（尸体袋也是搜刮信号）/ `loot_highlight`（金光柱）。跑刀的核心诉求是"避开"而不是"识别准"，误报比漏报便宜。
- **标注成本控制**：视频抽帧 + SAM2 记忆传播 + §3.4 的模板预标注技巧。
- **训练配置**：batch 16-32，epochs 100-150，默认超参起步，末轮关 mosaic（`close_mosaic`）；RTX 5070 本地几小时搞定。
- **部署（现有代码的扩展点）**：`OnnxRunner` 是单输入/单输出定长缓冲设计，检测头输出形状不同——需要新增 `OnnxDetector`：YOLO11 导出后要在 C# 端补几十行 NMS；YOLO26 的 NMS-free 导出可直接解析框+类。DirectML 1.24.4 钉版兼容两者。
- **节奏与灰度**：伺服 5-10Hz 下检测每 2-3 帧跑一次即可（预算 10-20ms）；同样 observe-only 先行，预警接入既有 Escalate/暂停人工路径。
- **验收**：每类 mAP@50 ≥ 0.7，且真机"每分钟误报次数"可接受，才准碰动作层。

### 4.3 可通行性 v2：双带 ROI，比分割划算

`AiTypes.cs` 已预留 `Warn(远端)` 与"v2 双带 ROI"——顺着做：近带 Blocked=避让、远带 Warn=减速，同一个分类器两份输入，训练数据完全同源复用。全画幅语义分割（PIDNet-S 一类实时轻量模型）列为 v3 远期选项：即使 SAM2 辅助，每张 mask 仍要人工修，当前收益不如双带。业界第一人称视频弱监督可通行性（Wild Visual Navigation 一系，用自运动自动产标签）值得跟踪，但那是素材积累够之后的进阶课题。

### 4.4 OCR：先评测，再决定动不动

跑刀方案的"OCR 主 + 品质色判档 + 模板兜底"管线是对的。第一步不是换引擎而是**建评测集**（100-300 张拾取面板裁剪 + 真值 CSV，测字符错误率）：Windows OCR（现用 `WindowsOcrEngine`）够用就不折腾；不够就换 **RapidOCR**（PaddleOCR 的 ONNX 模型，能在现有 onnxruntime-directml 里直接跑，运行时依然零 Python）；还不行才在 ai-training 里微调识别模型（2000-5000 条文本行裁剪，可用游戏 UI 字体合成扩充）。

### 4.5 明确不建议现在做的

- **小地图自定位/姿态回归**：导航设计已否决（无坐标显示、玩家箭头检测风险高、标点外包给游戏引擎更稳），仅作为标点方案失效时的退路保留调研。
- **VLM 场景理解**：体量与延迟不匹配伺服循环，"unknown → 停住等人工"便宜且更安全；远期可作低频兜底再评估。
- **强化学习端到端**：样本效率与"模型不持决策权"红线冲突。

## 5. 评估与验收：三层指标

1. **离线门禁**（已有机制）：金标集 macro-F1 ≥ 0.85；检测每类 mAP@50；OCR 字符错误率。金标集每赛季重建。
2. **observe-only 在线观察**：预警精确率（守卫矛盾作免费代理）、每分钟误报数、推理 p99（`OnnxRunner` 已计时）。
3. **闭环业务（最终验收）**：撤离成功率、局均收益、死因分布、人工接管次数——模型指标只是过程量，K5 的验收标准（人盯连跑 3 局收益为正）已在跑刀方案里。

## 6. 里程碑映射（训练怎么插进 K0-K6）

| 阶段 | 训练侧动作 |
|---|---|
| K0 标定采集 | aicollect 采集夜 ×3-5（按 §3.2 矩阵）+ 跑刀方案 §8 截图清单 + `item_catalog` 录 20-30 条 + **开始每局录像** |
| K1 撤离直通 | 分类 v1 训练 + 金标集 + observe-only（不阻塞 K1——K1 只用模板）；HUD 标记多模板标定 |
| K2-K4 | 零训练（交互提示/红屏/品质色/OCR 评测） |
| K5 漫游成熟 | 数据回流复标，分类 v1 迭代 |
| N5 / 之后 | YOLO 避战 v1（素材从录像库挖，X-AnyLabeling/SAM2 标注） |
| 远期 | 双带 v2 → 容器检测 → （可选）分割 |

## 7. 风险与红线（训练侧对齐）

- 继承项目总红线：不做任何战斗/击杀/瞄准辅助；模型只感知不决策（`ai_vision` 红线注释）；observe-only 起步、人必须在场、每日会话限额、低频拟人；风险自担声明见 `docs/项目大纲.md §1/§7`。
